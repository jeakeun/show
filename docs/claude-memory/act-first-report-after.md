자동화의 변경 제안(회고 플레이북, 프롬프트 감사 제안, 회고·감사가 낸 코드·설정 개선)은 사용자에게 "적용할까요?"를 묻지 말고 **먼저 조치하고 보고만** 한다.

**Why:** 2026-09-21 사용자 지시 "변경사항 내가 체크해줘야 하는 거 수동으로 하자고 했는데 그냥 선조치 후보고로 변경, 일단 니가 조치하고 보고만 해". 9/7에 만든 승인 게이트([[roles-and-hub]])가 9/20 플레이북을 하루 묵혀 "적용 시작 9/21"을 놓치게 했고, 사용자는 비개발자라 승인 판단이 부담.

**How to apply:** yt-auto는 `config.json` `auto_approve: true` — insights가 플레이북을, promptaudit가 프롬프트 hunk를 자동 적용하고 바탕화면 `PLAYBOOK-적용보고.txt`/`PROMPT-적용보고.txt` + ntfy로 보고(이전본은 data/playbook_history·prompt_history, 프롬프트는 문법·스모크 실패 시 원복). 대화 중에도 같은 원칙: 되돌릴 수 있는 수정은 하고 나서 무엇을·왜·되돌리는 법을 보고. **여전히 먼저 물을 것**: 돈이 드는 결정(유료 구독·모델 상향), 영상 삭제·공개 전환 같은 외부 비가역 조치, 하루 2편 같은 사용자 기존 결정 뒤집기, 실전 매매 전환. 코인봇 회고 제안은 자동 장치가 없으니 회고를 볼 때 내가 적용하고 보고.
