# 자동화 역할 구조 (Cloud Compass 원칙 적용, 2026-09-07)

모든 자동화는 네 칸 중 하나에 속한다. **분석 칸은 어떤 파일도 실행 칸에 직접 쓰지 않는다.** 전략·설정·프롬프트가 바뀌는 길은 「분석 → 제안 파일 → 사람 승인 → 적용」 하나뿐이다.

| 칸 | 하는 일 | 쓸 수 있는 곳 | 못 하는 것 |
|---|---|---|---|
| ① 수집 (읽기) | 외부에서 숫자·문서를 가져와 기록 | 자기 데이터 폴더(스냅샷·csv·jsonl)만 | 전략·설정·코드 수정, 외부에 쓰기 |
| ② 규칙 (코드) | 정해진 규칙으로 판정·차단·복구 | 상태 파일, 격리 폴더 | LLM 호출로 규칙을 바꾸기 |
| ③ 분석 (LLM) | 데이터를 읽고 제안·리포트 작성 | 리포트 폴더, `*_proposed.md` | 설정·소스·프롬프트·플레이북 직접 수정, 새 파일 생성 |
| ④ 실행 | 실제 업로드·매매·발행 | 외부 플랫폼 | 규칙 밖 행동 (안전장치는 항상 우선) |

## 가드(②)가 지키는 불변식
1. 분석 LLM이 보호 파일을 바꾸면 → 원복 + 폰 알림 (코인 회고 `run_weekly.ps1`, 자가감사 `run-audit.ps1`, AI데일리 `run-daily.ps1`).
2. 분석 LLM이 루트에 새 파일을 만들면 → 격리 폴더로 이동 + 알림.
3. 유튜브 회고 결과는 승인 전엔 대본에 영향 없음 (`playbook_proposed.md` ≠ `playbook.md`).
4. 실행 칸의 안전장치(손절·STOP.txt·의료단어 차단·무결성)는 어떤 제안으로도 자동 완화되지 않는다.

## 승인 흐름 (승인 #1)
회고/감사가 제안 → 폰 푸시 "승인 대기" + 바탕화면 `PLAYBOOK-승인대기.txt` → 사용자가 클로드에게 "적용해"/"폐기해" → 클로드가 `src.approve` 실행 + git 커밋(변경 기록 = 승인 #2 대용). 3일 넘게 대기하면 자가감사가 🟡로 표시.
