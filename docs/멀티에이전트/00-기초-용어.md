# 기초 용어 — RAG, LangChain이 무슨 뜻인지부터

> 어려운 문서(01~05)를 읽기 전에 보는 용어집입니다. 용어마다 **한 줄 뜻 → 비유 → 내 프로젝트에서 본 예** 순서입니다.
> 한 번에 다 외우려 하지 말고, 교시 하나씩 읽고 끝의 퀴즈를 풀어봅니다.

## 큰 그림 먼저

```
사용자 질문
   ↓
[LLM]  ← 프롬프트(지시문) + 컨텍스트(같이 넣어주는 자료)
   ↓ 필요하면 도구를 부름
[도구]  검색, DB 조회, 업로드 …         ← LLM + 도구 + 반복 = 에이전트
   ↑
[RAG]  문서를 미리 잘라(청킹) → 숫자로 바꿔(임베딩) → 벡터 DB에 저장
       → 질문과 뜻이 가까운 조각을 찾아 컨텍스트에 넣어줌

이걸 만드는 도구 상자
  LangChain = 부품 상자    LangGraph = 흐름도    LangFlow = 화면으로 조립    LangSmith = 기록·평가
```

## 1교시 · AI 기본 (6개)

| 용어 | 한 줄 뜻 | 비유 | 내 프로젝트에서 |
|---|---|---|---|
| **LLM** (대형 언어 모델) | 엄청난 양의 글을 읽고 "다음에 올 말"을 예측하도록 학습한 AI. 클로드, GPT, 제미나이가 여기에 속함 | 책을 엄청 많이 읽은 글쓰기 선수 | 유튜브 대본을 쓰는 클로드 |
| **프롬프트** | LLM에게 주는 지시문. 그중 역할·규칙을 정하는 고정 지시문을 **시스템 프롬프트**라고 함 | 일 맡길 때 주는 작업 지시서 | 대본 지시문 (9/14에 3,182자 → 2,944자로 정리) |
| **토큰** | LLM이 글을 읽고 쓰는 단위. 낱말보다 작은 조각. **요금과 길이 한도가 전부 토큰으로 계산됨** | 택시 미터기의 거리 단위 | 회고가 출력 한도 10,000토큰에 걸려 본문 0자로 실패 (9/13) |
| **컨텍스트** (맥락) | LLM이 한 번에 보는 모든 글: 지시문 + 대화 기록 + 같이 넣어준 자료. 한 번에 볼 수 있는 최대량을 **컨텍스트 윈도우**라고 함 | 책상 위에 펼쳐둔 자료. 책상 크기에 한계가 있음 | 클로드가 메모리 색인을 보고 필요한 파일만 책상에 올림 |
| **환각** (hallucination) | LLM이 사실이 아닌 걸 그럴듯하게 지어내는 것 | 모르는 문제도 자신 있게 답을 쓰는 학생 | AI데일리의 없는 회차 기록, 회고의 "-76% 급락" 오진 |
| **API** | 프로그램끼리 정해진 방식으로 요청하고 답을 받는 창구. 열쇠 역할을 하는 비밀번호가 **API 키** | 식당 주문 창구 + 회원 카드 | YouTube API로 업로드, 업비트 API로 시세 조회 |

**더 알아두면 좋은 것**
- **학습(training)과 추론(inference)**: 학습은 모델을 만드는 단계(회사가 함), 추론은 만든 모델에 질문해서 답을 받는 단계(우리가 하는 것).
- **파인튜닝**: 이미 만든 모델을 내 데이터로 조금 더 학습시키는 것. 말투나 형식을 가르칠 때 씀. 지식을 넣는 데는 RAG가 더 맞음 (2교시).
- **모델 크기와 값**: 큰 모델(오퍼스)은 똑똑하지만 비싸고, 작은 모델(하이쿠)은 싸고 빠름. 그래서 검수처럼 단순한 일은 하이쿠에 맡김.

<details><summary>1교시 퀴즈 (답은 펼쳐서 확인)</summary>

1. "토큰"이 왜 중요한가요? → **요금과 길이 한도가 토큰으로 계산되기 때문.** 너무 낮게 잡으면 답이 잘리고(9/13 사건), 많이 쓰면 비싸짐.
2. 컨텍스트에 자료를 많이 넣으면 무조건 좋을까요? → **아니요.** 책상(컨텍스트 윈도우)에 한계가 있고, 넣은 만큼 돈이 들고, 관련 없는 자료가 섞이면 오히려 헷갈림. 그래서 필요한 것만 골라 넣는 기술(RAG)이 생김.
3. 환각을 줄이는 방법 하나는? → **근거 자료를 같이 주고 그 안에서만 답하게 하기**(RAG), 또는 **다른 AI·코드가 검사하기**(검수 에이전트).
</details>

## 2교시 · RAG (9개)

**RAG를 한 문장으로**: 오픈북 시험. 질문이 오면 교과서(내 문서)에서 관련 페이지를 먼저 찾아 펴놓고, 그걸 보면서 답을 쓰게 하는 방식.
RAG는 Retrieval(찾기) · Augmented(더하기) · Generation(답 쓰기)의 줄임말입니다.

| 용어 | 한 줄 뜻 | 비유 |
|---|---|---|
| **RAG** | 질문과 관련된 문서를 먼저 찾아 LLM에게 같이 주고 답하게 하는 방식 | 오픈북 시험 |
| **문서 로더** | PDF·웹페이지·한글 파일 같은 문서를 읽어 글자로 꺼내는 부품 | 책을 스캔하는 기계 |
| **청크 / 청킹** | 긴 문서를 검색하기 좋은 크기의 조각으로 자른 것 / 자르는 일 | 교과서를 문단마다 포스트잇으로 나누기 |
| **임베딩** | 글의 **뜻**을 숫자 목록으로 바꾸는 것. 뜻이 비슷하면 숫자도 비슷함 | 문단마다 "의미 지도" 위의 좌표를 찍기 |
| **벡터** | 임베딩으로 나온 숫자 목록 그 자체 (예: [0.12, -0.8, 0.33, …]) | 지도 좌표 |
| **벡터 DB** | 벡터와 원래 글 조각을 함께 저장하고, 가까운 것을 빨리 찾아주는 저장소 | 좌표로 정리된 도서관 |
| **유사도 검색 / top-k** | 질문도 좌표로 바꿔서, 가장 가까운 조각 k개를 찾는 것 | 지도에서 내 위치와 가장 가까운 가게 3곳 찾기 |
| **키워드 검색 (BM25)** | 뜻이 아니라 **같은 단어**가 얼마나 들어있는지로 찾는 옛날 방식 | 책 뒤의 색인(찾아보기) |
| **하이브리드 검색** | 뜻 검색 + 키워드 검색을 섞은 것. 제품 코드·이름처럼 정확한 단어가 중요할 때 강함 | 지도 검색 + 간판 이름 검색 |

**흐름 정리**

```
[미리]  문서 로더 → 청킹 → 임베딩 → 벡터 DB 저장
[질문]  질문 임베딩 → 유사도 검색(top-k) → 찾은 조각 + 질문을 LLM에게 → 출처를 붙여 답변
```

**왜 쓰나**
- LLM은 우리 회사 문서나 어제 일을 모릅니다. RAG로 넣어주면 그걸로 답합니다.
- 찾은 조각을 출처로 보여줄 수 있어서 환각을 확인하기 쉽습니다.
- 문서가 바뀌면 다시 저장만 하면 됩니다. 모델을 다시 학습시킬 필요가 없습니다.

<details><summary>2교시 퀴즈</summary>

1. 임베딩과 벡터의 차이는? → 임베딩은 **바꾸는 일**(또는 그 방법), 벡터는 **바꾼 결과인 숫자 목록**.
2. "환불 규정"을 검색했는데 문서에는 "돈 돌려받는 방법"이라고 써 있어요. 키워드 검색과 뜻 검색 중 어느 쪽이 찾을까요? → **뜻 검색(임베딩)**. 단어는 다르지만 뜻이 가까움.
3. 반대로 "ERR-4021" 같은 오류 코드를 찾을 땐? → **키워드 검색**이 강함. 그래서 둘을 섞는 하이브리드를 씀.
4. 청크를 너무 크게 자르면? → 한 조각에 여러 주제가 섞여 검색이 흐려지고, LLM에 넣는 양이 늘어 비싸짐. 너무 작으면 앞뒤 맥락이 잘림.
</details>

## 3교시 · 에이전트 (7개)

| 용어 | 한 줄 뜻 | 내 프로젝트에서 |
|---|---|---|
| **에이전트** | LLM + 도구 + 반복. 목표를 받으면 스스로 "생각 → 도구 사용 → 결과 확인"을 반복하다 끝냄 | AI데일리 채용 수집 |
| **도구 (Tool)** | 에이전트가 부를 수 있는 기능. 검색, 파일 쓰기, DB 조회, 업로드 등 | AI데일리에 허용한 도구: 웹 검색, 웹 읽기, 파일 읽기·쓰기·찾기 |
| **함수 호출 (Function calling)** | LLM이 "이 도구를 이 값으로 불러줘"라고 정해진 형식으로 말하는 기능. 실제 실행은 프로그램이 함 | — |
| **워크플로** | 순서는 코드가 정하고 일부 칸만 LLM이 하는 것 | 유튜브 파이프라인 (대본만 AI) |
| **멀티 에이전트** | 따로 맥락을 가진 에이전트 여러 개가 일을 나누는 구조 | 대본 작성 AI ↔ 검수 AI |
| **MCP** | AI에 도구를 연결하는 표준 규격. 한 번 만들면 여러 AI 앱에서 같은 방식으로 씀 | 노션·깃허브 연결 |
| **Human-in-the-loop** | 중요한 단계에서 사람이 확인·승인하게 하는 설계 | 돈·영상 삭제는 사람이 결정 |

<details><summary>3교시 퀴즈</summary>

1. 워크플로와 에이전트의 차이는? → **다음에 뭘 할지 누가 정하나.** 코드가 정하면 워크플로, LLM이 정하면 에이전트.
2. 함수 호출에서 실제로 도구를 실행하는 건 LLM인가요? → **아니요.** LLM은 "이걸 불러줘"라고 말만 하고, 실행은 프로그램이 함. 그래서 프로그램 쪽에서 막거나 승인을 걸 수 있음.
</details>

## 4교시 · LangChain 가족 (4개 + 그래프 용어 5개)

**비유**: 요리
- **LangChain** = 주방 도구 세트. 불(모델)·칼(도구)·냉장고(검색기)를 어느 회사 제품이든 같은 손잡이로 씀.
- **LangGraph** = 요리 순서도. "간 보고 싱거우면 소금 넣고 다시 간 보기" 같은 갈림길과 반복, 중간 저장이 가능.
- **LangFlow** = 그 순서도를 마우스로 그리는 화면. (LangChain 팀이 아니라 다른 회사 제품)
- **LangSmith** = 주방 CCTV와 기록장. 어느 단계에서 뭘 넣고 뭐가 나왔는지, 돈이 얼마 들었는지 기록하고 평가.

| 용어 | 한 줄 뜻 |
|---|---|
| **프레임워크 / 라이브러리** | 자주 쓰는 기능을 미리 만들어둔 코드 묶음. 처음부터 다 짜지 않게 해줌 |
| **LangChain** | LLM·도구·RAG 부품을 표준화한 파이썬 라이브러리. `create_agent` 로 에이전트를 쉽게 만듦 |
| **LangGraph** | 에이전트 흐름을 그래프(점과 화살표)로 설계·실행하는 라이브러리. 멀티 에이전트에 많이 씀 |
| **LangFlow** | LangChain 부품을 화면에서 끌어다 연결해 흐름을 만드는 도구 |
| **LangSmith** | 실행 기록(추적)과 평가 서비스 |

**LangGraph 그래프 용어**

| 용어 | 뜻 | 요리 비유 |
|---|---|---|
| **State (상태)** | 모든 단계가 같이 보고 고치는 공유 메모 | 주방 화이트보드 |
| **Node (노드)** | 일하는 단계 하나 | "썰기", "볶기", "간 보기" |
| **Edge (엣지)** | 다음 단계로 가는 화살표 | 순서도의 화살표 |
| **Conditional edge** | 상태를 보고 갈 곳을 고르는 갈림길 | "싱거우면 → 소금 / 괜찮으면 → 담기" |
| **Checkpoint / interrupt** | 단계마다 상태 저장 / 사람 확인을 기다리며 멈춤 | 손님에게 "이 맛 괜찮으세요?" 묻고 기다리기 |

<details><summary>4교시 퀴즈</summary>

1. LangChain과 LangGraph 중 "갈림길과 반복이 많은 멀티 에이전트"에 더 맞는 건? → **LangGraph.**
2. LangFlow는 LangChain 팀이 만들었나요? → **아니요.** LangChain 부품을 쓰는 별도 오픈소스이고, 지금은 IBM 소유.
3. 어느 단계에서 비용이 많이 드는지 보고 싶으면 무엇을 쓰나요? → **LangSmith** (추적).
</details>

## 5교시 · 평가·운영 (6개)

| 용어 | 한 줄 뜻 |
|---|---|
| **평가셋** | 질문과 정답을 미리 모아둔 시험지. 바꿀 때마다 같은 시험지로 점수를 비교 |
| **기준선 (baseline)** | 가장 단순한 방법의 점수. 이걸 넘어야 복잡하게 만든 의미가 있음 |
| **재현율 / 정밀도** | 재현율 = 찾아야 할 걸 얼마나 안 빠뜨렸나. 정밀도 = 찾은 것 중 맞는 비율 (틀린 걸 얼마나 안 섞었나) |
| **LLM-as-judge** | 다른 LLM에게 채점을 맡기는 방법. 빠르지만 채점자도 틀릴 수 있음 |
| **추적 (tracing) / 관측성** | 실행 단계마다 무엇이 들어가고 나왔는지 기록해서 문제를 찾을 수 있게 하는 것 |
| **지연 시간 (latency)** | 질문하고 답이 나오기까지 걸리는 시간 |

<details><summary>5교시 퀴즈</summary>

1. 공고에서 요구사항 10개 중 8개를 찾았고, 엉뚱한 것 2개를 더 만들었어요. 재현율과 정밀도는? → 재현율 8/10 = **80%**, 정밀도 8/(8+2) = **80%**.
2. 멀티 에이전트로 바꾸기 전에 꼭 있어야 하는 두 가지는? → **평가셋**과 **기준선**. 없으면 나아졌는지 말할 수 없음.
</details>
