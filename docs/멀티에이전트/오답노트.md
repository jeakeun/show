# 오답노트

퀴즈에서 틀리거나 반만 맞힌 문제를 모읍니다. 며칠 뒤 다시 풀어서 맞히면 ✅ 표시합니다.

**지금까지의 공통점**: 용어 뜻은 알지만 **"누가 하는 일인가, 어느 단계인가"의 경계**가 헷갈림.

| 날짜 | 교시 | 문제 | 내 답 | 정답과 핵심 | 다시 풀기 |
|---|---|---|---|---|---|
| 10-22 | 1 | 회고가 본문 0자로 실패한 건 어느 용어와 관련? | 환각 | **토큰.** 쓸 수 있는 양이 바닥나 끊긴 것. 답이 **틀리면** 환각, **잘리거나 비면** 토큰 한도 | ✅ 10-22 5교시 복습("-76% 급락" = 환각)에서 구분함 |
| 10-22 | 1 | 컨텍스트에 자료를 많이 넣으면 무조건 좋나? | 아니요, 오래 걸려서 (반만 맞음) | 아니요. **돈**(토큰=요금), **책상 크기**(컨텍스트 윈도우 한계), **헷갈림**(관련 없는 자료가 섞임) → 그래서 RAG | |
| 10-22 | 2 | "ERR-4021" 같은 코드는 어떤 검색이 유리? | 청킹 | **키워드 검색.** 청킹은 미리 자르는 준비 작업이지 찾는 방법이 아님. 코드는 뜻이 없어서 뜻 검색은 비슷하게 생긴 다른 코드와 헷갈림 → 하이브리드 | |
| 10-22 | 3 | 유튜브 파이프라인은 워크플로? 에이전트? | 에이전트 (대본을 AI가 써서) | **워크플로.** 기준은 "AI가 일하나"가 아니라 "다음 단계를 누가 정하나". 순서는 코드가 정함. 대본 칸 안에서 AI가 검색 여부를 정하면 그 칸만 작은 에이전트 | |
| 10-22 | 3 | 함수 호출에서 도구를 실제로 실행하는 건? | LLM | **프로그램.** LLM은 주문서만 씀. 그래서 프로그램 쪽에서 막거나 승인을 걸 수 있음 (05 예제) | ✅ 10-22 4교시 복습에서 맞힘 |
| 10-22 | 4 | 사람 승인은 어디에 거나? | 대본 검수 (반만 맞음) | **도구를 실행하기 직전.** 검수 = AI가 품질 검사(자동), 승인 = 사람이 실행 허락. LangGraph는 업로드 노드 앞 interrupt. 매일 반복 업로드는 검수만, 되돌릴 수 없는 일에만 사람 승인 | |
| 10-22 | 5 | 정답 10개, AI가 12개 냈고 9개 맞음. 재현율·정밀도는? | 모르겠음 | 재현율 = 맞힌 수 ÷ **정답 수** = 9/10 = **90%** (빠뜨림). 정밀도 = 맞힌 수 ÷ **낸 수** = 9/12 = **75%** (섞임). 분모만 기억 | |
