# 1단계 · 내 설계 결정 기록 (Architecture Decision Records)

운영 중인 자동화에서 내가 실제로 내린 설계 결정 10개입니다.
각 결정은 **상황 → 고민한 선택지 → 결정 → 이유 → 대가 → 결과 → 업계 원칙과 연결 → 면접 한 줄** 순서로 적었습니다.
면접 답변 형식(상황·과제·행동·결과)으로 바로 옮길 수 있습니다.

숫자는 메모리와 운영 기록에 남은 것만 썼습니다. **"확인 필요"** 는 메인 PC 최신 로그로 채울 곳입니다.

## ADR-01. 만드는 AI와 검사하는 AI를 나눈다

**날짜**: 2026-08-27 · **프로젝트**: 유튜브 대본 검수 게이트(`scriptgen.critique_script`), AI데일리 검수 에이전트

- **상황**: 대본에 의료 조언 같은 정책 위험 표현이나 구독 멘트 누락이 섞일 수 있음. 업로드는 무인 자동이라 사람이 보지 못함.
  AI데일리 결과물도 형식·링크·한글 깨짐 문제가 생길 수 있음.
- **선택지**
  - A. 작성 지시문에 규칙을 더 넣는다
  - B. 같은 AI에게 "다시 검토해"라고 한다
  - C. 별도 검수 AI가 기준표로 채점한다
  - D. 사람이 검토한다
- **결정**: C에 코드 사후검사(제목·의료 단어 정규식)를 함께 둔다.
  - 차단급(정책 위험, 구독 멘트 누락)이면 재생성하고, 2번 연속이면 예비 대본으로 바꾼다.
  - 경고급(모호한 훅 등)은 2건 이상일 때만 1회 재생성한다.
- **이유**: 같은 맥락에 있는 AI는 자기 글에 관대하다. 검사 기준을 작성 AI와 분리해야 기준이 흔들리지 않는다. 무인이라 D는 불가능하다.
- **대가**
  - 호출 비용과 시간이 늘어난다.
  - 검수 API가 죽으면 어떻게 할지 정해야 했다. **통과시키기(fail-open)** 를 골랐다. 하루 2편 발행 유지를 더 중요하게 봤기 때문이다.
    대신 코드 사후검사는 항상 강제해서 최소 안전선은 지킨다.
- **결과**: 도입 검증에서 정상 대본 3편은 지적 없이 통과했고, 일부러 만든 의료 조언 가짜 대본은 정확히 차단했다.
- **업계 연결**: 평가자-최적화자 패턴. Cognition 2026 후속 글의 "리뷰 에이전트" 사례와 같은 구조다. 쓰는 건 하나, 검토는 따로.
- **면접 한 줄**: "작성 AI가 자기 글을 검사하면 관대해서 기준표를 가진 별도 검수 AI를 붙였습니다.
  검수가 죽어도 발행은 계속되게 하되, 코드 검사로 최소 안전선은 항상 지키게 했습니다."

## ADR-02. 판단 없는 단계는 에이전트로 만들지 않는다

**날짜**: 2026-08-27 · **프로젝트**: 유튜브 파이프라인

- **상황**: 트렌드 → 대본 → 음성 → 자막 → 렌더 → 업로드의 각 단계를 "부서별 에이전트"로 나누고 감독 에이전트를 두자는 안이 나왔다.
- **선택지**
  - A. 단계마다 에이전트 + 감독 에이전트
  - B. 판단이 필요한 칸만 AI, 나머지는 코드
- **결정**: B. 대본 작성·검수·회고만 AI이고, 음성·자막·렌더·업로드는 코드다.
- **이유**: 렌더나 업로드는 판단이 없는 공정이다. AI를 두면 "감독관 격"이라 비용과 실패 지점만 늘어난다.
- **대가**: 겉보기에 덜 "에이전트스럽다". 데모의 화려함을 포기했다.
- **결과**: 2026-08-02부터 매일 2편 무인 운영.
- **업계 연결**: Anthropic "가장 단순한 방법으로 시작하고 필요할 때만 복잡도를 더하라". 직함 기준 분할을 피했다.
- **면접 한 줄**: "멀티 에이전트를 안 쓰는 결정도 설계라고 봅니다. 판단이 없는 단계까지 에이전트로 만들면 비용과 실패 지점만 늘어서, AI는 판단이 필요한 세 칸에만 뒀습니다."

## ADR-03. 분석 AI는 제안만, 적용은 코드 한 곳에서

**날짜**: 2026-09-07 · **프로젝트**: 전체 (수집·규칙·분석·실행 4칸 구조, `docs/역할구조.md`)

- **상황**: 회고 AI가 설정·프롬프트를 직접 고칠 수 있으면 잘못된 분석이 곧바로 실행에 반영된다.
  실제로 코인 주간 회고 AI가 저장소 루트에 임시 분석 스크립트(`_wk.py`)를 만든 일이 있었다 (2026-09-06).
- **선택지**
  - A. 회고 AI가 직접 수정
  - B. 회고 AI는 제안 파일만 쓰고 코드가 적용
  - C. 사람만 수정
- **결정**: B에 가드를 더한다.
  - 분석 AI는 리포트와 `*_proposed.md` 만 쓴다.
  - 적용은 `src.approve` 코드만 한다. 이전본을 보관하고 승인 기록을 남긴다.
  - 보호 파일은 해시를 찍어 두고, 바뀌면 원복하고 폰으로 알린다. 루트에 생긴 새 파일은 격리한다.
- **이유**: 쓰기 경로가 한 곳이면 무엇이 언제 왜 바뀌었는지 추적하고 되돌릴 수 있다. AI 권한은 필요한 만큼만 준다.
- **대가**: 적용까지 한 단계가 늘어난다. 이 비용은 ADR-07에서 다시 조정했다.
- **결과**
  - 9/6 가드가 `_wk.py` 를 격리했다 (정상 작동).
  - 코인 주간 회고는 처음 만들 때(8/21)부터 "제안만, 직접 수정 금지" 규칙이었다. 첫 회고가 결함(트레일링 1.5%/1.5% 설정은 사실상 본전 청산 구조)을 찾아 제안했고, 검토 후 2.0%/1.0%로 적용했다.
    9/7에 이 규칙을 전체 프로젝트로 넓힌 것이 4칸 구조다.
- **업계 연결**: Cognition 2026 "생각은 여럿이 보태고, 쓰기는 한 줄기로". 권한 최소화 원칙.
- **면접 한 줄**: "여러 AI가 분석은 하지만 시스템을 실제로 바꾸는 경로는 코드 한 곳뿐입니다. AI가 보호 파일을 건드리면 자동 원복하고 알림이 옵니다."

## ADR-04. 숫자는 코드가, 문장은 AI가

**날짜**: 2026-08-27 감사 이후 · **프로젝트**: AI데일리 `streaks.py`, 유튜브 회고, 대시보드 쉬운 설명

- **상황**
  - 8/27 감사에서 AI데일리 결과물에 실제로 없던 회차(유령 17회차)가 기록된 것이 발견됐다. 그때 "연속 0건" 같은 카운터도 AI가 손으로 세고 있었다.
  - 유튜브 회고는 추적 중인 영상 50편의 합으로 일별 조회수를 계산했다. 옛 영상이 목록에서 밀리면 음수(-697)가 나오는 착시가 생겼고, 회고 AI가 그 숫자로 잘못된 해석을 썼다.
- **선택지**
  - A. 지시문에 "정확히 세라"를 강화
  - B. 코드가 계산해서 AI에게 값을 넘김
- **결정**: B.
  - AI데일리는 회차별 카운트를 구조화된 기록(`tech_counts.jsonl`)으로 남기고, `streaks.py` 가 연속 기록을 계산한다.
  - 유튜브 회고에는 채널 전체 조회수를 따로 넣는다.
  - 쉬운 설명(ELI5)에 원문에 없는 숫자가 나오면 다시 쓰게 한다.
- **이유**: AI는 셈이나 누적 상태 유지에 약하고, 틀려도 그럴듯하다. 계산은 코드가 해야 매번 같은 답이 나온다.
- **대가**: 데이터를 구조화해서 기록하는 일이 늘었다.
- **결과**: 카운터 계산 근거가 파일로 남아 감사할 수 있게 됐다. 이후 정확도는 **확인 필요**.
- **업계 연결**: AI와 코드의 경계. market-compass도 "숫자는 코드만 계산"을 원칙으로 삼았다.
- **면접 한 줄**: "AI에게 맡길지 코드에게 맡길지는 '매번 같은 답이 나와야 하는가'로 나눴습니다. 계산은 코드, 해석과 문장은 AI입니다."

## ADR-05. 회고는 다른 AI가 반박 검증한다

**날짜**: 2026-08-27 · **프로젝트**: 유튜브 주간 회고 팩트체크(`insights._factcheck`)

- **상황**: 주간 회고 AI가 쓴 전략(플레이북)이 다음 주 대본 방향이 된다. 출처 없는 주장, 표본이 적은 결론, 과한 목표가 섞이면 그대로 실행된다.
- **결정**: 별도 AI가 회고를 반박 검증한다.
  - 출처 없는 주장은 삭제하고, 표본 부족은 표시하고, 과한 목표는 낮춘다.
  - 리포트에 검증 노트를 붙인다.
  - 길이 가드를 둔다. 검증 AI가 리포트를 요약해 버리는 오작동을 막기 위해서다.
- **이유**: 회고 AI는 자기가 세운 가설에 유리하게 해석하기 쉽다. 반박 역할을 따로 둬야 균형이 맞는다.
- **대가**: 호출 비용이 늘었다. 9/7에 검증 모델을 하이쿠로 내려 비용을 줄였다.
- **결과**: 이 원칙은 대화형 작업에서 먼저 효과를 봤다. 8/23부터 클로드가 낸 전략 제안과 코드 변경을 검토 에이전트가 먼저 반박하게 했더니,
  첫 적용에서 과대 목표치·규칙 충돌·정책 위험·무인 실행 버그 6건을 잡았다. 그 경험을 8/27 무인 회고에 옮긴 것이다.
- **업계 연결**: 평가자 패턴의 적대적(반박) 버전.
- **면접 한 줄**: "회고 AI가 쓴 전략은 다른 AI가 반박부터 합니다. 출처 없는 주장은 지우고, 표본이 적으면 표시하고, 과한 목표는 낮춥니다."

## ADR-06. 감사는 읽기 전용 에이전트를 병렬로

**날짜**: 2026-08-27 (이후 매주 일요일 10:00 자동) · **프로젝트**: 자가감사

- **상황**: 프로젝트가 늘면서 리포트가 실제 데이터와 맞는지 아무도 대조하지 않았다.
- **결정**: 읽기 전용 감사 에이전트 3기를 병렬로 돌린다. 각자 리포트의 주장을 원본 데이터와 대조하고, 발견은 심각도순으로 낸다.
  이후 주간 자동 감사로 만들었다. 감사 중에도 보호 파일 해시 가드를 켠다.
- **이유**: 프로젝트별 조사는 서로 독립적이고 넓게 퍼지는 읽기 작업이라 병렬에 맞는다. 읽기 전용이라 서로 충돌할 쓰기가 없다.
- **결과**
  - 8/27 첫 감사: 노출된 API 키, 코인봇 수수료 계산 오류(20.5%), AI데일리 유령 데이터를 발견했다.
    1회차 시험 감사에서는 8건을 발견했고, 검증 후 6건을 실제로 고쳤다.
  - 9/6 감사: 채널 조회수 수집이 9/2부터 멈춘 것, 손절 15건 모두 -2%를 넘겨 체결된 것(평균 -2.94%)을 발견했다.
- **대가·교훈**: 감사 리포트도 틀릴 수 있다. 한 건을 "오탐"이라고 잘못 반박했다가 로그를 다시 보고 정정했다.
  그래서 감사 결과도 검증 대상으로 둔다.
- **업계 연결**: Anthropic 리서치 시스템과 같은 "읽기 중심 병렬" 구조.
- **면접 한 줄**: "감사는 읽기 전용이라 병렬로 돌려도 충돌이 없습니다. 첫 감사에서 노출된 API 키와 코인봇 수수료 계산 오류를 찾았습니다."

## ADR-07. 사람 승인 위치는 "되돌릴 수 있는가"로 정한다

**날짜**: 2026-09-07 승인 게이트 → 2026-09-21 선조치 후보고 · **프로젝트**: 전체

- **상황**
  - 9/7부터 회고 제안을 모두 사람이 승인했다. 그런데 9/20 플레이북이 승인 대기로 하루 묵어 9/21 적용 시작을 놓쳤다.
  - 비개발자인 운영자에게 승인 판단이 부담이었다.
  - 반대 방향의 교훈도 있다. 품질 문제로 이미 올린 영상을 지우고 다시 올렸더니, 유튜브가 중복으로 보고 노출을 거의 주지 않았다 (16시간 조회 2회).
    이미 밖으로 나간 것은 되돌릴 수 없었다.
- **선택지**
  - A. 모두 승인
  - B. 모두 자동
  - C. 되돌릴 수 있는 변경은 자동 적용 후 보고, 되돌릴 수 없는 결정은 사람
- **결정**: C.
  - 플레이북과 프롬프트 개선은 자동 적용한다. 이전본을 보관하고, 프롬프트는 문법·스모크 테스트 실패 시 자동 원복한다. 적용 후 폰과 바탕화면으로 보고한다.
  - 돈이 드는 결정, 영상 삭제·공개 전환, 실전 매매 전환은 계속 사람이 정한다.
  - 사람이 정할 것은 리포트에 A/B/C/D 선택지로 올라온다.
  - 품질은 업로드 **전** 게이트로만 잡고, 이미 나간 영상은 교체하지 않는다.
- **이유**: 승인의 가치는 되돌릴 수 없는 피해를 막는 데 있다. 되돌릴 수 있는 변경까지 막으면 속도만 잃는다.
- **결과**: 적용 지연 문제가 사라졌다. 사람이 정할 결정은 "1A 2B"처럼 답하는 형식으로 정리됐다 (9/28~).
- **업계 연결**: Human-in-the-loop 위치 설계. 비가역 행동 앞에 게이트를 둔다.
- **면접 한 줄**: "처음엔 전부 승인받게 했다가 적용이 하루 밀리는 걸 겪고, 되돌릴 수 있는 건 자동 적용 후 보고, 되돌릴 수 없는 건 사람으로 기준을 바꿨습니다."

## ADR-08. 역할마다 모델을 다르게, 비용은 호출마다 기록

**날짜**: 2026-09-07 · **프로젝트**: 유튜브 (`src/apicost.py`)

- **상황**: 실측 월 US$51(앤트로픽) + 제미나이 약 ₩6천. 목표는 US$30 이하.
- **결정**
  - 판단 난이도에 맞춰 모델을 배정했다. 주간 분석은 상위 모델, 대본은 중간 모델, 검수·팩트체크는 하이쿠.
  - 대본 지시문은 프롬프트 캐싱으로 재사용했다.
  - 회고는 일요일에만 돌린다.
  - 모든 호출의 비용을 기록하고, 대시보드에 "매일 운영비"와 "주간 분석비"로 나눠 보여준다.
- **이유**: 측정하지 않으면 줄일 수 없다. 모든 칸에 상위 모델을 쓸 이유가 없다.
- **대가·실패**: 비용을 줄이려고 회고의 출력 한도를 16,000 → 10,000 토큰으로 낮췄다. 그런데 상위 모델은 사고(thinking) 토큰도 이 한도에 포함돼서, 사고만 하다 한도를 다 쓰고 본문 0자로 실패했다 (9/13).
  US$0.76이 낭비됐고 실패 알림도 없었다.
  수정 내용은 이렇다.
  - 한도를 24,000으로 올렸다.
  - 사고 강도를 중간으로 낮췄다.
  - 한도 초과로 멈추면 명시적 오류로 처리하게 했다.
  - 실패하면 폰으로 알린다.
- **결과**: 하이쿠 검수 호출당 약 US$0.0015 (실측). 월 총액 변화는 **확인 필요**.
- **업계 연결**: 멀티 에이전트는 토큰을 많이 쓴다 (Anthropic 측정 약 15배). 그래서 역할별 모델 선택과 비용 측정이 필수다.
- **면접 한 줄**: "역할마다 모델을 다르게 썼고, 모든 호출 비용을 기록했습니다. 비용을 줄이다 사고 토큰 때문에 회고가 실패한 적이 있어서, 지금은 비용과 함께 실패율도 같이 봅니다."

## ADR-09. 실패는 조용히 나지 않게, 성공은 결과물로 판정

**날짜**: 2026-08-27 ~ 09-08 · **프로젝트**: 전체 (폰 알림 `notify`)

- **상황**
  - 8/26 제미나이 월 지출 한도 초과로 이미지·음성 생성이 막혔다. 영상 2편이 이모지 배경과 예비 음성으로 조용히 발행됐다.
  - 9/6 감사 "실패" 알림은 오탐이었다. 리포트는 정상이었는데 AI가 완료 표시 문구를 빼먹었다.
  - 9/8 구독 로그인 만료로 헤드리스 작업 전부가 실패했다.
- **결정**
  - 모든 자동화 실패와 품질 저하 발행은 바탕화면 경고 파일과 폰 푸시로 알린다.
  - 성공 판정은 AI가 출력한 문구가 아니라 **결과물 파일 실존(800바이트 초과) + 종료 코드 0** 으로 한다.
- **이유**: 운영자가 "왜 안 올라갔지?"라고 묻기 전에 시스템이 먼저 알려야 한다. AI 출력 형식은 흔들리니 판정은 관측 가능한 결과물로 한다.
- **대가**: 알림이 많아지면 무시하게 된다. 알림 자체가 실패해도 본 작업은 죽지 않게 했다.
- **후속 과제**: 시작 전에 로그인 상태를 미리 점검하는 기능은 제안 단계다 (**적용 여부 확인 필요**).
- **업계 연결**: 에이전트 관측성(observability).
- **면접 한 줄**: "AI가 '완료'라고 말하는 것과 실제로 완료된 것은 다릅니다. 그래서 성공은 결과물로 판정하고, 조용한 품질 저하도 알림으로 올라오게 했습니다."

## ADR-10. 법 규정 검사는 AI가 아니라 규칙 엔진으로

**날짜**: 2026-09 (개발 중) · **프로젝트**: market-compass

- **상황**: 마케팅 메시지가 정보통신망법이나 카카오 정책을 어기면 제재·과태료를 받는다. 틀리면 안 되고, 왜 막혔는지 설명할 수 있어야 한다.
- **결정**
  - 대상 판단(Radar)과 문구 생성은 AI가 한다.
  - 규정 검사(Guard)는 코드 규칙 R01~R12와 테스트로 한다.
  - 사람이 두 번 승인한다.
  - 발송(Dispatch)은 한 경로에서만 한다.
- **이유**: 법 규정 판정은 매번 같아야 하고, 규칙 번호로 이유를 설명할 수 있어야 한다. AI 판정은 그럴듯하지만 재현과 설명이 어렵다.
- **결과**: 9/7 기준 Guard 테스트 24/48 통과 (2일차). 이후 진행은 **확인 필요**.
- **업계 연결**: 가드레일을 결정적 코드로 두는 설계. 쓰기(발송) 단일화.
- **면접 한 줄**: "자동보다 '안 걸리게'가 목표라, 규정 검사는 AI가 아니라 테스트가 붙은 규칙 엔진으로 만들고 발송 경로는 하나로 묶었습니다."
