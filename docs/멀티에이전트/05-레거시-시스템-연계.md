# 레거시 시스템 연계 (Agent Action)

> 목표 공고 담당업무: "Legacy System과 연계 (Agent Action에 필요한)"
> 예제는 2026-10-22에 실제로 실행해 확인했습니다 ([예제/06_legacy_tools.py](예제/06_legacy_tools.py)).

## 1. 공고가 말하는 것

에이전트가 말만 하는 게 아니라 실제 일(조회, 등록, 변경, 발송)을 하려면 **회사에 이미 있는 시스템**을 불러야 합니다.
ERP, 그룹웨어, 사내 DB, 오래된 REST·SOAP API, 배치 파일 같은 것들입니다. 이 연결을 안전하게 만드는 일입니다.

에이전트 입장에서 레거시 시스템은 **도구(Tool)** 입니다.
면접에서 이 업무는 결국 **"어떤 도구를, 어떤 권한으로, 어떤 안전장치와 함께 주는가"** 를 설계하는 일입니다.

## 2. 연결 방식 4가지

| 방식 | 언제 | 어떻게 |
|---|---|---|
| **API를 도구로 감싸기** | 레거시에 REST·SOAP API가 있을 때 | `@tool` 함수 안에서 API 호출, 결과를 AI가 읽기 좋게 정리해 반환 |
| **DB 조회 도구** | API가 없고 DB 접근만 될 때 | 읽기 전용 계정 + **미리 정한 쿼리와 파라미터** |
| **MCP 서버로 감싸기** | 여러 에이전트·여러 AI 클라이언트가 같은 시스템을 써야 할 때 | 사내 MCP 서버 하나에 도구를 모아 표준 방식으로 노출 |
| **파일·배치·화면 자동화** | API도 DB도 없을 때 | 정기 내보내기 파일을 읽거나, 마지막 수단으로 화면 자동화 (불안정) |

## 3. 설계 원칙 9가지 (내 운영 경험에서 온 것)

| # | 원칙 | 이유 | 내 운영 경험 |
|---|---|---|---|
| 1 | **읽기 도구와 쓰기 도구를 나눈다.** 쓰기는 사람 승인 뒤에 | 조회는 틀려도 되돌릴 수 있지만 등록·발송은 못 되돌림 | ADR-07 "되돌릴 수 있는가" |
| 2 | **자유 SQL 대신 정해진 쿼리** | AI에게 아무 SQL이나 주면 대량 조회, 개인정보 노출, 테이블 잠금 위험 | 분석 AI 권한 최소화 (ADR-03) |
| 3 | **도구 설명문 = 계약서** | AI는 설명문만 보고 부름. 입력 형식, 단위, 한도, 실패 시 반환값을 적음 | — |
| 4 | **같은 요청이 두 번 와도 한 번만 처리 (멱등성)** | 재시도하다 이중 등록·이중 결제가 남 | 해외 미러는 업로드 직후 기록(중복 업로드 방지), 코인은 매매 직후 상태 저장(이중 매도 방지) |
| 5 | **실패를 AI가 판단할 수 있는 말로** | "타임아웃 → 다시 시도", "권한 없음 → 사람에게" 처럼 다음 행동을 고를 수 있게 | 업로드 5회 백오프 재시도 |
| 6 | **레거시를 보호한다** | 오래된 시스템은 부하에 약함. 호출 횟수 제한, 타임아웃, 캐시 | 코인 뉴스 30분 캐시, 예약 시간 겹침 금지 |
| 7 | **누가 언제 무엇을 불렀는지 기록** | 사고 났을 때 추적, 감사 | 승인 기록(`approvals.jsonl`), 가드 로그 |
| 8 | **비밀은 코드·프롬프트에 넣지 않는다** | 프롬프트·로그로 새어 나감 | `secrets/` 커밋 금지, 노출 키 사건 (ADR-06) |
| 9 | **숫자는 도구가 계산해서 돌려준다** | AI가 레거시 데이터를 다시 세면 틀림 | ADR-04 |

## 4. 예제 — 읽기 도구는 바로, 쓰기 도구는 승인 뒤에

```python
@tool
def get_channel_views(start_day: str, end_day: str) -> str:
    """채널 일별 조회수를 조회한다. 날짜는 YYYY-MM-DD. 최대 31일. 읽기 전용."""
    rows = legacy.execute(                      # 자유 SQL 대신 정해진 쿼리 + 파라미터
        "SELECT day, views FROM channel_daily WHERE day BETWEEN ? AND ? ORDER BY day LIMIT 31",
        (start_day, end_day)).fetchall()
    total = sum(v for _, v in rows)             # 숫자는 도구가 계산
    return f"{len(rows)}일, 합계 {total}회, 일별 {rows}"

@tool
def pause_uploads(reason: str) -> str:
    """자동 업로드를 일시 중지한다. 되돌리기 어려운 쓰기 작업이라 사람 승인이 필요하다."""
    ...

agent = create_agent(
    model=model,
    tools=[get_channel_views, pause_uploads],
    middleware=[
        HumanInTheLoopMiddleware(interrupt_on={"pause_uploads": True}),  # 쓰기 도구만 승인
        ToolCallLimitMiddleware(run_limit=5),                            # 폭주 방지
    ],
    checkpointer=InMemorySaver(),
)
```

**실행 결과** (모델은 정해진 순서로 도구를 부르는 시험용 가짜 모델)

| 순서 | 일어난 일 | DB `paused` 값 |
|---|---|---|
| 1 | 조회 도구는 승인 없이 바로 실행: "3일, 합계 5940회" | 0 |
| 2 | 쓰기 도구 호출 직전에 멈추고 승인 요청 (`pause_uploads`) | **0 (아직 안 바뀜)** |
| 3 | `Command(resume={"decisions": [{"type": "approve"}]})` 로 승인 → 실행 | 1 |

승인 전에는 레거시 DB가 전혀 바뀌지 않았습니다. 이게 "쓰기는 사람 승인 뒤에"를 코드로 보장하는 방법입니다.

## 5. 내가 이미 해본 외부 시스템 연동

공고의 "레거시"는 아니지만, **남이 만든 시스템을 에이전트·자동화의 도구로 붙여본 경험**으로 말할 수 있습니다.

| 연동 대상 | 방식 | 겪은 문제와 대응 |
|---|---|---|
| YouTube Data·Analytics API | 공식 API, OAuth | 지운 영상을 다시 올렸더니 노출이 거의 없었음(중복 취급으로 추정) → 이미 나간 건 교체하지 않음 |
| 업비트 시세 | 공개 API (인증 없음) | — |
| 인스타그램·쓰레드 | Graph API, 텍스트 API | 권한 이름이 연동 방식마다 달라 공식 문서로 재검증 |
| 티스토리 | **오픈 API가 종료돼 브라우저 자동화** | API가 없는 레거시를 화면 자동화로 붙이는 마지막 수단의 예 |
| 뉴스 RSS | 피드 수집 | 죽은 피드(410) → 대체 피드로 교체 |
| 노션·깃허브·취몽 | MCP | 표준 도구 연결 |

**Java·Spring 경험 살리기**: 교육 과정에서 Java·Spring Boot·React·AWS를 이수했습니다. 실제 기업의 레거시는 Java·Spring으로 된 경우가 많습니다.
"레거시 쪽 코드를 읽고, 그 API를 파이썬 에이전트 도구나 MCP 서버로 감쌀 수 있다"는 건 이 공고에 맞는 강점입니다.
2단계 프로젝트에서 **작은 Spring Boot API를 레거시 역할로 두고, 에이전트가 그 API를 도구로 부르게** 만들면 직접 보여줄 수 있습니다.

## 6. 면접 질문

<details><summary>Q1. 에이전트를 레거시 시스템에 연결할 때 가장 먼저 무엇을 보나요?</summary>

그 시스템을 읽기만 하는지, 쓰기도 하는지부터 나눕니다. 조회는 도구로 바로 열고, 등록·변경·발송 같은 쓰기는 사람 승인 뒤에 둡니다.
그다음 연결 수단을 봅니다. API가 있으면 API를 도구로 감싸고, 없으면 읽기 전용 DB 계정과 정해진 쿼리, 그것도 안 되면 파일이나 화면 자동화 순서로 봅니다.
</details>

<details><summary>Q2. 에이전트에게 SQL을 직접 쓰게 해도 되나요?</summary>

운영 DB에서는 피합니다. 대량 조회로 부하를 주거나, 개인정보를 꺼내거나, 잠금을 걸 수 있습니다.
정해진 쿼리에 파라미터만 받는 도구를 만들고, 읽기 전용 계정, 행 수 제한, 시간 제한을 겁니다.
분석용으로 자유 SQL이 꼭 필요하면 복제본 DB와 허용 테이블 목록 안에서만 허용합니다.
</details>

<details><summary>Q3. 에이전트가 같은 작업을 두 번 실행하면요?</summary>

같은 요청이 두 번 와도 한 번만 처리되게 요청 ID를 붙이고, 실행 직후 결과를 기록해서 재시도 때 확인합니다.
제 운영 시스템에서도 해외 채널 업로드 직후 기록을 남겨 중복 업로드를 막았고, 코인 매매는 매수·매도 직후 상태를 저장해 이중 매도를 막았습니다.
</details>

<details><summary>Q4. 사람 승인은 코드로 어떻게 보장하나요?</summary>

LangChain의 `HumanInTheLoopMiddleware` 로 쓰기 도구 호출 직전에 멈추게 합니다. 상태는 체크포인터에 저장되고, 사람이 승인하면 `Command(resume=...)` 로 이어서 실행합니다.
예제에서 승인 전에는 레거시 DB 값이 바뀌지 않았고, 승인 후에만 바뀌는 걸 확인했습니다.
</details>

<details><summary>Q5. MCP는 레거시 연계에서 왜 쓰나요?</summary>

도구를 MCP 서버 하나에 모아두면 여러 에이전트와 AI 클라이언트가 같은 방식으로 씁니다. 연동 코드를 에이전트마다 따로 짤 필요가 없습니다.
권한·로그·호출 제한도 서버 한 곳에서 관리할 수 있어서, 레거시 보호와 감사에 유리합니다.
</details>
