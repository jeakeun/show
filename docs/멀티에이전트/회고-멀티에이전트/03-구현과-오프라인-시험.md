## 3. 결과 — 같은 심사위원으로 채점한 비교

심사위원: `claude-sonnet-5-5`. 참고 자료: 코드 숫자표·가설 채점·일별 추이·직전 리포트 (모두 10/18 시점). 두 문서 끝의 자체 검증 노트는 빼고 본문만 채점.

| 지표 | 기존 회고 (10/18 실제) | 새 회고 (그림자) |
|---|---|---|
| 근거 없는 주장 수 | 14 | **6** |
| 표본 부족 단정 수 | 3 | 3 |
| 과대 목표 수 | 0 | 0 |
| 주인 결정 위반 수 | 1 | 2 |
| 다음 기간 가설 수 | 3 | 3 |
| 비용 | US$1.66 | US$1.92 (작성자 1.84 = 첫 초안 0.88 + 고친 초안 0.96, 나머지 0.08) |
| 걸린 시간 | 약 7.6분 | 약 7.1분 (분석가 3명이 동시에 20~37초) |
| 근거 번호 표시 | 0 | 84 |
| 자체 팩트체크 | 직접 고침 | 지적 11 → 고친 뒤 다시 12 |

| 보호 파일 | — | 실행 전후 해시 같음 |

**조심해서 읽을 점**
- **표본 1회입니다.** 한 번 비교로 결론 내리지 않습니다. 3주 그림자 운영으로 반복합니다.
- **심사위원도 흔들립니다.** 참고 자료에 일별 추이를 넣기 전에는 같은 문서를 9 대 8로 채점했고, 넣은 뒤 14 대 6이 됐습니다. 심사위원에게 무엇을 주느냐가 결과를 바꿉니다. 그래서 그림자 기간에는 참고 자료를 고정합니다.
- 벤치마크·인기 급상승·시청자 댓글은 10/18 시점으로 맞출 수 없어 오늘 값을 썼습니다.
- **고친 초안이 지적을 줄이지 못했습니다(11 → 12).** 작성자가 지적된 곳을 고치면, 팩트체커가 다른 곳을 새로 찾았습니다. "되돌림 1회"가 품질을 올렸는지는 첫 초안과 고친 초안을 같은 심사위원으로 채점해 그림자 기간에 따로 봅니다(되돌림 비용이 US$0.96 이라 효과가 없으면 빼는 것이 맞음).

## 4. 심사위원이 찾은 문제 (일부)

- 기존 회고: "저녁편 48h 는 데이터에 따로 없어 누적 조회로 대신했다"(숫자표에는 48h 가 있음), 48h 지표라면서 현재 조회로 계산한 905 등 — 한 AI 가 24만 토큰 원자료를 직접 계산하다 생긴 오류가 많았습니다.
- 새 회고: 근거 카드 문장을 그대로 옮기면서 생긴 과장(" 2편만으로도 큰 실패는 걸러낼 수 있다"), 주인 결정 규칙("10/25 회고에서 750 기준으로 판정")을 "판정하지 않는다"로 바꾼 것 2건.

## 학습노트 — 3단계 (구현·시험)

**무엇을 했나**
- LangGraph 로 회고 그래프를 만들고, 운영 회고와 같은 모델·호출 코드로 작성자를 두었습니다.
- 10/18 시점으로 자료와 규칙을 맞춰 돌리고, 같은 심사위원으로 실제 회고와 나란히 채점했습니다.
- 실패 2번을 체크포인트 기록으로 원인까지 찾아 고쳤습니다.

**왜 이렇게 했나 (대안과 버린 이유)**
- 오늘 자료로 시험하는 대안: 쉽지만 비교 상대가 없습니다. 10/18 실제 회고와 같은 시점이어야 "구조 차이"만 남습니다.
- 운영 팩트체크 결과를 채점 기준으로 쓰는 대안: 운영 쪽은 직접 고친 뒤 결과만 남고, 새 쪽은 지적만 남아 기준이 달라집니다. 그래서 제3의 심사위원을 같은 조건으로 붙였습니다.
- 규칙을 오늘 판으로 쓰는 대안: 시험이 미래 정보를 보게 됩니다(실제로 2회차에서 그랬음). git 기록에서 그날 판을 꺼내는 쪽을 택했습니다.

**새 용어**

| 용어 | 한 줄 뜻 | 비유 |
|---|---|---|
| 오프라인 시험 | 지난 자료로 새 시스템을 돌려 실제 결과와 비교하는 것 | 지난 시험지를 새 공부법으로 다시 풀어 보기 |
| 미래 정보 누수 | 과거 시점 시험에 그 뒤에 생긴 정보가 섞이는 것 | 답안지를 보고 푼 모의고사 |
| 심사위원 모델 (LLM-as-judge) | 두 결과를 같은 기준으로 채점하는 별도 AI | 두 반 시험지를 같은 채점자가 채점 |
| 구조화 출력 (json_schema) | AI 답을 정해진 칸에 맞춰 받는 것. 이 방식은 생각(thinking)을 끄지 않음 | 서식 있는 신청서 |
| 체크포인트 재개 | 칸마다 저장된 상태에서 이어 가거나 열어 보는 것 | 게임 세이브 불러오기 |
