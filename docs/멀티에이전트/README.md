# 멀티 에이전트 공부 — "왜 이렇게 설계했나"까지 설명하는 나 만들기

> 시작: 2026-10-22 · 목적: AX 취업 면접 대비

면접에서 멀티 에이전트 질문을 받으면 교과서 정의가 아니라
**내가 직접 만들고 운영하면서 내린 결정과 그 근거(숫자)** 로 답할 수 있게 만드는 것이 목표입니다.

## 왜 이 순서인가

1. **이미 운영 중인 것부터 설명한다.** 유튜브·AI데일리·코인·자가감사는 이미 여러 AI가 역할을 나눠 일하는 시스템입니다.
   면접관이 가장 믿는 건 "실제로 돌려본 경험"이라, 새로 만드는 것보다 이걸 정확히 설명하는 게 먼저입니다.
2. **새 멀티 에이전트를 프레임워크 없이 한 번 직접 짠다.** LangGraph 같은 도구가 숨겨주는 것
   (반복 루프, 에이전트 사이 정보 전달, 도구 호출)을 손으로 짜봐야 "왜"를 설명할 수 있습니다.
3. **같은 걸 프레임워크로 다시 만들어 비교한다.** 그래야 "LangGraph 써봤어요?"에
   "직접 짠 버전과 비교해 보니 이런 점이 편하고 이런 점은 과했다"고 답할 수 있습니다.
4. **면접 질문으로 말해본다.** 아는 것과 말할 수 있는 것은 다릅니다.

### 2단계 세부 순서 (주제와 상관없이 같음)

| # | 만드는 것 | 배우는 것 |
|---|---|---|
| 2-1 | 도구를 쓰는 에이전트 1개 | 에이전트 루프, 도구 호출, 멈춤 조건 |
| 2-2 | 검수 에이전트 추가 | 평가자-최적화자 패턴, 재시도 한도 |
| 2-3 | 지휘자 + 병렬 작업자 | 오케스트레이터 패턴, 맥락 분리, 결과 합치기 |
| 2-4 | 가드와 사람 승인 | 권한 최소화, 쓰기 단일화, 되돌릴 수 있는가 |
| 2-5 | 평가: 에이전트 1개 vs 여러 개 실측 비교 | 평가셋, 채점 기준, "멀티가 정말 나은가"를 숫자로 |
| 2-6 | 비용·실행 기록 남기기 | 토큰 비용, 실행 추적, 장애 알림 |

2-5가 핵심입니다. "멀티 에이전트로 바꿨더니 정확도 X%가 올랐고 비용은 Y배 들었다"를
직접 잰 숫자로 말할 수 있으면, 그 자체로 면접에서 가장 강한 답이 됩니다.

## 공부하는 방법

- 각 문서 끝의 **스스로 점검 질문**을 소리 내어 답해보고, 접힌 답과 비교합니다.
- 막히는 질문은 클로드에게 "이 질문 모의면접 해줘"라고 하면 꼬리 질문까지 이어서 연습합니다.
- 설계 결정 기록에서 숫자는 **실제 운영 기록(메모리·로그)에서 온 것만** 씁니다.
  "확인 필요"라고 적힌 곳은 메인 PC에서 최신 로그로 확인한 뒤 고칩니다.
