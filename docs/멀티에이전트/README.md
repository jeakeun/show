# 멀티 에이전트 공부 — "왜 이렇게 설계했나"까지 설명하는 나 만들기

> 시작: 2026-10-22 · 목적: AX 취업 면접 대비 · 기준 공고: LangChain 기반 AI Agent 개발 (아래)

면접에서 멀티 에이전트 질문을 받으면 교과서 정의가 아니라
**내가 직접 만들고 운영하면서 내린 결정과 그 근거(숫자)** 로 답할 수 있게 만드는 것이 목표입니다.

이 폴더에서 "내가 만든 것"은 **운영자인 내가 설계·운영하고 클로드 코딩 에이전트가 구현한 것**을 말합니다.
면접에서도 "설계하고 운영했으며, 구현은 AI 코딩 도구와 함께 했다"고 정확히 말합니다.

## 2단계 프로젝트: 맞춤 지원서 에이전트

공고 하나를 넣으면 요구사항을 뽑고, 내 경력 문서에서 근거를 찾아 적합도를 계산합니다.
그다음 **모든 문장에 근거가 달린** 자기소개서·이력서 강조점 초안을 만들고, 사람이 확정하면 지원 이력에 등록합니다.

```
공고 ──→ [① 공고 분석가] 요구 항목을 구조화된 목록으로
              │
              ├─→ [② 근거 검색가] × 요구 항목 수   ← 내 경력 문서 RAG. 읽기라 병렬(Send)
              │
         [③ 적합도 계산] 코드                       ← 숫자는 코드가
              │
         [④ 작성자] 1명                              ← 쓰기는 한 곳. 문장마다 [근거 번호]
              │
         [⑤ 검증가] 근거 없는 문장·과장 표현 검사 ──→ 문제 있으면 ④로 (최대 2회)
              │
         [⑥ 사람 확정] interrupt                    ← 되돌릴 수 없는 일 앞
              │
         [⑦ 지원 이력 등록] 레거시 API 도구          ← 조회는 자유, 등록은 승인 뒤. 같은 공고 중복 등록 방지
```

### 왜 이렇게 나눴나 (설계 이유 초안)

| 결정 | 이유 | 연결된 내 경험 |
|---|---|---|
| 공고 분석을 따로 둔다 | 공고만 보는 맥락에서 구조화된 목록을 만들어야 평가가 쉬움 (추출 정확도를 따로 잴 수 있음) | 맥락 분리 (01) |
| 근거 검색을 요구 항목별로 병렬로 | 항목끼리 독립적이고 읽기 전용이라 나눠도 충돌이 없음 | 읽기는 나눈다 (ADR-06) |
| 적합도 점수는 코드가 | AI가 센 숫자는 부풀었던 전례 | ADR-04 |
| 작성자는 한 명 | 여러 명이 쓰면 말투·주장이 어긋남 | 쓰기는 한 곳 (Cognition) |
| 검증가는 작성자와 다른 맥락에서 | 자기 글은 관대하게 봄. **이 공부 자료를 만들 때 검토 에이전트가 과장·근거 없는 표현 53개를 잡아낸 경험을 그대로 기능으로 만든 것** | ADR-01·05 |
| 확정과 등록은 사람 승인 뒤에 | 제출한 지원서는 되돌릴 수 없음 | ADR-07 |
| 지원 이력은 별도 API(레거시 역할) | 공고 요구 "레거시 연계"를 보여줌. 작은 Spring Boot API로 만들어 Java·Spring 경험도 살림 | 05 |

### 공고 요구와 연결

| 공고 요구 | 이 프로젝트에서 |
|---|---|
| LangGraph | 병렬 검색(`Send`), 검증 루프(갈림길), 사람 확정(`interrupt`) |
| LangChain | 모델·도구·RAG 부품, 미들웨어 |
| LangFlow | 근거 검색 흐름을 LangFlow로도 만들어 코드와 비교 |
| RAG | 내 경력 문서로 청킹·임베딩·하이브리드 검색, 검색 적중률 측정 |
| 레거시 연계 | 지원 이력 관리 API를 도구로 연결, 등록은 승인 뒤, 중복 등록 방지 |

### 세부 순서

| # | 만드는 것 | 배우는 것 |
|---|---|---|
| 2-1 | **평가셋 먼저**: 공고 10~20개, 공고별 요구 항목 정답, 항목별 정답 근거 | 평가 기준을 만들고 시작하기 |
| 2-2 | 경력 문서 RAG (근거 검색가) | 청킹·임베딩·하이브리드 검색, 적중률 측정 |
| 2-3 | 공고 분석가 + 적합도 계산 | 구조화된 출력, 코드와 AI의 경계 |
| 2-4 | 작성자 + 검증가 루프 (LangGraph) | 평가자-최적화자, 근거 표시, 재시도 상한 |
| 2-5 | 사람 확정 + 지원 이력 API 연결 | `interrupt`, 레거시 도구, 멱등성 |
| 2-6 | **에이전트 1개 vs 여러 개 실측 비교**, 비용·추적 | 근거 없는 문장 비율·비용·시간 |
| 2-7 | LangFlow로 근거 검색 다시 만들기 | 시각적 도구와 코드의 장단점 |

**개인정보 주의**: 공개 저장소라 전화번호·주소 같은 개인정보가 든 문서는 올리지 않습니다.
경력 문서는 이미 공개된 프로젝트 설명 위주로 쓰고, 개인 문서는 깃에서 제외한 로컬 폴더에 둡니다.

## 공부하는 방법

- 각 문서 끝의 **면접 질문**을 소리 내어 답해보고, 접힌 답과 비교합니다.
- 막히는 질문은 클로드에게 "이 질문 모의면접 해줘"라고 하면 꼬리 질문까지 이어서 연습합니다.
- 숫자는 **실제 운영 기록과 실제 실행 결과에서 온 것만** 씁니다. "확인 필요"는 메인 PC 최신 로그로 채웁니다.
- **아직 안 한 일을 "하고 있다"고 말하지 않습니다.**
