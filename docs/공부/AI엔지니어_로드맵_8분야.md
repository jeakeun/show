# AI 엔지니어 로드맵 8분야 — 공부 순서·개념·활용법·문제

## 0. 이 영상이 말하는 것
- AI 엔지니어가 알아야 할 것을 **8개 분야 × 20개 = 160개 개념**으로 나눴다는 소개 영상입니다.
- 영상 화면에는 분야마다 **앞의 4개만** 나옵니다 → 이 노트는 그 **32개**를 다룹니다.
- 나머지 128개는 "댓글에 AI라고 쓰면 DM으로 PDF를 준다"는 방식이라 영상에는 없습니다.

## 1. 내 공부 순서 (영상 순서와 다르게 바꿈)

영상 순서는 "전문 개발자" 기준입니다. 저는 **지금 이미 하는 일 + 인턴 업무**에 맞춰 순서를 바꿨습니다.

| 순서 | 분야 | 왜 이 순서? |
|---|---|---|
| 1 | LLM | 모든 것의 바닥. 토큰을 알아야 비용·한도가 이해됨 |
| 2 | AI 에이전트 | 이미 Claude Code로 매일 쓰는 것. 아는 것부터 이름 붙이기 (하네스 노트와 연결) |
| 3 | 평가 | 유튜브 자동화의 반복 가드가 이미 평가. 만들면 바로 시험해야 함 |
| 4 | AI 보안 | 자동화가 웹을 읽고 메모리를 올리니 바로 필요 |
| 5 | AI 시스템 설계 | 이미 "대본은 Opus, 작은 일은 싼 모델"을 하고 있음 → 이름 배우기 |
| 6 | RAG | 회사 문서 챗봇 같은 사내 자동화에 가장 많이 쓰임 |
| 7 | 백엔드 | 냠냠플래닛에서 FastAPI를 써봄. 직접 서비스 만들 때 필요 |
| 8 | 배포 | GPU·vLLM은 "AI를 직접 돌릴 때"만 필요. 지금은 우선순위 가장 낮음 |

**냉정한 판단:** 비개발자 인턴에게 1~5번은 바로 쓸모가 있고, 6~7은 사내 자동화를 만들 때, 8번은 당분간 "단어만 알면 되는" 수준입니다.

## 2. 분야별 정리

각 개념 = **뜻(쉬운 말)** / **활용(내 일에서)**

### 1단계: LLM — 모델이 어떻게 움직이나

| 개념 | 뜻 | 활용 |
|---|---|---|
| 토큰 (Tokens) | AI가 글을 자르는 조각. 단어보다 작은 단위. 한국어는 영어보다 같은 뜻에 토큰이 더 많이 듦 | 요금·한도는 글자 수가 아니라 **토큰 수**로 매겨짐 → 긴 지시문 = 돈. Code Mode 켠 것도 토큰 아끼려고 |
| 임베딩 (Embeddings) | 글의 **뜻을 숫자 목록으로** 바꾼 것. 뜻이 비슷하면 숫자도 가까움 | "같은 주제 반복 금지" 검사를 글자 비교 대신 뜻 비교로 할 수 있음 |
| 트랜스포머 (Transformers) | 지금 거의 모든 LLM의 설계도. 하는 일은 결국 **"다음 토큰 맞히기"** 반복 | AI가 그럴듯한 거짓말을 하는 이유 = 사실 확인이 아니라 다음 말 맞히기라서 |
| 셀프 어텐션 (Self-attention) | 문장 속 각 단어가 **다른 단어들 중 무엇이 중요한지 살펴보는** 방법 | "그것"이 무엇을 가리키는지 AI가 알아내는 원리. 지시문이 길면 중요한 말이 묻힐 수 있음 |

더 볼 것: 컨텍스트 창(한 번에 읽을 수 있는 양), 온도(temperature, 답의 무작위성), 환각(hallucination)

### 2단계: AI 에이전트 — 도구를 쓰는 AI

| 개념 | 뜻 | 활용 |
|---|---|---|
| 에이전트 루프 (Agent loop) | 생각 → 도구 사용 → 결과 보기 → 다시 생각… 끝날 때까지 반복 | 하네스 노트의 "반복 고리"와 같은 것. Claude Code가 파일을 여러 번 읽고 고치는 방식 |
| 도구 호출 (Tool calling) | 모델이 "이 도구를 이 값으로 써줘"라고 **요청**하면 프로그램이 실행 | 모델은 요청만, 실행은 하네스. 사내 자동화에서 "메일 보내기" 도구를 줄지 말지가 핵심 결정 |
| 도구 설명서 (Tool schemas) | 도구 이름·하는 일·받는 값을 적은 **사용 설명서** | 설명이 엉성하면 AI가 도구를 잘못 씀 → 설명서를 잘 쓰는 게 성능을 좌우 |
| 정해진 형식 출력 (Structured outputs) | 답을 아무렇게나 쓰지 말고 **정해진 틀(JSON 등)로** 내게 하기 | 엑셀·시트에 바로 넣을 수 있음. "이름/전화/주소 칸으로 뽑아줘" |

더 볼 것: MCP(도구를 꽂는 표준 콘센트), 멀티 에이전트, 사람 승인 단계(human-in-the-loop)

### 3단계: 평가(Evals) — AI 시험 보기

| 개념 | 뜻 | 활용 |
|---|---|---|
| 모범 답안 묶음 (Golden dataset) | "이 질문엔 이 답이 맞다"를 사람이 확인해 모아둔 **정답지** | 사내 챗봇을 만들면 자주 받는 질문 20개 + 정답부터 만들기 |
| 테스트 케이스 (Test cases) | 시험 문제 하나하나. 입력 + 기대 결과 | "전화번호 3·4·4자리" 같은 사소한 실수도 문제로 만들어 두면 다시 안 틀림 |
| 확인 조건 (Assertions) | "결과에 ○○가 **반드시** 있어야/없어야 한다"는 자동 검사 | 유튜브 반복 가드 = "지난 주제와 겹치면 안 된다"는 확인 조건 |
| 정확히 일치 (Exact match) | 답이 정답과 **한 글자도 안 틀리고 같은지** 보는 가장 엄격한 채점 | 숫자·날짜·코드엔 좋음. 문장 답엔 너무 엄격 → 뜻 비교나 AI 채점을 씀 |

더 볼 것: AI가 채점하기(LLM-as-judge), 회귀 테스트(고친 뒤 예전 것이 안 깨졌나)

### 4단계: AI 보안

| 개념 | 뜻 | 활용 |
|---|---|---|
| 프롬프트 주입 (Prompt injection) | 사용자가 **"앞의 지시는 무시해"** 같은 말로 AI를 조종하려는 공격 | 회사 챗봇을 공개하면 반드시 들어옴. 규칙을 지시문에만 두지 말고 코드로도 막기 |
| 간접 주입 (Indirect injection) | 사람이 아니라 **AI가 읽는 웹페이지·문서·메일 속에 숨긴** 지시문 | AI데일리가 웹을 읽음 → 페이지 속 "이 메일로 보내라" 같은 문장이 위험. 읽은 글은 명령이 아니라 자료로 취급 |
| 탈옥 (Jailbreaks) | 역할극·우회 질문으로 AI의 **안전 규칙을 풀게** 만드는 것 | 고객용 AI를 만들면 "엉뚱한 말 하게 만들기" 시도를 대비 |
| 데이터 유출 (Data leakage) | 비밀번호·개인정보·내부 자료가 **AI 답이나 기록으로 새어 나감** | 메모리 동기화 때 비밀값 검사·중단 장치를 둔 게 바로 이 대비. 공개 저장소(show) 주의 |

더 볼 것: 최소 권한(필요한 도구만 주기), 출력 검사, 개인정보 가리기

### 5단계: AI 시스템 설계

| 개념 | 뜻 | 활용 |
|---|---|---|
| 모델 고르기 (Model selection) | 일에 맞는 모델 고르기. 똑똑함 ↔ 속도 ↔ 가격 저울질 | 대본처럼 중요한 건 Opus, 분류처럼 쉬운 건 작은 모델 |
| 모델 나눠 보내기 (Model routing) | 요청마다 **자동으로** 알맞은 모델에 보내는 장치 | yt-auto에서 "대본·회고는 큰 모델, 작은 호출은 다른 모델"로 나눈 게 이것 |
| 대체 경로 (Fallbacks) | 첫 방법이 실패하면 **자동으로 다음 방법** 쓰기 | "구독 한도면 1회 자동 재실행"이 대체 경로. 무인 자동화엔 필수 |
| 뜻 기반 캐시 (Semantic caching) | 전에 받은 질문과 **뜻이 비슷하면** AI를 또 부르지 않고 저장해 둔 답 재사용 | 사내 챗봇에 같은 질문이 반복되면 비용·속도 크게 절약 (임베딩 활용) |

더 볼 것: 비용 계산, 응답 속도(latency), 기록 남기기(로깅)

### 6단계: RAG — AI에게 내 문서를 주기

RAG = **필요한 문서 조각을 찾아서(검색) AI 질문에 붙여 주는** 방식. AI가 모르는 회사 자료로 답하게 만듭니다.

| 개념 | 뜻 | 활용 |
|---|---|---|
| 문서 읽어내기 (Document parsing) | PDF·한글(hwp)·엑셀에서 **글자를 깨끗하게 뽑기** | 첫 단계가 망가지면 전부 망가짐. kordoc(설치해 둔 한글 문서 도구)이 이 역할 |
| 조각내기 (Chunking) | 긴 문서를 **적당한 크기로 자르기** | 너무 크면 엉뚱한 내용이 섞이고, 너무 작으면 앞뒤 맥락이 사라짐 |
| 조각 겹치기 (Chunk overlap) | 자를 때 앞 조각 끝부분을 다음 조각 앞에 **조금 겹치기** | 문장이 중간에서 잘려 뜻을 잃는 것을 방지 |
| 임베딩 모델 (Embedding models) | 조각을 숫자(뜻)로 바꿔 주는 모델 | 질문과 뜻이 가까운 조각을 찾는 데 씀. 한국어 문서면 한국어에 강한 모델 선택 |

더 볼 것: 벡터 DB, 재순위(reranking), 출처 표시

### 7단계: 백엔드 — AI를 둘러싼 코드

| 개념 | 뜻 | 활용 |
|---|---|---|
| 파이썬 (Python) | AI 일에서 가장 많이 쓰는 프로그래밍 언어 | 내 자동화(yt-auto, ai-daily)가 전부 파이썬 |
| FastAPI | 파이썬으로 **웹 주소로 부를 수 있는 기능**을 쉽게 만드는 도구 | 냠냠플래닛에서 써봄. "내 AI 기능을 다른 프로그램이 부르게" 할 때 |
| REST API | 프로그램끼리 **정해진 주소·방식으로 주고받는** 약속 (GET=가져오기, POST=보내기) | 유튜브 API로 영상 상태 확인하는 것이 REST API 사용 |
| async/await | 기다리는 동안 **다른 일을 먼저** 하게 하는 코드 방식 | AI 답을 기다리는 동안 다른 요청 처리 → 여러 개를 동시에 빠르게 |

더 볼 것: 데이터베이스(SQL — hub.sqlite가 이것), 환경변수·비밀값 관리, 오류 처리

### 8단계: 배포 — 실제로 내놓기

| 개념 | 뜻 | 활용 |
|---|---|---|
| API vs 직접 운영 (API vs self-hosted) | 남의 AI를 돈 내고 부를까, **내 컴퓨터·서버에서 직접** 돌릴까 | 대부분 API가 정답. 직접 운영은 데이터가 밖으로 나가면 안 될 때 |
| 추론 서버 (Inference servers) | 모델을 띄워 놓고 요청을 받아 답을 내주는 프로그램 | 직접 운영할 때만 필요 |
| vLLM | 대표적인 추론 서버 중 하나. 빠르고 많은 요청을 처리 | 이름만 알아두기 |
| GPU와 VRAM | AI를 돌리는 그래픽카드와 그 **전용 메모리**. 모델이 VRAM에 다 들어가야 돌아감 | 내 PC에서 WhisperX 같은 걸 돌릴 때 이 한계에 걸림 |

더 볼 것: 도커(Docker — 냠냠플래닛에서 써봄), 모니터링, 비용 관리

## 4. 답

1. **토큰** 수. 한국어는 같은 뜻에 토큰이 더 많이 들어 더 비쌉니다.
2. 글의 뜻을 숫자 목록으로 바꾼 것. 뜻이 비슷하면 숫자도 가깝습니다.
3. 사실을 확인하는 게 아니라 "다음에 올 그럴듯한 토큰"을 맞히는 방식이라서.
4. **하네스**. 모델은 요청만 합니다.
5. 프롬프트 주입은 **사용자가 직접** 조종하는 말을 넣는 것, 간접 주입은 AI가 읽는 **웹페이지·문서 속에 숨겨 둔** 지시문.
6. 문장이 조각 경계에서 잘려 뜻을 잃지 않게 하려고.
7. 라우팅은 처음부터 **요청에 맞는 모델을 골라** 보내는 것, 폴백은 **실패했을 때** 다음 방법으로 넘어가는 것.
8. 문장으로 된 답. 뜻이 같아도 표현이 다르면 틀렸다고 채점되기 때문.
9. **5단계 AI 시스템 설계 → 대체 경로(Fallbacks)**.
10. 문서 읽어내기·조각내기·임베딩(**RAG**) → 질문 20개 정답지로 시험(**평가**) → "규정 무시해" 같은 공격 대비(**보안**) → 같은 질문 재사용(**시스템 설계: 뜻 기반 캐시**) → 사내에서 쓰게 올리기(**백엔드·배포**).
11. **간접 주입**. 읽은 글은 "자료"로만 다루고 명령으로 따르지 않게 지시문·코드로 막고, AI에게 메일 보내기 같은 위험한 도구를 아예 주지 않습니다(최소 권한).
12. **뜻 기반 캐시**. 두 질문은 뜻이 같으므로 처음 답을 저장해 두고 재사용합니다.
13. **정해진 형식 출력**(이름/전화/주소 칸 고정) + **확인 조건**(전화번호가 3·4·4자리인지 자동 검사).
14. 예: 대체 경로(한도 시 재실행), 모델 나눠 보내기(대본 Opus), 확인 조건(반복 가드). 데이터 유출 대비(메모리 비밀값 검사)도 정답.
15. 영상은 전문 개발자 기준이고, 나는 **이미 하는 것과 인턴 업무에 바로 쓰는 것부터** 배우는 게 효율적이라서.
