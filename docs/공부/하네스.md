# 하네스(harness)란? — 쉬운 정리

작성: 2026-11-21 (공부 세션)

## 한 줄 요약
**하네스 = AI 모델(뇌)을 감싸서 실제로 일을 하게 만드는 프로그램(몸과 작업대).**

영어 harness의 원래 뜻은 말에 채우는 **마구(고삐·안장·끈)** 입니다.
말은 힘이 세지만 마구가 없으면 수레를 끌 수 없죠. AI 모델도 똑똑하지만 하네스가 없으면 실제 일을 못 합니다.

## 1. 모델 혼자서는 뭘 할 수 있나?
모델(예: Claude Opus 5.5)이 혼자 할 수 있는 건 딱 하나입니다.
> 글을 받으면 → 다음 글을 써서 돌려준다.

- 내 컴퓨터 파일을 못 읽습니다.
- 명령을 실행하지 못합니다.
- 어제 대화를 기억하지 못합니다.
- "이 파일 읽어줘"라고 **말**만 할 수 있지, 직접 읽지는 못합니다.

## 2. 하네스가 해주는 일 (5가지)
| 하는 일 | 쉬운 설명 | 지금 이 대화에서의 예 |
|---|---|---|
| ① 지시문 조립 | 모델에게 보낼 "작업 안내서"를 만들어 붙임 | CLAUDE.md, 메모리 파일, "한글로 써라" 규칙을 매번 같이 보냄 |
| ② 도구 연결 | 모델이 쓸 손발을 달아줌 | 파일 읽기·쓰기, 명령 실행, 브라우저 |
| ③ 반복 고리(루프) | 모델 요청 → 실행 → 결과를 다시 모델에게 → 끝날 때까지 반복 | "파일 읽을게요" → 하네스가 읽음 → 내용을 모델에게 → 모델이 다음 행동 결정 |
| ④ 안전장치 | 위험한 행동 전에 허락 받기, 금지 규칙 | "이 명령 실행할까요?" 허락 창 |
| ⑤ 기억 관리 | 대화가 길어지면 요약, 메모리 파일 저장 | 긴 대화 자동 요약, memory 폴더 |

③이 핵심입니다. 모델은 "말"만 하고, 하네스가 그 말을 "행동"으로 바꿔 줍니다.

```
사용자 질문
   ↓
하네스: 안내서 + 질문을 묶어서 모델에게 보냄
   ↓
모델: "docs 폴더를 찾아볼게요" (도구 사용 요청)
   ↓
하네스: 실제로 폴더를 찾고, 결과를 모델에게 다시 보냄
   ↓
모델: "이제 답할 수 있어요" → 최종 답변
   ↓
하네스: 사용자 화면에 보여줌
```

## 3. 비유: 요리사와 주방
- **모델 = 요리사의 실력**
- **하네스 = 주방** (칼·불·냉장고 = 도구, 주문서 = 지시문, 위생 규칙 = 안전장치, 레시피 노트 = 기억)

같은 요리사라도 주방이 엉망이면 음식이 엉망입니다.
그래서 **같은 모델이라도 하네스가 좋으면 훨씬 일을 잘합니다.**
요즘 업계에서 "하네스 엔지니어링"이라는 말이 나오는 이유입니다. 모델을 바꾸지 않고 주방(하네스)을 고쳐서 성능을 올리는 것이죠.

## 4. 내 프로젝트에서 이미 만난 하네스
- **Claude Code(지금 쓰는 앱)** 자체가 하네스입니다. 모델은 Opus 5.5, 하네스는 Claude Code.
- **유튜브 자동화(yt-auto)가 화면 없이 `claude`를 실행하는 것** → 하네스를 사람 없이(헤드리스) 돌리는 것.
- **claude.exe 경로 사고(10/2~4)** → 앱 업데이트로 하네스 위치가 바뀌어 자동화가 멈춘 사건. 모델 문제가 아니라 하네스 문제였습니다.
- **context-mode 플러그인, Code Mode 켜기** → 하네스 설정을 바꾼 것. 그래서 이상한 일이 생기면 "하네스 설정을 바꿨던가?"부터 의심하면 됩니다.

## 5. 다른 뜻 하나: 테스트 하네스
개발에서는 **"코드를 시험하기 위한 틀"** 도 하네스라고 부릅니다.
예: 계산 함수를 만들면, 여러 숫자를 자동으로 넣어 보고 답이 맞는지 확인하는 프로그램.
AI 쪽에서도 "평가 하네스(eval harness)" = 모델에게 시험 문제를 자동으로 내고 채점하는 프로그램.
→ 공통점: **무언가를 감싸서 일을 시키거나 시험하는 틀.**

## 6. 인턴 업무와 연결
회사에서 "AI로 자동화하자"는 건 결국 **작은 하네스를 만드는 일**입니다.
1. 어떤 안내서를 줄지 (지시문)
2. 어떤 도구를 쥐여줄지 (엑셀 읽기, 메일 보내기 등)
3. 어디서 사람 허락을 받을지 (안전장치)
4. 결과를 어떻게 확인할지 (테스트)

이 네 가지만 정하면 자동화 설계의 뼈대가 나옵니다.

## 7. 하네스 vs 하네스 엔지니어링 (2026-11-21 추가 질문)
같은 말이 아니라 **물건과 그 물건을 만드는 일**의 관계입니다.
- **하네스** = 주방 그 자체 (물건)
- **하네스 엔지니어링** = 주방을 설계하고 고쳐서 요리가 잘 나오게 만드는 **일·기술**

### 비슷한 말 3개 정리 (작은 것 → 큰 것)
| 이름 | 무엇을 다듬나 | 주방 비유 |
|---|---|---|
| 프롬프트 엔지니어링 | 모델에게 보내는 **문장 하나** | 주문서 한 장을 잘 쓰기 |
| 컨텍스트 엔지니어링 | 모델이 보는 **모든 자료** (지시문·메모리·파일·검색 결과) | 요리사 앞에 놓을 재료와 레시피를 고르기 |
| 하네스 엔지니어링 | 모델을 둘러싼 **환경 전체** (도구·반복 고리·자동 검사·안전장치·기억) | 주방 전체를 설계하기 |

큰 것이 작은 것을 포함합니다: 하네스 엔지니어링 ⊃ 컨텍스트 엔지니어링 ⊃ 프롬프트 엔지니어링.

### 핵심 생각
"모델이 실수하면 모델 탓만 하지 말고, **같은 실수가 다시 안 나오게 환경을 고친다.**"
- 말로 부탁하기 (프롬프트): "같은 주제 반복하지 마" → 가끔 어김
- 환경으로 막기 (하네스): 반복을 검사하는 코드를 넣어 **자동으로 차단** → 어길 수 없음

### 내가 이미 한 하네스 엔지니어링
- 1분호기심 **반복 가드 하드 차단** — 부탁 대신 코드로 막음
- **지시문 잘림 수정 + 구독 한도 시 1회 자동 재실행** — 모델이 아니라 실행 환경을 고침
- **CLAUDE.md 규칙, 메모리 파일** — 매번 같은 안내서를 자동으로 붙임
- **브랜치에서 테스트 후 main 병합** — 결과를 자동으로 확인하는 장치

## 스스로 확인 질문
1. 모델과 하네스의 차이를 한 문장으로 말하면? → 모델은 생각하고 말하고, 하네스는 그 말을 행동으로 바꾼다.
2. 같은 모델인데 앱마다 성능이 다른 이유는? → 하네스(도구·지시문·반복 방식)가 다르기 때문.
3. 자동화가 갑자기 멈췄을 때 먼저 볼 곳은? → 모델이 아니라 하네스(실행 경로·설정·플러그인).
