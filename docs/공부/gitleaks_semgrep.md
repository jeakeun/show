# Gitleaks와 Semgrep — 커밋 전에 기계가 잡아 주는 검사기

작성: 2026-11-25 (공부 세션) · 실제로 메인 PC 저장소 8개에 연결함

## 한 줄 요약
- **Gitleaks** = 코드에 실수로 들어간 **비밀번호·API 키·토큰**을 찾는 도구
- **Semgrep** = 코드 안의 **버그·보안 구멍·위험한 습관**을 찾는 도구
- 둘 다 "사람이 깜빡해도 **기계가 막아 주는 장치**"예요. → [하네스 엔지니어링](하네스.md)의 "말로 부탁하지 말고 환경으로 막는다"와 같은 생각이에요.

## 1. 왜 필요한가
| 사고 | 결과 |
|---|---|
| API 키가 든 파일을 공개 저장소에 커밋 | 자동 수집 봇이 몇 분 안에 가져감 → 남이 내 요금으로 API 사용 |
| "나중에 지우면 되지" | 파일을 지워도 **커밋 기록에 남음** → 키 자체를 새로 발급(재발급)해야 함 |
| 입력값을 그대로 명령에 붙이는 코드 | 해킹 통로(인젝션)가 됨 |

## 2. Gitleaks
- **하는 일:** 깃 저장소의 파일과 **지난 커밋 기록 전체**를 훑어요. `sk-ant-…`, `AIza…`, `ghp_…`처럼 생김새가 정해진 키, `password = "…"` 같은 줄을 찾아요.
- **두 가지 쓰는 법**
  1. **처음 한 번 전체 검사**: 이미 새어 나간 게 있는지 찾아요. `gitleaks git 저장소경로 --redact`
  2. **커밋할 때마다 자동 검사(pre-commit 훅)**: 이번에 커밋하려는 변경만 봐요. 빨라요(1초 안).
- `--redact` = 찾은 값을 화면에 `REDACTED`로 가려서 보여 줌 (검사 결과 때문에 또 새는 걸 막음)
- **오탐(잘못 걸림):** 진짜 키가 아니면 그 저장소의 `.gitleaksignore`에 지문(Fingerprint) 줄을 넣어 예외로 만들어요.

## 3. Semgrep
- **하는 일:** 코드를 단순 글자가 아니라 **문법 구조로** 읽고 규칙에 어긋나는 곳을 찾아요.
- **잡는 예** (이번에 일부러 만든 파일로 실제로 3개 다 잡음)
  - `subprocess.call(x, shell=True)` → 명령 주입 위험
  - `requests.get(url, verify=False)` → 보안 연결 확인을 끔
  - `eval(x)` → 바깥 글자를 코드로 실행
- 이미 만들어진 규칙 묶음(`p/default`, 수천 개)을 받아서 써요. 우리만의 규칙도 직접 쓸 수 있어요.
- **한계:** 오탐도 있고 놓치는 것도 있어요. 그래서 경고를 보고 **사람이 판단**해야 해요.

## 4. 훅(hook)이란
깃이 특정 순간에 **자동으로 실행해 주는 스크립트**예요.
| 훅 | 언제 | 실패하면 |
|---|---|---|
| `pre-commit` | `git commit` 직전 | 커밋이 안 만들어짐 |
| `pre-push` | `git push` 직전 | 푸시가 안 됨 |

`core.hooksPath` 설정으로 **여러 저장소가 한 폴더의 훅을 같이 쓰게** 할 수 있어요.

## 5. 내 PC에 실제로 건 방식 (2026-11-25)
```
커밋  → [pre-commit] gitleaks: 이번 변경에 비밀값? ── 있으면 ✋ 차단 + 폰 알림
푸시  → [pre-push]  gitleaks: 올라갈 커밋들에 비밀값? ── 있으면 ✋ 차단 + 폰 알림
                    semgrep: 바뀐 코드 파일에 위험 코드? ── 있으면 ⚠ 경고만 (푸시는 진행)
```
- **대상 저장소 8개:** show · yt-auto · ai-daily · coin-bot · market-compass · hub · kids-toon · YummyPlanet
- **훅 파일:** `show/tools/hooks/` (`pre-commit`, `pre-push`, `_common.sh`, `install.sh`)
- **연결/해제:** `bash tools/hooks/install.sh` / `bash tools/hooks/install.sh --uninstall`
- **semgrep 규칙 새로 받기:** `bash tools/hooks/install.sh --update-rules`
- **semgrep 보고서:** `D:\tools-venv\semgrep-logs\`

### 왜 semgrep은 막지 않고 경고만 하나 (설계 판단)
- 매일 자동화(유튜브 기록 백업 등)가 사람 없이 커밋·푸시해요.
- semgrep 오탐 하나로 푸시가 막히면 **자동화가 조용히 멈춰요.** 비밀값 유출은 되돌릴 수 없어서 막고, 코드 습관은 사람이 보고 고칠 수 있어서 경고만 해요.
- 데이터만 바뀐 푸시(코드 파일 없음)는 semgrep을 건너뛰어서 1초 안에 끝나요.
- gitleaks가 없거나 오류가 나면 **경고만 하고 통과**해요(자동화 보호). 대신 푸시 때 한 번 더 검사해요.

### 시험 결과 (임시 저장소)
| 시험 | 기대 | 결과 |
|---|---|---|
| 평범한 커밋 | 통과 | 통과 |
| 가짜 토큰 커밋 | 차단 | 차단 |
| `--no-verify`로 억지 커밋 후 푸시 | 푸시 차단 | 차단 |
| 위험 코드(한글·띄어쓰기 파일명) 푸시 | 경고 후 통과 | 경고 1건, 통과 |
| 새 브랜치 데이터 푸시 | 빠르게 통과 | 1.1초 |
| 새 브랜치에 가짜 토큰 푸시 | 차단 | 차단 |

## 6. 인턴 업무와 연결
- 사내 자동화 코드를 만들기 시작하면 **첫날부터 같은 훅을 그 저장소에 연결**하세요. (`install.sh`의 REPOS 목록에 경로 추가)
- 회사 API 키(큐샵·메일·엑셀 연동 등)는 **`.env` 파일 + `.gitignore`**, 코드에는 `os.environ["KEY"]`로만.

## 스스로 확인 질문
1. 공개 저장소에 키를 올렸다가 바로 파일을 지웠어요. 이제 안전한가요?
2. gitleaks와 semgrep 중 "막는" 것과 "경고만 하는" 것은 각각 무엇이고, 왜 그렇게 나눴나요?
3. gitleaks가 진짜 키가 아닌 걸 잡았어요. 어떻게 하나요?
4. `git commit --no-verify`는 무엇이고, 그걸로 억지로 커밋하면 어디서 다시 잡히나요?

### 답
1. 아니요. 커밋 기록에 남아요. **키를 재발급**하고 옛 키는 폐기해야 해요.
2. 막는 것 = gitleaks(유출은 되돌릴 수 없음), 경고 = semgrep(오탐으로 자동화가 멈추면 안 됨, 사람이 판단).
3. 그 저장소의 `.gitleaksignore`에 출력된 Fingerprint 줄을 넣어요.
4. 훅을 건너뛰는 옵션이에요. 푸시할 때 pre-push 훅의 gitleaks가 다시 잡아요.
