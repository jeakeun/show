# 메인 PC 클로드 지시서 — 지원서 변경 테스트 (2026-10-26)

> 클라우드 세션에서 작성. 사용자가 "10/26 지원서 테스트 지시서 실행해"라고 하면 이 문서대로 한다.

## 배경

클라우드 세션이 웹 검색으로 사용자 직무(AX·AI 에이전트·LLM)에 맞는 공고 후보 9개를 골랐다: `jobfit-agent/eval/candidates-2026-10-26.md`.
클라우드 환경에서는 채용 사이트 접속이 막혀 있고 API 키도 없다. 그래서 **공고 원문 가져오기와 실제 모델 실행은 메인 PC**가 한다.
테스트는 사람 확정 직전까지만 돌리며, 승인·지원·이력 등록은 하지 않는다.

## 0. 받기

```
cd C:\Users\User\OneDrive\Desktop\show
git fetch origin
git merge origin/claude/gifted-babbage-aw2t9a
```

## 1. 공고 원문 가져오기 (008~016)

- 후보 표의 링크를 연다. 로그인이 필요한 화면은 열지 않는다. 열리지 않으면 같은 회사·포지션을 원티드 등에서 찾는다.
- 원문을 `jobfit-agent/eval/postings/NNN.md` 로 저장한다. 형식은 기존 `002~007` 과 같다.
  - 맨 위 메모 줄에 다음을 적는다: `company`, `position`, `url`, `source: 클라우드 검색 후보 2026-10-26`, `note: 확인 날짜, 마감 여부`
  - 복지·혜택·기사 링크는 뺀다.
- **원문이 검색 요약과 크게 다르거나 공고가 없어졌으면** 그 번호는 건너뛰고 보고에 적는다. 내용을 지어내지 않는다.

## 2. 정답표 (008~016)

- `jobfit-agent/eval/answers/NNN.json` 을 `eval/README.md` 규칙대로 만든다. 요구 항목과 제외 항목을 적는다.
- `mentor_reading` 은 넣지 않는다. 멘토가 해석한 공고가 아니기 때문이다.

## 3. 실행 준비 (처음 한 번)

`jobfit-agent/docs/학습노트/2-1-첫-골격.md` 의 "메인 PC에서 처음 실제로 돌리는 법" 1~4를 따른다.
- 가상환경은 `D:\jobfit-venv` 에 만든다.
- `.env` 에 `ANTHROPIC_API_KEY` 를 넣는다. 이 파일은 커밋하지 않는다.
- `python -m pytest` 로 20개 테스트가 통과하는지 확인한다.

## 4. 테스트 실행

```
cd C:\Users\User\OneDrive\Desktop\show\jobfit-agent
D:\jobfit-venv\Scripts\python batch_run.py --only 008,009,010,011,012,013,014,015,016 --max-usd 5
```

- 결과는 `eval/results/batch-날짜/` 에 공고별 파일과 `summary.md` 로 남는다.
- 비용 상한 5달러에 걸리면 멈춘다. 첫 공고 하나의 비용을 보고 전체 예상 비용을 사용자에게 먼저 알려도 된다.
- 유튜브 예약 시간(07:00, 17:20~18:30, 23:50)은 피한다.

## 5. 커밋과 보고

- 공고 원문, 정답표, 테스트 결과를 커밋해 show `main` 에 푸시한다.
- 초안은 공개 문서(README, 설계 결정 기록)에서만 근거를 가져오므로 개인정보가 없다. 그래도 커밋 전에 한 번 훑어본다.
- 사용자에게 보고한다.
  - 요약 표 (적합도, 근거 운영/학습/없음, 작성 횟수, 남은 지적, 비용)
  - 건너뛴 공고와 이유
  - "클라우드 세션에 '테스트 결과 검토해'라고 하면 초안 품질을 같이 본다"는 안내
