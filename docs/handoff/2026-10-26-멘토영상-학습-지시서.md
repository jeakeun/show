# 메인 PC 클로드 지시서 — 멘토 영상에서 "공고 읽는 법" 정리 (2026-10-26)

> 클라우드 세션에서 작성. 사용자가 "10/26 멘토영상 지시서 실행해"라고 하면 이 문서대로 한다.

## 배경

사용자가 다운로드 폴더에 영상을 하나 받았다. 영상에서 멘토가 **원티드에서 채용 공고를 열어 보고, 그 회사가 실제로 무엇을 원하는지** 설명한다.
목적은 두 가지다.
1. **사용자 공부**: 멘토의 공고 읽는 법을 정리해 면접·지원 준비에 쓴다.
2. **jobfit-agent에 반영**: 공고 분석가가 멘토처럼 "회사가 실제로 원하는 것"까지 읽게 만든다.
   모델을 다시 학습시키는 게 아니라, 지시문과 평가셋에 멘토의 기준을 넣는 방식이다.
   이 반영 작업은 클라우드 세션에서 한다. 메인 PC는 **재료를 뽑아 정리하는 데까지만** 한다.

## 1. 영상 찾기

다운로드 폴더(`%USERPROFILE%\Downloads`)에서 가장 최근 영상 파일을 찾는다.
**파일 이름, 길이, 받은 시각을 사용자에게 보여주고 맞는지 확인받는다.** 영상은 원래 위치에 그대로 둔다.
작업 폴더는 OneDrive 밖에 만든다. 예: `D:\study\mentor\2026-10-26\`

## 2. 말 → 글 (전사)

- 유튜브 자동화가 쓰는 faster-whisper로 한국어 전사를 하고, 타임스탬프를 붙인다. ffmpeg로 음성을 먼저 뽑는다.
  모델 크기는 정확도를 위해 가능하면 small보다 큰 것(medium 등)을 쓴다.
- **사용자의 다른 예약 작업과 시간이 겹치지 않게 한다.** 특히 17:20~18:30에는 GPU를 쓰는 저녁 작업이 있다.
- 전사 원문은 작업 폴더에만 둔다. 멘토 강의 원문이라 **깃에 올리지 않는다.**

## 3. 화면 → 공고 (프레임)

- ffmpeg로 일정 간격(예: 5~10초) 프레임을 뽑는다. 원티드 공고 화면이 나오는 프레임을 골라 읽는다.
- 공고마다 회사명, 포지션, 주요업무, 자격요건, 우대사항, 기술 스택을 글로 옮긴다.
- 화면으로 읽기 어려우면 원티드에서 같은 공고를 찾아 확인해도 된다. 단, 로그인이 필요한 화면은 열지 않는다.

## 4. 정리 문서 (깃에 올림 — 요약과 의역만)

`show/docs/멀티에이전트/멘토-공고읽는법-2026-10-26.md` 에 쓴다.

1. **멘토의 공고 읽는 원칙**
   - 멘토가 말한 기준을 의역해 번호 목록으로 쓰고, 타임스탬프를 단다.
   - 예: "우대사항이 실제 업무를 보여준다", "기술 스택보다 문제 상황을 봐라" 같은 식이다. 이건 형식 예시일 뿐이니 실제 내용을 쓴다.
2. **공고별 정리**: 공고마다 아래 표를 만든다.

   | 공고 문구 | 멘토 해석: 회사가 실제로 원하는 것 | 지원자가 보여줘야 할 증거 |
   |---|---|---|

3. **내 경험과 연결**: 공고마다 사용자의 어떤 경험을 내세우면 되는지 `docs/멀티에이전트/02-내-설계결정-기록.md` 근거로 한두 줄씩 쓴다. 근거가 없으면 "없음"이라고 쓴다.
4. 잘 안 들리거나 확실하지 않은 부분은 **"(불확실)"** 로 표시한다. 멘토가 하지 않은 말을 만들지 않는다.

## 5. 평가셋에 공고 추가

- 영상에 나온 공고마다 `jobfit-agent/eval/postings/NNN.md` 로 추가한다. 번호는 002부터 이어서 붙인다.
- 맨 위 메모 줄에 출처를 적는다: `source: 멘토 영상 2026-10-26, 원티드`.
- 같은 번호로 `jobfit-agent/eval/answers/NNN.json` 정답표도 만든다. 규칙은 `jobfit-agent/eval/README.md` 를 따른다.
- 정답표에 `"mentor_reading"` 칸을 추가해, 멘토가 해석한 "회사가 실제로 원하는 것"을 항목별로 짧게 적는다. 공고 분석가 개선 평가에 쓴다.
