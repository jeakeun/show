## A. 기존 에이전트 (검토 후 순서)

### A1. 1분호기심 판정 규칙 정리 — ab-testing (1순위)
- 지금 `insights.py` 안에 판정 규칙이 서로 부딪힘: "5편 미만이면 표본 부족"(44줄 부근), "48시간 지난 4편이 하한 미달이면 폐기"(233), "가설 2편 맞으면 규칙 후보"(255·299).
- 할 일: 우선순위를 한 줄로 못 박기 → **① 사용자가 정한 실험 일정 > ② 미리 정한 운영 중단 기준 > ③ 탐색 관찰**.
- "N편 더 필요" 같은 숫자를 AI가 지어내지 못하게: 쇼츠 조회수는 무작위 실험이 아님 → "적은 표본은 방향만 참고".
- 실험 기록표(실험 이름·슬롯·바꾼 것·기간·제외 기준·48시간 경과·같이 바뀐 것)를 코드가 집계해 회고에 넘김.
  예: 11/22 저녁 후킹 재판정은 피드 노출 0~3 편 제외 결과와 전체 결과를 **둘 다** 보고, 11/16 목소리 엔진 교체를 "같이 바뀐 것"으로 표시.
- 비용: 새 도구 구매는 없지만 회고는 유료 API라 지시문 늘어난 만큼 조금 듦.

### A2. 우리 영상 눈으로 검수 — watch (2순위, 이상할 때만 수동)
- `output/`의 우리 mp4를 대본·자막과 맞춰 첫 3초 자막·그림·대사가 맞는지 확인. 남의 영상 분석보다 이게 먼저.

### A3. 대본 검사 규칙 보강 — social·copywriting (3순위, 먼저 시험)
- 대본 검사는 `promptlint.py`가 아니라 `scriptgen.py`의 `CRITIC_PROMPT`(177줄)·`critique_script()`, 재생성 결정은 `pipeline.py`(231).
- 새 규칙은 **지난 대본(정상·문제 있던 것)에 먼저 돌려** 엉뚱하게 잡는지·재생성이 몇 번 늘지 비교 후 넣음(경고 2개면 재생성이라 비용 직결).
- 넣을 후보: 제목·첫 문장이 같은 약속인지, 과장 금지. "첫 문장에 숫자 필수"는 기존 후킹 규칙과 충돌 → 안 넣음.
- social 스킬의 쇼츠 첫 장면 훅(화면·소리·자막 동시) 지침이 marketing-psychology보다 직접적. 단 "구독 요청 필수"는 채널 규칙(음성 구독 요청 금지)이 우선.

### A4. 한글 첨부 읽기 — kordoc (4순위, 따로 시험부터)
- ai-daily에 바로 붙이지 않음: 변환 명령이 무인 실행 허용 목록에 없고, 지금 프롬프트는 임시 파일을 금지함(`run-daily.ps1:104`, `jobs-prompt.md`).
- 쓰는 곳: **유료 지원서(jobfit) 만들기 전 필수조건 확인** 단계로 한정(수집 범위는 그대로).
- 변환문에 문서명·원문 주소·쪽·해당 문구를 함께 남기고, 표가 깨지거나 실패하면 "결격"이 아니라 "미확인".
- market-compass: 법령 개정 문서를 근거 자료로만, Guard 규칙 변경과 분리.

### A5. 소재 후보 공급 — content-strategy (5순위)
- 월간 보고서 대신, 이미 쓰는 `topic_bank.md` 형식에 맞춰 "안 쓴 사건·실험" 후보를 채워 넣는 제안(주제 선택기 `scriptgen.py:299`가 이미 읽음).

### A6. save/resume-session — 나(대화)만

## B. 숏드라마 webdrama (검토 후 순서)

현재: 1화 대본 15장면, 장면 영상 0개, 인물 사진 4명(`series/characters/seoyeon·dohyun·yuna·minjae.png`) 있음, 채널 미연결.

### B1. 영상 만들기 전 대본 연속성 검사 (1순위, 지금 바로 가능)
- 1화 핵심 인과: 2번 뚜껑, 3번 커피 쏟기, 10번 "거울로 봤다". 2번에서 도현이 거울로 볼 수 있는 구도가 화면에 안 나오면 10번 반전이 갑작스러움.
- 커피 얼룩 위치·크기, 컵 개수, 손수건 상태를 장면별 표로 → 작업지시서에 표시. 영상 만든 뒤 고치는 것보다 훨씬 쌈.

### B2. 어려운 3장면 시험 — 코덱스 그림 첫 프레임 (2순위)
- 힉스필드 Kling은 Start/End Frame·인물 Elements를 지원. 단 첫 그림의 얼룩이 끝까지 유지되거나 쏟는 동작이 자연스럽다는 보장은 없음.
- 시험: **1인 대사 / 2인 장면 / 커피 쏟기** 각 1개를 "지금 방식(인물 사진 참조)" vs "첫 프레임 그림" 비교 → 쓸 만한 비율·재생성 횟수·사람 시간 기록 후 확대 여부 결정.
- 그림은 기존 인물 사진을 **매번 참조**해서 만들고 사람이 골라냄(새 얼굴 금지). 1화엔 민재가 안 나와 3명만, 기본 의상만.
- 고정할 것은 얼굴·머리·체형, 의상·얼룩·소품은 장면마다 바뀜.
- 효과 있으면: `sheet.py`(66·74줄 장면 반복)에 `frames/NN.png` 칸 추가, "참고 인물 사진"과 "Start Frame" 구분 표시.
  정지 구도 문장을 따로 받으려면 `writer.py`의 `EPISODE_SCHEMA`·`make_episode()`도 수정.

### B3. 대사·자막 맞추기 (3순위)
- 지금 `editor.py:98`은 자막을 실제 말소리 시간이 아니라 글자 수 비율로 나눔 → Kling이 늦게 말하면 자막이 어긋남.
- 클립 소리를 받아쓰기(로컬 음성인식)해서 대본과 비교 + 실제 말 시작 시간에 자막 맞추기.
- watch로 클립 검수는 "합격 판정"이 아니라 **의심 구간 알려주기**로(장면당 6장이면 15장면 90장, 손 변형·입모양 놓칠 수 있음).

### B4. 업로드 전 사람 승인 상태 (4순위)
- 지금은 편집만 끝나면(`built`) 바로 업로드 대상(`drama.py:167·201·223`). "검수 완료" 상태를 추가하고, 클립 바꾸거나 다시 편집하면 승인 취소.

### B5. AI 제작 표시 점검 (4순위, 같이)
- 유튜브·틱톡은 표시 켜져 있음. **인스타 업로드에는 AI 표시가 없고**, 수동 게시 문구는 `#AI드라마` 해시태그뿐 → 명시 문구 추가, 메타 공개 기능 확인.

### B6. 대본 지시 보강 — copywriting (5순위)
- 첫 3초 갈등·매화 보상·끝 5초 떡밥은 **이미 있음**(`writer.py:93·138`).
- 새로 할 것: 앞 화 **떡밥(cliffhanger)이 다음 화에 전달 안 됨**(`drama.py:91`, `writer.py:120`) → 전달하고 회수했는지 확인. 회차 제목을 장면 속 구체적 사건으로.

### B7. 플랫폼별 문구 — social (6순위)
- `업로드문구.txt`는 `drama.py`가 만들고 자동 업로드는 `publisher.texts()`를 다시 부름 → 고칠 곳은 `texts()`.
- social 스킬 숫자는 공식 문서로 재확인(예: 유튜브 해시태그 스킬은 15개, 공식은 60개 초과 시 무시).

### B8. 썸네일 — 코덱스 그림 (6순위)
- 몰아보기는 `binge.py:132`가 영상에서 썸네일을 뽑음 → 직접 만든 그림이 있으면 그걸 먼저 쓰는 경로 필요. 쇼츠 표지 코드는 없음.

### B9. 벤치마크 측정·운영 판정
- 남의 드라마 내려받기 금지 → 허락받은 자료만. video 스킬의 "참고 영상을 컷·자막·소리 편집 명세로 나누기" 방법은 쓸 만함.
- 중단 기준(4주 중앙값 1만 등)은 통계 실험이 아니라 **사업 판단**으로 적고, 같은 경과시간 성과 + 제작시간·재생성 비용을 함께 봄.
