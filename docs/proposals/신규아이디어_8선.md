# 0. 어떻게 찾았나 — 발상법 5개

**"신박한 아이디어"는 영감이 아니라 방법으로 나옵니다.** 제가 쓴 방법을 먼저 공개합니다.

| # | 방법 | 뜻 | 예 |
|---|---|---|---|
| **1** | **방향 뒤집기** | 모두가 "어디에 지을까"를 묻는다 → **"어디를 없앨까"** 는 아무도 안 묻는다 | 인구가 주는 시대의 진짜 고민은 짓는 게 아니라 **줄이는 것** |
| **2** | **주인공 바꾸기** | 모두가 "환자가 병원까지 얼마나 걸리나"를 본다 → **"병원이 받아주는가"** 는 안 본다 | 응급실 뺑뺑이의 진짜 원인 |
| **3** | **1차 → 2차 효과** | 모두가 "이게 망하나"를 본다 → **"이게 망하면 다음은 뭐가 망하나"** 는 안 본다 | 연쇄 반응 |
| **4** | **시간 축 넣기** | 모든 접근성 연구가 **"24시간 열려 있다"고 가정**한다 | 새벽 3시엔 세상이 완전히 다르다 |
| **5** | **데이터를 직접 만들기** | 남이 안 모은 걸 **오늘부터 모으면 우리만 가진 데이터**가 된다 | 5주면 5주치 데이터 |

> **발상법 5번이 특히 강력합니다.**
> 공개 데이터는 누구나 씁니다. 그런데 **실시간으로만 나오고 저장은 아무도 안 하는 데이터**가 있습니다.
> **오늘부터 모으기 시작하면, 발표일에는 우리만 가진 데이터가 됩니다.**

# 1. 먼저 — 조사해서 확인한 빈칸 2개

## 빈칸 ① 응급의료 분야

| 이미 있는 것 | 아직 없는 것 |
|---|---|
| 거리 기반 접근성 분석 (**30분 안에 갈 수 있나**) — 논문 많음 | **"가긴 가는데 안 받아주면?"** 을 다룬 도구 |
| 병원 한 곳 내부의 대기 개선 (린 6시그마 등) | **여러 병원 사이를 떠도는 과정**을 재현한 것 |
| "뺑뺑이" 원인 분석 (전문의 부재, 병상 부족) — 뉴스·보고서 있음 | **그걸 시뮬레이션으로 재현하고 대책을 실험**하는 도구 |

**실제 확인된 숫자**
> 응급실 병상포화지수 전국 평균 **52.6%**, 그런데 **가장 붐비는 상위 20개 기관은 107%** —
> **365일 내내 빈 병상이 없는 상태**로 운영 중입니다.

> **즉, 거리 계산은 이미 다 했는데 "받아주느냐"는 아무도 계산 안 했습니다.**

## 빈칸 ② 인구감소 대응 분야

| 이미 있는 것 | 아직 없는 것 |
|---|---|
| "압축도시", "생활권 축소", "거점 집적화" — **개념과 정책 방향** 논의는 많음 | **"그래서 어느 시설을 어느 순서로 줄이나"** 를 계산하는 도구 |
| 인구감소로 재정이 나빠지고 시설 유지비가 는다는 진단 | 구체적인 **축소 우선순위** |

> **왜 아무도 안 했을까요? 정치적으로 너무 민감하기 때문입니다.**
> "이 학교부터 없애세요"라고 말하고 싶은 연구자는 없습니다.
>
> **그런데 학생 프로젝트는 이걸 할 수 있습니다.** 특정 지역을 지목하지 않고
> **"이런 기준으로 계산하면 이런 순서가 나온다"** 는 방법론만 보여주면 됩니다.

## 【1】 🚨 응급실 뺑뺑이 시뮬레이터 ⭐⭐ 가장 추천

### 한 줄로
> **"거리는 12분인데, 왜 실제로는 68분 걸리는가."**

### 뭐가 다른가 (기존 연구와 비교)

| 기존 연구 전부 | 우리 |
|---|---|
| 가장 가까운 응급실까지 **거리** | **그 응급실이 받아주는가** |
| "30분 안에 갈 수 있는 인구" | **"몇 군데를 거쳐야 받아주는가"** |
| 병원이 항상 열려 있다고 가정 | **병상이 꽉 차면 거부당한다** |

> **주인공을 바꾼 겁니다.** 환자의 이동거리가 아니라 **병원의 수용 능력**을 봅니다.
> 그리고 이게 **실제 뺑뺑이의 진짜 원인**입니다.

### 화면

```
┌─────────────────────────────────────────────────┐
│  [지도] 📍 환자 발생 지점 클릭                    │
│  환자 상태  [ 중증(심근경색)  ▼]                 │
│  발생 시각  ◀━━━━━●━━━▶  화요일 새벽 2시        │
│                                                 │
│  🚑 이송 과정 재현                                │
│   1. ○○병원   (8분)  → ❌ 거부 (중환자실 만실)   │
│   2. △△의료원 (19분) → ❌ 거부 (당직 전문의 없음) │
│   3. □□대학병원(41분) → ❌ 거부 (병상 포화)      │
│   4. ◇◇센터   (68분) → ✅ 수용                  │
│                                                 │
│  ┌───────────────────────────────────────┐      │
│  │ 직선거리 기준   12분                    │      │
│  │ 실제 도착시간   68분  (5.7배) ⚠️        │      │
│  │ 골든타임 초과   O                       │      │
│  └───────────────────────────────────────┘      │
│                                                 │
│  🔧 만약 이렇게 하면?                             │
│   ☑ ○○병원 중환자실 +3병상 → 68분이 8분으로      │
│   ☐ △△의료원 야간 당직 추가 → 68분이 19분으로   │
└─────────────────────────────────────────────────┘
```

### ⭐ 결정적 강점 — 우리만 가진 데이터를 만들 수 있습니다

> **국립중앙의료원이 실시간 응급실 가용 병상 정보를 API로 줍니다.**
> (중환자실, 수술실, 일반병상, **중증질환 수용 가능 여부**까지)
>
> **그런데 "실시간"입니다. 지금 이 순간 상태만 알려주고, 과거는 안 줍니다.**
> **아무도 이걸 저장해두지 않습니다.**
>
> **9월 9일부터 10분마다 저장하면, 10월 13일엔 5주치 전국 응급실 포화 기록이 됩니다.**
> **이건 세상에 우리만 가진 데이터입니다.**

| 날짜 | 우리가 가진 것 |
|---|---|
| 9월 9일 | 0일치 |
| 9월 23일 | 2주치 |
| **10월 13일** | **5주치 (약 5,000회 스냅샷 × 전국 응급실)** |

> **9월 9일에 수집 스크립트부터 돌리세요.** 하루 늦으면 하루치를 영영 못 얻습니다.
> **이것 하나만으로도 다른 팀과 완전히 다른 프로젝트가 됩니다.**

### AI가 어디에 들어가나 (★ = 엔진)

| 순서 | 하는 일 | 기술 | AI |
|---|---|---|---|
| ① | 5주치 병상 기록 수집·정리 | 데이터 파이프라인 | ✗ |
| ② | **★ 이 시간에 이 병원이 만실일 확률 예측** | **머신러닝** | **✅ 엔진** |
| ③ | **★ 이 환자를 받아줄 확률 예측** (중증도별) | **머신러닝** | **✅ 엔진** |
| ④ | 병원까지 이동시간 | 도로망 계산 | ✗ |
| ⑤ | 이송 과정 재현 (거부되면 다음으로) | 시뮬레이션 | ✗ |
| ⑥ | 정책 브리핑 문서 | Claude | 보조 |

> **②③이 없으면 이 시뮬레이터가 아예 성립하지 않습니다.**
> "새벽 2시에 이 병원이 받아줄까?"를 모르면 이송 과정을 재현할 수 없습니다.

### 채점 방법

| 방법 | 어떻게 |
|---|---|
| **미래 맞히기** | 4주치로 학습 → **5주차 실제 병상 상태를 맞히나** |
| **통계와 대조** | 우리가 계산한 평균 이송시간 vs 응급의료 통계포털의 실제 통계 |
| **알려진 사실 재현** | "상위 20개 기관 포화지수 107%"를 우리 데이터가 재현하나 |

### 왜 이게 강력한가
- **사회적 무게**: "응급실 뺑뺑이"는 사람이 죽는 문제입니다. "왜 만들었냐"는 질문이 안 나옵니다
- **완전히 새로운 각도**: 기존 연구는 전부 거리만 봅니다
- **우리만의 데이터**: 발표에서 "이 데이터는 저희가 5주간 직접 수집했습니다"는 강력합니다
- **조절 항목이 진짜 정책**: 병상 추가, 당직 추가는 실제로 정부가 결정하는 것입니다

### ⚠️ 주의
- **API 호출 제한**을 반드시 확인하세요. 10분마다 전국을 부르면 막힐 수 있습니다 (→ 지역을 좁히거나 주기를 늘리기)
- **환자 상태별 수용 조건**이 복잡합니다. 처음엔 **중증 1~2종만** 다루세요
- 실제 이송 기록(누가 어디서 거부당했는지)은 비공개입니다 → **"병상 상태로 추정한 것"임을 명시**

## 【2】 📉 공공시설 철수 순서 시뮬레이터

### 한 줄로
> **"예산이 20% 줄었다. 어느 시설부터 없애야 주민 피해가 가장 적은가?"**

### 뭐가 다른가

| 기존 연구 | 우리 |
|---|---|
| "어디에 새로 지을까" — 논문 수백 편 | **"어디를 없앨까"** |
| "압축도시로 가야 한다" — 개념 논의 | **구체적인 순서를 계산** |

> **모든 입지 연구는 "짓는 것"을 가정합니다.**
> 그런데 **인구가 주는 지역의 실제 고민은 "줄이는 것"** 입니다.
> **방향을 뒤집으면 아무도 안 한 영역이 나옵니다.**

### 화면

```
┌─────────────────────────────────────────────────┐
│  지역 [ ○○군          ▼]                        │
│  줄여야 할 예산 ◀━━━●━━━━▶  20 %                │
│  시설 종류 ☑어린이집 ☑도서관 ☑버스노선 ☐보건지소 │
│                                                 │
│  📋 없애는 순서 추천 (피해 대비 절감 큰 순)        │
│   1. ○○리 도서관     절감 1.2억 / 영향 40명     │
│   2. △△노선 심야편   절감 0.8억 / 영향 12명     │
│   3. □□어린이집      절감 2.1억 / 영향 180명 ⚠️ │
│   ────────── 여기까지 20% 달성 ──────────       │
│                                                 │
│  ⚠️ 절대 없애면 안 되는 시설 (대체 불가)          │
│   • ◇◇보건지소 — 없애면 반경 18km에 의료 0곳    │
│   • ☆☆어린이집 — 없애면 반경 12km에 보육 0곳    │
└─────────────────────────────────────────────────┘
```

### AI가 어디에 들어가나

| 순서 | 하는 일 | AI |
|---|---|---|
| ① | 시설 위치·인구·이용 통계 수집 | ✗ |
| ② | **★ 시설이 없어졌을 때 늘어나는 이동 부담 계산** | 도로망 + 예측 |
| ③ | **★ "이 시설이 사라지면 그 동네가 얼마나 빨리 비는가" 예측** | **머신러닝** |
| ④ | **★ 최적 축소 조합 찾기** (수천 가지 조합 중) | **최적화 (OR-Tools)** |
| ⑤ | 판단 근거 설명 | Claude |

> **③이 이 프로젝트의 핵심입니다.**
> 어린이집이 없어지면 젊은 가구가 떠납니다. 그러면 학교도 위험해집니다.
> **"단순 불편"이 아니라 "인구 이탈까지" 계산하는 게 차별점입니다.**
> 과거에 실제로 폐쇄된 시설 주변의 인구 변화로 학습합니다.

### 데이터
어린이집 정보(보건복지부), 학교알리미, 도서관·보건지소 위치, **주민등록 인구 시계열**, SGIS 격자 인구, 지방행정 인허가 데이터

### 채점 방법
> **실제로 폐쇄된 시설을 찾습니다.** (폐교, 폐원, 노선 폐지는 실제로 많습니다)
> 폐쇄 전 데이터로 "이 시설이 없어지면 주변 인구가 이렇게 변할 것"이라 예측하고,
> **폐쇄 후 실제 인구 변화와 비교**합니다.

### 반드시 지킬 것
> **특정 지역·시설을 "없애라"고 지목하지 마세요.**
> **"이런 기준으로 계산하면 이런 순서가 나온다"** 는 방법론만 보여주고,
> 화면에는 **"실제 결정은 주민 의견 수렴이 필요합니다"** 를 반드시 표시하세요.

## 【3】 🔗 폐업 도미노 시뮬레이터

### 한 줄로
> **"이 동네 마지막 슈퍼가 문을 닫으면, 그 다음엔 뭐가 닫히나?"**

### 뭐가 다른가
> 폐업 **예측**은 연구가 많습니다. (**1차 효과**)
> **폐업의 연쇄**를 본 건 거의 없습니다. (**2차 효과**)
>
> 동네가 죽는 건 한 번에 일어나지 않습니다. **순서가 있습니다.**
> 서점 → 문구점 → 약국 → 병원 → 학교 → 그리고 사람이 떠납니다.
> **이 순서를 데이터로 찾아내는 게 이 프로젝트입니다.**

### AI가 하는 일
> **"A 업종이 사라진 뒤 N개월 안에 B 업종이 사라질 확률"** 을 전국 데이터에서 학습합니다.
> 그러면 **업종 간 도미노 지도**가 그려집니다.

### 데이터와 검증
> 지방행정 인허가 데이터에 **폐업일자**가 있습니다.
> **실제로 소멸한 동네를 골라, 폐업이 일어난 순서와 우리 예측 순서를 비교**하면 검증됩니다.

### 화면에서 조절하는 것
> "이 시설 하나를 살린다면?" → 도미노가 어디서 멈추는지

### 약점
> **인과인지 상관인지 구분이 어렵습니다.** (서점이 닫혀서 약국이 닫힌 게 아니라, 둘 다 인구 때문일 수 있음)
> → **정직하게 "함께 사라지는 순서 패턴"이라고 표현**하고, 인과라고 우기지 마세요.

## 【4】 🌙 시간대별 "생활 사막" 지도

### 한 줄로
> **"새벽 3시에 이 동네에서 아픈데 갈 수 있는 곳이 있나?"**

### 뭐가 다른가
> **기존 접근성 연구는 100% "시설이 24시간 열려 있다"고 가정합니다.**
> 지도에 점을 찍고 거리를 잽니다. **영업시간은 아무도 안 봅니다.**
>
> 그런데 **새벽 3시의 세상은 완전히 다릅니다.**
> 낮에는 반경 500m에 약국 5곳인데, 새벽엔 반경 15km에 0곳일 수 있습니다.
>
> **시간 축 하나를 넣었을 뿐인데 완전히 새로운 지도가 나옵니다.**

### 화면
```
시각 ◀━━━━━━━━●━━▶  새벽 03:00

[지도가 시간에 따라 실시간으로 색이 바뀜]
  🟩 5분 내 접근 가능
  🟨 15분
  🟥 30분 이상 (= 생활 사막)

낮 14시:  사막 인구 2.1%
새벽 3시: 사막 인구 61.4%  ⚠️
```

> **슬라이더를 돌리면 지도가 빨갛게 물드는 장면** — 시연 임팩트가 아주 큽니다.

### AI가 하는 일
| 하는 일 | 왜 AI가 필요한가 |
|---|---|
| **★ 영업시간 정보 정리** | 데이터의 영업시간이 지저분함 ("연중무휴", "09~18(점심 12~13)", "명절 휴무") → **Claude가 정리** |
| **★ 영업시간이 없는 곳 추정** | 상당수 시설은 영업시간 정보가 비어 있음 → **업종·규모·위치로 예측** |
| 접근성 계산 | 도로망 |

> 여기서는 **Claude가 진짜 일을 합니다.** 지저분한 한국어 영업시간 텍스트를 구조로 바꾸는 건 규칙으로는 거의 불가능합니다.

### 데이터
지방행정 인허가 데이터(영업시간 항목 확인 필요), 응급의료기관 진료시간(**이건 확실히 있습니다**), 심야약국 목록

### 3일 안에 확인
- [ ] 인허가 데이터에 **영업시간 항목이 실제로 채워져 있는 비율**이 얼마인가 ← 이게 성패

## 【5】 👨‍⚕️ 무의촌 카운트다운

### 한 줄로
> **"이 군에 의사가 0명이 되는 건 몇 년 뒤인가."**

### 뭐가 다른가
> 모든 의료 접근성 연구는 **"지금 병원이 몇 개 있나"** 를 봅니다.
> **아무도 "그 의사들이 몇 살인가"를 안 봅니다.**
>
> 시골 의원의 원장이 68세라면, **그 병원은 10년 뒤 사라집니다.**
> 새 의사가 안 옵니다. **이건 예측이 아니라 거의 확정된 미래입니다.**

### AI가 하는 일
- **개원 시점과 폐업 시점 데이터로 "개원 후 몇 년 만에 문 닫는가" 학습**
- 지역·과목별 **신규 개원 유입률** 예측
- **10년 뒤 지역별 의료기관 수 시뮬레이션**

### 데이터
건강보험심사평가원 요양기관 현황(개설일자, 진료과목, 위치), 지방행정 인허가 데이터

### 조심할 것
> **의사 개인의 나이는 공개되지 않습니다.**
> → **개설일자로 간접 추정**하거나(개원 30년차면 최소 55세 이상), **의료기관 단위**로만 다루세요.
> 개인을 추정하지 말고 **"이 지역 의료기관의 평균 업력이 28년"** 같은 집계로만.

## 【6】 🎈 풍선효과 시뮬레이터

### 한 줄로
> **"여기를 막으면, 사람들은 어디로 몰리나?"**

### 뭐가 다른가
> 모든 정책 분석은 **"여기를 개선하면 여기가 좋아진다"** 만 봅니다.
> **"그러면 옆 동네는 어떻게 되나"** 는 아무도 안 봅니다.

### 적용 예
| 상황 | 어디로 몰리나 |
|---|---|
| 충전소 한 곳이 고장 | 근처 충전소 대기시간 급증 |
| 응급실 한 곳이 축소 | 옆 병원 포화지수 상승 |
| 버스 노선 폐지 | 인근 노선·지하철로 |

### 왜 신박한가
> **"좋아진다"만 보고 정책을 결정하면, 옆에서 터집니다.**
> 이걸 미리 계산해주는 도구는 거의 없습니다.

### 약점
> **어디로 갈지는 실제로 관찰하기 어렵습니다.** (사람 마음속을 모름)
> → **실제로 시설이 문 닫은 사례 전후 데이터**로 검증해야 합니다. 사례를 못 찾으면 이 주제는 어렵습니다.
