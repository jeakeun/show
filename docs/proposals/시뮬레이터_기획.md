# 시뮬레이터 프로젝트 주제 추천 10개 (새 주제)

기간: 2026년 9월 9일 ~ 10월 20일 · 6명 · 실제 개발 4주

> **시뮬레이터** = 사용자가 값을 바꾸면 결과가 바뀌는 것.
> **"만약 이렇게 하면 어떻게 될까?"** 를 직접 만져보는 도구.

---

# 0. 왜 시뮬레이터가 유리한가

| 그냥 예측 프로그램 | 시뮬레이터 |
|---|---|
| "이 지역 위험도 62%입니다" | **"이 시설 하나 없어지면 62% → 81%로 올라갑니다"** |
| 심사위원이 화면을 **본다** | 심사위원이 **직접 만진다** |
| 성능표를 설명해야 이해됨 | **슬라이더 한 번 당기면 바로 이해됨** |

> 발표장에서 **심사위원이 직접 값을 바꿔보게 하는 것**만큼 강한 시연은 없습니다.
> "결과를 수치화해서 잘 보이게 하라"는 요구를 정면으로 만족합니다.

---

# 1. ⚠️ 주제를 고르는 기준 — 여기서 대부분 실패합니다

## 아무 예측 모델이나 시뮬레이터로 만들면 거짓말이 됩니다

> **쉬운 예로 설명하겠습니다.**
>
> "우산 든 사람이 많으면 비가 온다"는 예측 프로그램을 만들었습니다.
> 실제로 잘 맞습니다. 우산이 많으면 진짜 비가 오거든요.
>
> 그런데 이걸 시뮬레이터로 만들어서
> **"우산 든 사람 수" 슬라이더를 0으로 내리면** 프로그램은
> **"비가 안 옵니다"** 라고 답합니다.
>
> **말도 안 되죠.** 우산을 뺏는다고 비가 안 오지 않습니다.
> 우산은 비의 **원인이 아니라 결과**니까요.

**예측 프로그램은 "같이 움직이는 것"을 배웁니다. "뭐가 뭘 만드는지"는 모릅니다.**

## 그래서 시뮬레이터 주제는 이 두 가지를 다 만족해야 합니다

| 조건 | 뜻 | 좋은 예 | 나쁜 예 |
|---|---|---|---|
| ① **사람이 진짜로 정할 수 있는 값인가** | 정책·설계로 결정하는 것 | 충전기를 몇 대 놓을까 | 이 동네 인구가 늘면 |
| ② **그 값이 결과를 직접 만드는가** | 물리적·수학적으로 이어지는가 | 병원이 없으면 그 병원으로 못 감 | 경쟁 가게가 줄면 장사가 잘 될까 |

> **이 문서의 10개 주제는 전부 이 조건을 만족하도록 골랐습니다.**
> 그래서 "시뮬레이터인데 숫자가 엉터리"라는 사고가 안 납니다.

# 【1위】 응급실 접근성 시뮬레이터 ⭐ 가장 추천

## 한 줄로

> **"이 응급실이 문을 닫으면, 몇 명이 골든타임 안에 병원에 못 가게 되는가?"**

## 왜 이 주제인가

**"응급실 뺑뺑이"는 지금 한국에서 가장 뜨거운 사회 문제 중 하나입니다.**
그런데 **"응급실 하나가 없어지면 실제로 누가 얼마나 위험해지는지"** 를 숫자로 보여주는 도구가 없습니다.

지금은 이렇게 논의됩니다:
> "○○병원 응급실 축소 결정" → 뉴스 → 주민 반발 → **아무도 정확한 피해 규모를 모름**

**우리가 만드는 것**: 지도에서 병원 하나를 끄면, **그 순간 위험해지는 인구가 몇 명인지** 지도에 빨갛게 뜹니다.

## 화면이 이렇게 됩니다

```
┌───────────────────────────────────────────────┐
│  [지도 — 전국 / 시군구 선택]                   │
│                                               │
│  🏥 응급실 목록                                │
│   ☑ ○○대학교병원 (권역응급의료센터)            │
│   ☐ △△병원 (지역응급의료기관)  ← 껐음         │
│   ☑ □□의료원                                  │
│                                               │
│  ┌─────────────────────────────────────┐      │
│  │ 30분 내 도달 불가 인구                │      │
│  │      12,400명  →  47,800명           │      │
│  │              (+35,400명) ⚠️           │      │
│  │                                      │      │
│  │ 평균 도달시간  18분 → 27분            │      │
│  │ 최악 지역     △△면 (52분)            │      │
│  └─────────────────────────────────────┘      │
│                                               │
│  🔍 어디에 새로 지으면 가장 효과적인가?         │
│   1순위: ○○읍  → 불가인구 18,200명 감소       │
│   2순위: △△리  → 불가인구 11,400명 감소       │
└───────────────────────────────────────────────┘
```

## 함정이 없는 이유

> **"병원이 있냐 없냐"는 정책으로 실제 결정하는 값**이고,
> **병원이 없으면 그 병원으로 못 가는 건 물리적으로 확실합니다.**
>
> 앞에서 말한 "우산과 비" 같은 문제가 **아예 생기지 않습니다.**

## 데이터 (직접 확인했습니다)

| 뭘 받나 | 어디서 | 뭐가 들어있나 |
|---|---|---|
| 전국응급의료기관 표준데이터 | data.go.kr/data/15096291 | **위도·경도**, 기관 분류, 진료시간 |
| 전국 응급의료기관 정보 조회 | data.go.kr/data/15000563 (국립중앙의료원) | 실시간 병상, 중증질환 수용 가능 여부, 위치 |
| 응급의료시설 | data.go.kr/data/15101855 (행안부) | 시설 목록 |
| **격자 인구** | 국가데이터처 SGIS — data.go.kr/data/15141768 + SGIS 오픈API | **100m·500m 격자 인구** (100m는 총값만) |
| 도로망 | OpenStreetMap (무료) | 실제 도로 기반 이동시간 계산 |

**3일 안에 확인할 것**
- [ ] 응급의료기관 위경도가 전부 채워져 있나
- [ ] SGIS 격자 인구를 받아서 **지도에 얹을 수 있나**
- [ ] 도로망 기반 이동시간 계산이 **한 지역이라도 돌아가나** ← 이게 핵심 기술
- [ ] 기관 분류(권역/지역응급의료센터/지역응급의료기관)가 구분되나

## 채점을 어떻게 하나 (여기가 결정적)

**정부가 이미 "응급의료 취약지"를 공식 지정해 놨습니다.**

> **우리 프로그램이 계산한 취약지 ↔ 정부가 지정한 취약지**
> 이 둘을 맞춰보면 **정확도를 숫자로 낼 수 있습니다.**
>
> | | |
> |---|---|
> | 정부 지정 취약지를 우리가 잡아낸 비율 | ○% |
> | 우리만 취약하다고 한 지역 | ○곳 (→ 왜 다른지 분석하면 그게 발견) |
>
> **"정부 기준을 재현했다"** 를 증명하고 나면,
> **"그럼 병원이 하나 없어지면?"** 이라는 우리 시뮬레이션도 믿을 수 있게 됩니다.

추가 검증: **실제로 응급실이 폐쇄·축소된 사례**를 찾아, 그 전후로 우리 계산이 맞았는지 확인합니다.

## AI를 어디에 쓰나

| 부분 | 쓰는 기술 | 설명 |
|---|---|---|
| 이동시간 계산 | 도로망 최단경로 | 직선거리가 아니라 **실제 도로로** 계산 |
| 이동시간 보정 | **예측 모델** | 시간대·도로 등급별로 실제 구급차 속도가 다름 → 학습으로 보정 |
| **최적 입지 찾기** | **조합 최적화** | "한 곳만 새로 짓는다면 어디?" — 후보 수천 곳 중 최선을 찾는 계산 |
| 결과 설명 | AI 챗봇 | "○○면 주민 3,200명이 가장 가까운 응급실까지 52분 걸립니다" |

> **"최적 입지 찾기"가 이 프로젝트에서 가장 어렵고 가장 값진 부분입니다.**
> 후보 지점이 5,000곳이면 경우의 수가 어마어마해서, 하나씩 다 해볼 수가 없습니다.
> **똑똑하게 좁혀가며 찾는 방법**을 써야 하고, 그게 기술 포인트가 됩니다.

## 6명이 뭘 맡나

| 담당 | 하는 일 |
|---|---|
| **1번** | 응급의료기관 데이터 수집·정리 (위치, 등급, 진료시간) |

| **6번** | 지도 화면 + 병원 켜고 끄기 + 결과 표시 |

## 목표 숫자

| 뭘 재나 | 목표 |
|---|---|
| 정부 지정 취약지 재현율 | **80% 이상** |

| 전국 계산 속도 | 병원 하나 끄면 **3초 안에** 결과 |
| 최적 입지 추천의 개선 효과 | 아무 데나 짓는 것 대비 **2배 이상** |

## 발표에서 나올 문장

> **"○○병원 응급실이 문을 닫으면, 30분 안에 응급실에 갈 수 없는 사람이 3만 5천 명 늘어납니다.
> 대신 △△읍에 하나 지으면 1만 8천 명이 다시 30분 안으로 들어옵니다."**

# 【2위】 전기차 충전소 입지 시뮬레이터

## 한 줄로

> **"여기에 충전기 3대를 놓으면, 줄 서는 시간이 얼마나 줄어들까?"**

## 왜 이 주제인가

전기차는 계속 느는데 **충전기는 어디에 몇 대를 놓아야 하는지** 감으로 정합니다.
너무 적게 놓으면 줄이 길고, 너무 많이 놓으면 놀립니다. **둘 다 돈 낭비입니다.**

**누가 쓰나**: 충전 사업자, 지자체, 아파트 관리사무소, 대형마트·주유소

## 화면이 이렇게 됩니다

```
┌───────────────────────────────────────────────┐
│  [지도] 📍 선택 위치: 강남구 역삼동 ○○         │
│                                               │
│  급속 충전기  ◀━━●━━━━━▶   2 대               │
│  완속 충전기  ◀━━━━●━━━▶   4 대               │
│                                               │
│  ┌─────────────────────────────────────┐      │
│  │ 평균 대기시간     18분 → 4분          │      │
│  │ 충전기 이용률     94% → 61%          │      │
│  │ 헛걸음 비율       31% → 6%           │      │
│  │                                      │      │
│  │ 하루 처리 대수    47대 → 112대        │      │
│  └─────────────────────────────────────┘      │
│                                               │
│  💰 급속 1대 더 놓으면 대기 4분 → 2분          │
│     (효과가 급격히 줄어드는 지점입니다)         │
└───────────────────────────────────────────────┘
```

## 함정이 없는 이유

> **충전기를 몇 대 놓을지는 사업자가 진짜로 정하는 값**이고,
> **대수가 늘면 줄이 짧아지는 건 수학적으로 확실합니다.**
>
> 이건 이미 100년 된 수학 이론(대기행렬 이론)으로 계산됩니다.
> 은행 창구를 몇 개 열지, 콜센터 상담원을 몇 명 둘지 정할 때 쓰는 바로 그 방법입니다.

## 데이터 (직접 확인했습니다)

| 뭘 받나 | 어디서 | 뭐가 들어있나 |
|---|---|---|
| 전기자동차 충전소 정보 | data.go.kr/data/15076352 (한국환경공단) | 충전소 ID, **충전기 타입**, 주소, **위도·경도**, 이용가능시간, 운영기관 |
| **서울시 소유 충전소 충전량** | data.seoul.go.kr (OA-22249) | **충전량, 충전시간, 날짜, 충전기 최대용량** ← 실제 사용 기록 |
| 지역별 충전소 현황 | 경기데이터드림 등 | 충전기 대수, 위치 |

> **"충전시간"과 "날짜"가 있다는 게 결정적입니다.**
> 언제 얼마나 오래 충전했는지를 알면, **줄이 얼마나 길었을지 역산할 수 있습니다.**

**3일 안에 확인**: 서울시 충전량 데이터에 **충전 시작·종료 시각**이 있나 / 충전소별로 몇 달치가 있나

## 채점을 어떻게 하나

**방법 1 — 과거로 맞춰보기**
> **충전기가 새로 늘어난 충전소를 찾습니다.**
> 늘기 전 데이터로 "이만큼 늘리면 대기시간이 이렇게 될 것"이라고 예측하고,
> **실제로 늘어난 뒤 데이터와 비교**합니다.

**방법 2 — 이용률 맞추기**
> 우리 모델이 예측한 이용률과 실제 이용률을 비교합니다.

## AI를 어디에 쓰나

| 부분 | 쓰는 기술 |
|---|---|
| **수요 예측** | 요일·시간대·주변 환경(아파트/사무실/상가)으로 **몇 대가 올지** 예측 |
| 대기시간 계산 | 대기행렬 이론 (수학) |

# 4. 최종 추천

## 하나만 고르라면: **1번 응급실 접근성 시뮬레이터**

이유 4가지:

1. **함정이 아예 없습니다.** 병원이 없으면 그 병원으로 못 가는 건 물리적 사실입니다.
2. **채점 방법이 특별합니다.** 정부가 지정한 취약지 목록과 대조해서 **"정부 기준을 재현했다"** 를 먼저 증명할 수 있습니다. 이런 검증을 하는 팀은 거의 없습니다.
3. **사회적 무게가 있습니다.** "응급실 뺑뺑이"는 지금 실제 문제입니다. **"이거 왜 만들었냐"는 질문이 안 나옵니다.**
4. **AI 기술이 확실히 들어갑니다.** 최적 입지 찾기는 경우의 수가 어마어마해서 똑똑한 탐색 기법이 꼭 필요합니다.

## 안전하게 가려면: **2번 전기차 충전소**

- 데이터가 가장 확실하고 (충전 시간 기록까지 있음)
- 대기시간 계산은 검증된 수학이라 **틀릴 여지가 적고**
- 증설 사례로 검증이 되고
- **사업성 질문에 바로 답이 됩니다** (충전 사업자가 실제로 쓸 도구)

## 시연이 가장 화려하려면: **3번 산불** (단, 범위 축소 필수)

## 조합 추천

- **1번 + 5번** (응급실 + 학교): 둘 다 **"시설이 없어지면 얼마나 멀어지나"** 라서 **핵심 계산 엔진이 똑같습니다.** 하나 만들어서 둘 다 보여줄 수 있습니다. **가성비 최고의 조합입니다.**
- **1번 + 7번** (응급실 + 대피소): 위와 같은 이유

> 시뮬레이터는 **화면이 예뻐서 만드는 재미**가 있습니다.
> 그래서 **안쪽 계산이 엉망인데 겉만 번드르르한 결과물**이 나오기 쉽습니다.

> **예쁜 화면에 틀린 숫자가 나오면 그건 그냥 예쁜 거짓말입니다.**
>
> **막는 법**: 화면은 **4주차(10/3~10/9)에 시작**합니다.
> 3주차까지 계산 정확도가 안 나오면 **화면을 단순하게 줄이고 계산에 집중**하세요.

## 함정 2 — 슬라이더를 너무 많이 만든다

> **조절 항목이 5개를 넘으면 사용자가 뭘 만져야 할지 모릅니다.**

## 함정 3 — 시뮬레이터 자체의 정확도를 안 잰다

> "슬라이더를 당기면 숫자가 바뀐다"만으로는 부족합니다.

> - 산불: 과거 산불의 실제 피해면적과 얼마나 맞았나
>
> **이 검증을 넣는 팀은 거의 없습니다. 넣으면 확실히 차별화됩니다.**
