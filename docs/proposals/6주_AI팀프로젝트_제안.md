# 6인 AI 팀프로젝트 후보 12개 (쉬운 설명판)

기간: 2026년 9월 9일 ~ 10월 20일 · 6명 · 마지막 주는 발표 준비

> **이 문서를 읽는 법**
> 어려운 말은 안 씁니다. 나오면 바로 옆에 쉬운 뜻을 적어뒀습니다.
> 표는 훑어보시고, 굵은 글씨만 따라가도 내용이 잡히게 썼습니다.

## 0. 먼저 알아야 할 3가지

### ① 시간이 생각보다 훨씬 없습니다

6주라고 하지만 실제로 만드는 시간은 **4주**입니다.

| 언제 | 뭘 하나 | 왜 |
|---|---|---|
| 9/9 ~ 9/11 (3일) | **되는지 확인만** | 데이터가 진짜 손에 들어오는지 봅니다. 안 들어오면 주제를 바꿉니다 |
| 9/12 ~ 10/9 (4주) | **진짜 만드는 기간** | 여기가 전부입니다 |
| 10/10 ~ 10/13 | **손 떼기** | 코드를 더 안 건드립니다. 마지막에 고치다 터지는 게 제일 흔한 사고입니다 |
| 10/14 ~ 10/20 | 발표 준비 | 자료 만들고 연습 |

**핵심**: "6주니까 여유 있다"고 생각하면 망합니다. **4주짜리 프로젝트**로 잡아야 합니다.

### ② 6명이 각자 만들면 합칠 때 터집니다

바이브코딩(AI에게 시켜서 코드 만들기)으로 각자 작업하면 개인 속도는 엄청 빠릅니다.
그런데 **합칠 때 반드시 터집니다.** 이유는 늘 똑같습니다.

> 사람 A는 날짜를 `2026-09-09`로 쓰고, 사람 B는 `20260909`로 씁니다.
> 각자 코드는 완벽하게 돌아갑니다. 근데 붙이면 안 돌아갑니다.

**해결법 (이 문서의 모든 후보에 똑같이 적용)**

| 위험 | 이렇게 막습니다 |
|---|---|
| 데이터 모양이 서로 다름 | **첫 주 첫날에 "주고받을 데이터 모양" 6개를 정하고 못 박습니다.** 코드보다 약속이 먼저입니다 |
| 마지막에 합치다 폭발 | **첫 주 안에 가짜 데이터로 6명 걸 한 번 쭉 연결해봅니다.** 알맹이는 나중에 채웁니다 |
| AI가 만든 코드를 아무도 검증 안 함 | 각자 맡은 부분마다 **테스트 5개는 사람이 직접 씁니다.** 이건 AI에게 안 맡깁니다 |
| 점수 기준이 사람마다 다름 | **점수 매기는 코드는 1명만 만지고 나머지는 못 건드립니다** |
| 데이터 담당이 병목 | 첫 3일에 **데이터를 파일로 떠서 나눠 갖습니다.** 6명이 각자 서버에 요청하지 않습니다 |

> 그래서 아래 모든 후보를 **미리 6조각으로 잘라놨습니다.** 그대로 1인당 1조각씩 가져가면 됩니다.

### ③ 이런 주제는 미리 뺐습니다

| 뺀 것 | 왜 |
|---|---|
| 큰 AI 모델을 처음부터 학습시키는 것 | 비싼 그래픽카드가 몇 주씩 필요합니다. 4주에 못 합니다 |
| 사람이 점수를 매겨야 하는 것 (글이 잘 써졌나 등) | 숫자로 증명이 안 됩니다 |
| 데이터를 처음부터 만들어야 하는 것 | 데이터 만들다 4주가 끝납니다 |
| 흔한 것 (AI 챗봇, 이력서 첨삭, 회의록 요약, 여행 추천, AI 면접) | 다른 팀도 다 합니다 |

## 1. 후보 12개 한눈에

**"정답 라벨"이 뭔가요?**
> AI가 잘했는지 못했는지 채점하려면 **정답지**가 필요합니다.
> 정답지를 사람이 직접 만들면 몇 주가 걸립니다. **그런데 정답지가 이미 데이터에 들어있는 주제들이 있습니다.**
> 예: "이 가게 망할까?"를 맞히는 문제 → 과거 데이터에 **실제로 망한 날짜**가 이미 적혀 있습니다. 그게 정답지입니다.
> 아래 12개는 전부 이 조건을 만족합니다.

| # | 뭘 만드나 | 정답지는 어디에 있나 | 특별한가 | 어렵나 |
|---|---|---|---|---|
| **1** | **법 바뀌면 고칠 문서 찾아주기** | 과거에 법이 바뀌었을 때 실제로 뭐가 고쳐졌는지 기록 | ★★★★★ | 보통 |
| **2** | **오래돼서 틀려진 답변 찾아내기** | 법 바뀌기 전 자료로 만든 답 = 자동으로 "낡음" 표시 | ★★★★★ | 보통 |
| **3** | **입찰 얼마 써야 딸지 알려주기** | 과거에 누가 얼마에 땄는지 전부 공개 | ★★★★☆ | 보통 |
| **4** | **우리 아파트 관리비 바가지인지 보기** | 비슷한 아파트들의 실제 관리비 | ★★★★★ | 쉬움 |
| **5** | **이 가게 망할 위험 알려주기** | 인허가 데이터에 **실제 폐업 날짜**가 있음 | ★★★★☆ | 보통 |
| **6** | **이 법안 국회 통과할지 맞히기** | 과거 법안이 통과됐는지 전부 공개 | ★★★★★ | 쉬움 |
| **7** | **통화 중 보이스피싱 잡아내기** | 금감원 공개 수법·목소리 | ★★★★☆ | 어려움 |
| **8** | **계약서에서 나한테 불리한 조항 찾기** | 표준계약서를 일부러 나쁘게 바꿔서 정답 만들기 | ★★★★☆ | 보통 |
| **9** | **AI 답변에서 거짓말 부분 표시하기** | 공개 벤치마크(다른 연구자들이 만든 시험지) | ★★★☆☆ | 보통 |
| **10** | **한국어로 물으면 데이터 찾아주기** | **컴퓨터가 직접 채점** (결과가 같으면 정답) | ★★★☆☆ | 보통 |
| **11** | **AI 비서가 왜 실수하는지 밝히기** | 공개 시험 도구 | ★★★★☆ | 보통 |
| **12** | **약 같이 먹으면 위험한 조합 찾기** | 이미 알려진 위험 조합 목록 | ★★★★☆ | 어려움 |

## 【1】 법이 바뀌면 고쳐야 할 문서 찾아주기 ⭐ 종합 1등

### 한 줄로
> **"법이 바뀌었다. 우리 회사 문서 3천 개 중에 지금 당장 고쳐야 하는 건 뭐지?"** 를 대신 찾아줍니다.

### 무슨 문제를 푸나 (쉽게)
법은 계속 바뀝니다. 그런데 회사 규정, 약관, 안내문은 **누가 언제 뭘 고쳐야 하는지 아무도 모릅니다.**
지금은 담당자가 개정된 법을 읽고 **문서를 하나하나 눈으로 대조**합니다. 사람이 3천 개를 다 볼 수는 없습니다.

**우리가 하는 일**: 3천 개를 **"고쳐야 할 가능성이 높은 순서로 정렬한 20개"** 로 줄여줍니다.

### 데이터는 어디서 (확인했습니다)
**법제처 국가법령정보 공개 서비스**가 조문 내용, 시행일, **개정 이력**을 공짜로 줍니다.
→ open.law.go.kr 에서 신청

### 채점이 왜 되나 (여기가 핵심)
> 과거에 법이 바뀌었던 기록이 남아 있습니다.
> **"2024년 3월에 A법이 바뀌었을 때, 그 뒤로 실제로 고쳐진 문서가 뭐였는지"** 가 데이터에 있습니다.
> 우리 프로그램이 그 문서를 상위에 올렸는지 확인하면 됩니다.
> **사람이 정답지를 만들 필요가 없습니다.** 이게 이 주제의 최대 장점입니다.

### 왜 특별한가
챗봇이나 검색이 아닙니다. **"하나가 바뀌면 뭐가 따라 바뀌어야 하나"** 를 찾는 문제입니다.
이런 걸 만드는 팀은 거의 없는데, 법무·규정 관리 쪽에서는 **실제로 돈 내고 사는 기능**입니다.

### 6명 역할 나누기
| 담당 | 뭘 만드나 |
|---|---|
| 1번 | 법령 데이터 모으고 조문 단위로 쪼개기 |
| 2번 | 검사할 문서들 모으고 조항별로 쪼개기 |
| 3번 | **바뀐 법 조문과 관련 있을 것 같은 문서 후보 찾기** (검색 담당) |
| 4번 | **후보 중에서 진짜 영향받는지 AI가 판단** + 이유 문장 뽑기 |
| 5번 | **채점**: 과거 사례로 우리가 잘 맞혔는지 점수 매기기 |
| 6번 | 화면: 바뀐 법 → 영향받는 문서 순위 → 근거 표시 |

### 3일 안에 확인할 것
1. 데이터 신청하고 **하루 안에 조문 1,000개** 받아지나
2. 과거 개정 사례 1건을 **손으로 추적해서 정답을 찾을 수 있나** (안 되면 이 주제 포기)
3. 검색으로 후보 20개 뽑았을 때 정답이 그 안에 들어오나

### 목표 숫자
| 뭘 재나 | 목표 |
|---|---|
| 정답 문서를 상위 20개 안에 넣는 비율 | **80% 이상** |
| 엉뚱한 걸 지목하는 비율 | 20% 이하 |
| 검토 시간 절감 | 3,000개 → 20개, **절감률 %로 환산** |

## 【2】 오래돼서 틀려진 답변 찾아내기 ⭐ 기술적으로 가장 새로움

### 한 줄로
> **"우리 회사 챗봇 답변 5천 개 중에, 제도가 바뀌어서 지금은 틀린 답이 몇 개지?"**

### 무슨 문제를 푸나 (쉽게)
회사 FAQ나 챗봇 답변은 **만들 땐 맞았는데 시간이 지나면 틀려집니다.**
세금 비율, 지원금 조건, 신청 기한, 수수료... 이런 게 바뀌면 예전 답변은 거짓말이 됩니다.
그런데 **아무도 주기적으로 검사하지 않습니다.**

**"AI가 거짓말했다"가 아니라 "유통기한이 지났다"** 는 문제입니다. 그래서 기존 도구로는 안 잡힙니다.

### 정답지를 프로그램이 자동으로 만듭니다 (여기가 핵심)
```
법이 바뀌기 전 자료로 만든 답변  →  지금 기준으로 보면 틀림  →  정답: "낡음"
법이 안 바뀐 자료로 만든 답변    →  지금도 맞음              →  정답: "괜찮음"
```
> 사람이 손대지 않고 **수천 개의 정답지**를 만들 수 있습니다.
> 4주짜리 프로젝트에서 이건 어마어마한 이점입니다.

### 왜 특별한가
"AI가 거짓말하는 걸 잡는" 연구는 많습니다.
**"시간이 지나서 틀려진 걸 잡는" 건 거의 없습니다.** 문제 자체가 새로워서 발표에서 확실히 눈에 띕니다.

### 6명 역할 나누기
| 담당 | 뭘 만드나 |
|---|---|
| 1번 | 법 조문의 **옛날 버전과 지금 버전** 둘 다 모으기 |
| 2번 | 옛날 자료 기준으로 답변 3,000개 자동 생성 |
| 3번 | **정답 붙이기**: 바뀐 부분 비교해서 "낡음/괜찮음" 자동 표시 |
| 4번 | **탐지기 만들기**: 3가지 방법으로 만들어 비교 |
| 5번 | 채점 |
| 6번 | 화면: 낡은 답변 목록 + 원인이 된 법 조문 + 고칠 문장 제안 |

### 3일 안에 확인할 것
1. **같은 조문의 옛날 버전과 지금 버전을 둘 다 받을 수 있나** ← 이거 하나가 성패를 가릅니다
2. 바뀐 부분에서 숫자·기한 변경을 자동으로 뽑을 수 있나
3. 자동으로 붙인 정답 50개를 사람이 봤을 때 **90% 이상 동의하나**

### 목표 숫자
| 뭘 재나 | 목표 |
|---|---|
| 낡은 답변 골라내는 정확도 | **AUROC 0.85 이상** (AUROC = 0.5면 찍는 수준, 1.0이면 완벽) |
| 헛짚는 비율을 5%로 고정했을 때 잡아내는 비율 | **70% 이상** |
| 1만 개 검사 비용 | AI를 전부 부르는 것 대비 **10분의 1 이하** |

## 【3】 입찰, 얼마 써야 딸지 알려주기

### 한 줄로
> **"우리 회사가 딸 만한 공고만 골라주고, 얼마를 써야 하는지 알려준다."**

### 무슨 문제를 푸나
나라장터(정부·공공기관이 물건 사고 공사 맡기는 사이트)에는 하루에 수백 건이 올라옵니다.
중소기업은 **읽을 시간이 없어서** 놓치고, 넣어도 **얼마를 쓸지 감으로** 정합니다.

### 데이터 (확인했습니다)
공공데이터포털에서 공짜로 줍니다.
- **입찰공고정보**: 어떤 일인지, 예상 금액, 자격 조건
- **낙찰정보**: **누가 얼마에 땄는지 전부 공개** ← 정답지

### 채점이 왜 되나
과거 데이터에 **누가 얼마에 땄는지 전부 있습니다.**
"우리 방식대로 작년에 입찰했으면 몇 건 땄을까?"를 그대로 계산해볼 수 있습니다.

### 주의: 이건 흔한 주제입니다
공모전에 자주 나옵니다. 차별화하려면 **금액 맞히기에서 멈추면 안 됩니다.**
- 공고문 원문을 읽고 **"우리 회사가 자격이 되나"를 AI가 판단**하는 부분
- **금액을 하나로 찍지 말고 "1억 2,600만~1억 3,100만 원 사이"처럼 범위로** 예측

여기까지 가면 흔하지 않습니다.

### 3일 안에 확인할 것
- **공고와 낙찰 결과가 서로 연결되나** ← 여기가 제일 자주 깨집니다
- 최근 3개월치 각 5,000건이 받아지나

### 목표 숫자
| 뭘 재나 | 목표 |
|---|---|
| 금액 예측 오차 | **3% 이내** |
| 자격 판별 정확도 | 80% 이상 |
| 담당자가 볼 공고 수 | **90% 줄이기** |

## 【4】 우리 아파트 관리비, 바가지인가?

### 한 줄로
> **"비슷한 조건 아파트들과 비교했을 때, 우리 아파트에서 유독 비싼 항목과 그 금액."**

### 무슨 문제를 푸나
관리비는 항목별로 다 공개됩니다. 그런데 **비교할 기준이 없어서** 숫자를 봐도 모릅니다.
"우리 경비비 3천만 원"이 비싼 건지 싼 건지 알 수가 없습니다.

### 데이터 (확인했습니다)
- **K-apt (공동주택관리정보시스템)**: 관리비 **48개 항목** 공개. 300세대 이상은 공개 의무
- 공공데이터포털에 단지 기본정보, 관리비 API가 여러 개 있음

### 이 프로젝트의 진짜 기술은 여기 있습니다
**단순히 전국 평균과 비교하면 아무 의미가 없습니다.**
1,000세대 새 아파트와 300세대 30년 된 아파트를 비교하면 당연히 다릅니다.

그래서 **조건이 비슷한 아파트끼리 묶는 게 기술의 절반**입니다.

| 맞춰야 할 조건 | 왜 |
|---|---|
| 세대수 | 클수록 1세대당 싸짐 |
| 지은 연도 | 오래되면 수리비가 늘어남 |
| 난방 방식 | 개별/중앙/지역난방은 구조가 완전히 다름 |
| 복도 형태 | 계단식/복도식은 공용 면적이 다름 |
| 지역 | 인건비·물가가 다름 |

### 잘 묶었다는 걸 어떻게 증명하나
> **비슷한 아파트끼리 묶었더니 관리비 차이가 전국 평균 대비 얼마나 줄었나.**
> 40% 이상 줄면 "제대로 묶었다"는 증거입니다. 이 숫자 하나로 증명합니다.

### 발표에서 제일 센 숫자
> **"전국에서 과하게 나가는 관리비 추정 총액 ○○억 원"**

### 약점과 대책
**기술이 좀 얕아 보일 수 있습니다** (통계만 하는 것처럼).
→ 아파트 묶는 부분에 AI 학습 기법을 쓰고, 이상한 이유를 AI가 문장으로 설명하게 만들어서 AI 비중을 확보합니다.

## 【5】 이 가게, 망할 위험이 있나

### 한 줄로
> **"이 자리, 이 업종, 이 가게가 6개월 안에 문 닫을 확률."**

### 왜 "실패할 확률이 가장 낮은" 주제인가
**정답이 이미 데이터에 다 들어 있기 때문입니다.**
```
2024년 시점 정보로 예측  →  2025년에 실제로 망했는지로 채점
```
성적이 안 나와도 **"뭐는 예측되고 뭐는 예측이 안 되더라"** 가 결론이 됩니다.
**빈손으로 끝날 수가 없는 구조입니다.**

### 데이터 (컬럼까지 확인했습니다)
지방행정 인허가 데이터에 이런 항목들이 들어 있습니다:
**인허가일자 / 영업상태명 / 폐업일자 / 휴업 시작·종료일 / 재개업일자**
→ **폐업일자가 곧 정답지입니다.**

> 참고: LOCALDATA 포털은 2026년 4월 16일에 닫혔고, 지금은 **공공데이터포털(data.go.kr)** 에서 받습니다.

### 이 프로젝트의 유일한 함정
**"미래 정보 훔쳐보기"** 입니다. 어려운 말로 데이터 누수라고 합니다.

> 쉽게 말하면 이런 겁니다.
> **시험 문제를 풀면서 답지를 몰래 본 거랑 똑같습니다.**
> 2024년 시점으로 예측한다면서 2025년 정보를 슬쩍 쓰면, 점수는 엄청 잘 나오는데 **다 가짜입니다.**

**막는 법**: 데이터를 만드는 사람 1명을 정하고, **나머지 5명은 그 사람이 만든 데이터만 씁니다.**
각자 데이터를 만들면 반드시 누가 실수합니다.

### 뭘 보고 예측하나
| 종류 | 예 |
|---|---|
| 가게 자체 | 몇 년 됐나, 업종, 쉬었던 적 있나 |
| **주변 경쟁 상황** | 반경 300m 안에 같은 업종 몇 개, **최근 1년간 늘었나 줄었나** |
| **상권 건강도** | 주변 폐업률 추세, 업종이 다양한가 |
| 위치 | 역세권인가, 큰길가인가 |

> **"주변 상권이 죽어가고 있나"를 시간 흐름으로 잡는 게** 일반 상권분석과 다른 점입니다.

### 목표 숫자
| 뭘 재나 | 목표 |
|---|---|
| 예측 정확도 (AUROC) | **0.75 이상** |
| 위험 상위 10%의 실제 폐업률 | **평균의 3배 이상** |
| 확률이 진짜 맞나 | "70% 위험"이라 했으면 실제로 70%가 망해야 함 |

## 【6】 이 법안, 국회 통과할까?

### 한 줄로
> **"발의된 법안 중에 실제로 통과되는 건 얼마 안 된다. 뭐가 통과되고 왜 통과되나?"**

### 무슨 문제를 푸나
회사, 협회, 시민단체는 자기한테 영향 주는 법안을 챙겨야 하는데 **너무 많아서** 뭘 봐야 할지 모릅니다.

### 데이터 (확인했습니다)
**열린국회정보 공개 서비스**에서 과거 법안과 **결과(통과됐나, 폐기됐나)가 전부 공개**됩니다.
의원 발의 법안, 본회의 표결 정보까지 있습니다.

### 왜 특별한가
**아무도 안 합니다.** 그런데 정책·대외협력 분야에서는 실제 수요가 있습니다.

그리고 기술적으로도 재밌습니다. 이걸 맞히려면 **3가지를 다 봐야 합니다**:
1. 법안 내용 (글)
2. 누가 발의했나, 몇 명이 같이 냈나, 어느 상임위인가 (숫자·분류)
3. **같이 발의한 의원들의 관계망** (누가 영향력 있는 의원인가)

### 발표에서 나올 수 있는 결론
> "통과 여부를 가르는 건 법안 내용보다 **발의자 수와 상임위**였다"
> — 이런 결론 자체가 결과물입니다.

### 반드시 지킬 것
**정치적으로 중립을 지켜야 합니다.**
특정 정당이 유리하다/불리하다는 해석은 결론으로 내지 말고, **"얼마나 정확히 맞혔나"와 "뭐가 중요한 요인이었나"까지만** 보고합니다.
이 원칙을 발표에서 밝히면 오히려 완성도가 높아 보입니다.

## 【7】 통화 중에 보이스피싱 잡아내기

### 한 줄로
> **"통화가 끝난 뒤에 경고하면 소용없다. 시작 30초 안에 잡아야 한다."**

### 무슨 문제를 푸나
지금 앱들은 대부분 **전화번호로 차단**합니다. 새 번호를 쓰면 못 막습니다.
**대화 내용을 듣고 판단**해야 합니다.

### 발표에서 제일 센 숫자
> **"몇 초 만에 잡아냈나"**

### 데이터 — 그리고 솔직한 한계
금융감독원 보이스피싱지킴이에서
- 2026년 4월에 **사기범 7명의 실제 목소리 공개**
- 2024년에 제보된 음성 3,959건을 국과수 분석으로 걸러낸 것

> ① 공개된 수법·대본을 **글로 정리**하고
> ② 컴퓨터 음성(TTS)으로 읽혀서 데이터를 늘리고
> ③ 평범한 한국어 통화 데이터를 "정상"으로 씁니다
>
> **3일 안에 진짜 음성이 몇 개 확보되는지 세어보고, 부족하면 "글자 단계에서 잡기"로 범위를 줄이세요.**

### 이건 어렵습니다
7개 중 난이도 최상입니다. **음성까지 붙이면 4주에 벅찹니다.**
→ **글(받아쓴 내용)로 먼저 잡는 걸 완성하고, 시간이 남으면 음성을 붙이는** 순서를 권합니다.

## 【8】 계약서에서 나한테 불리한 조항 찾기

### 한 줄로
> **"받은 계약서를 표준 계약서와 나란히 놓고, 나한테 불리하게 바뀐 부분만 빨갛게 표시."**

### 무슨 문제를 푸나
프리랜서, 소상공인, 초기 스타트업은 계약서를 받아도 **뭐가 불리한지 모릅니다.**
"요약해주는" 서비스는 많은데, **표준과 비교해서 다른 지점을 짚어주는 건** 거의 없습니다.

> 왜냐하면 **불리한지는 비교를 해야만 알 수 있기 때문입니다.**
> "손해배상 전액 부담"이라는 조항만 봐서는 이게 원래 그런 건지 이 계약서만 이상한 건지 모릅니다.

### 정답지를 어떻게 만드나
**표준계약서를 일부러 나쁘게 바꿔서 정답을 만듭니다.**

| 어떻게 바꾸나 | 예 | 나쁜 정도 |
|---|---|---|
| 권리를 지움 | 해지 통보 유예기간 조항 삭제 | 심각 |
| 기한을 늘림 | 대금 지급 30일 → 90일 | 심각 |
| 책임을 떠넘김 | 손해배상 전액 부담 추가 | 심각 |
| 한도를 만듦 | 배상 한도를 계약금 10%로 제한 | 보통 |
| 한쪽에만 권한 | 발주자가 마음대로 해지 가능 | 심각 |
| **아무 문제 없는 변경** | 문구만 다듬음, 순서만 바꿈 | **없음** |

> **마지막 항목이 제일 중요합니다.**
> 멀쩡한 변경을 섞어놔야 **"전부 다 빨갛게 칠하는" 엉터리 프로그램을 걸러낼 수 있습니다.**

### 목표 숫자
| 뭘 재나 | 목표 |
|---|---|
| 표준 제5조와 계약서 제6조를 올바르게 짝짓기 | **90% 이상** |
| 불리한 조항을 잡아내는 비율 | 80% 이상 |
| 멀쩡한 걸 불리하다고 하는 비율 | **15% 이하** |

## 【9】 AI 답변에서 거짓말 부분 표시하기

### 한 줄로
> **"AI가 문서를 보고 답했는데, 문서에 없는 내용을 지어낸 문장에 빨간 줄을 긋는다."**

### 왜 필요한가
AI에게 문서를 주고 답하게 해도 **문서에 없는 내용이 섞입니다.**
지금 이걸 거르는 방법은 두 개뿐인데 둘 다 문제입니다.

| 방법 | 문제 |
|---|---|
| 사람이 검수 | 느리고 비쌈. 실시간 서비스에 못 씀 |
| 비싼 AI에게 "이거 맞아?" 물어보기 | **정확도도 낮고** 돈이 많이 듦 |

### 이미 증명된 숫자 (외국 연구)
공개된 시험(RAGTruth, 문제 18,000개)에서:

| 방법 | 크기 | 점수 |
|---|---|---|
| GPT-4에게 물어보기 | – | **63.4점** |
| 130억짜리 모델 학습 | 130억 | 78.7점 |
| **4억짜리 작은 모델** | **4억** | **79.2점** |

> **4억짜리가 130억짜리를 이겼습니다.** 30배 작은데 더 정확합니다.
> 비용도 비슷한 연구에서 **1만 3천 건 검사에 $0.24 vs $107 (400배 차이)** 로 나왔습니다.

**한국어에는 이런 게 없습니다.** 시험지(K-HALU, K-FinHallu)는 있는데 도구가 없습니다.

### 4주에 맞는 현실적인 범위
큰 모델을 학습시키지 말고, **3단계로 걸러내는 방식**으로 갑니다.
```
문장 하나 → 1단계: 숫자·날짜가 원문에 있나? (공짜, 즉시)
          → 2단계: 원문과 뜻이 비슷한가? (거의 공짜, 0.005초)
          → 3단계: 애매한 것만 AI에게 물어보기 (돈 듦)
```
> **성과 = "AI 호출을 100%에서 30%로 줄이면서 정확도는 유지했다"**

## 【10】 한국어로 물으면 데이터 찾아주기

### 한 줄로
> **"작년 3분기 강남점 매출 알려줘" → 프로그램이 알아서 데이터를 찾아옴.**

### 왜 이게 채점 논쟁이 없나
> **컴퓨터가 직접 채점합니다.**
> 만든 명령어를 실제로 실행해서 **결과가 정답과 같으면 맞은 것**입니다.
> AI 심판도, 사람 채점도 필요 없습니다. **"이 점수 믿을 수 있냐"는 질문이 원천 차단됩니다.**

### 이미 나와 있는 숫자
공개 시험(BIRD: 문제 12,751개, 데이터베이스 95개, 분야 37개)

| 누가 | 정확도 |
|---|---|
| **사람** | **92.96%** |
| 현재 1등 AI | **80.04%** |
| 유명 AI들 | 약 70% |

> **최고 AI도 사람보다 13%p 못 합니다. 아직 안 풀린 문제입니다.**
> 그리고 **이 숫자는 전부 영어 기준입니다.**

### 우리가 채우는 빈칸 — 한국식 데이터의 어려움
| 뭐가 어려운가 | 예 |
|---|---|
| 한글로 된 항목 이름 | `주민등록인구`, `자치구코드` |

| 행정구역 | 시도-시군구-읍면동, 코드 체계가 여러 개 |
| 한글 값 맞추기 | "강남" vs "강남구" |

**한국식 데이터에서 얼마나 떨어지는지 아무도 측정 안 했습니다.**

## 【11】 AI 비서가 왜 실수하는지 밝히기

### 한 줄로
> **"AI가 도구를 5번 연달아 쓰면 왜 무너지는가."**

### 발표에서 제일 센 계산
> AI가 한 번에 잘할 확률이 **90%**라고 합시다. 괜찮아 보이죠.
> 그런데 **5번 연달아** 해야 하면?
> **0.9 × 0.9 × 0.9 × 0.9 × 0.9 = 59%**
>
> **10번 중 4번은 실패합니다.** 사람들은 이걸 모릅니다.

실제 공개 시험(BFCL)에서도 **여러 번 주고받는 경우 점수가 모든 AI에서 5~10점씩 떨어집니다.**

### 뭘 하나
1. 한국 공공 API로 AI가 쓸 도구 20~30개를 만듭니다
2. AI에게 시켜보고 **실패를 종류별로 분류**합니다
3. 각 실패를 고치는 방법을 적용하고 **얼마나 좋아지는지 잽니다**

### 실패 종류 (이걸 밝히는 게 핵심 결과물)
| 종류 | 뜻 |
|---|---|
| 1 | 엉뚱한 도구를 고름 |
| 2 | 값 형식을 틀림 (날짜를 이상하게 씀) |
| 3 | **모르는 값을 물어보지 않고 지어냄** |
| 4 | 앞에서 받은 결과를 까먹음 |
| 5 | 없는 도구를 부름 |
| 6 | 대화가 길어지자 처음 지시를 잊음 |
| 7 | 무한 반복 |

### 장점
API를 진짜로 부르지 않고 **가짜 서버로 처리**하므로 외부 비용이 0입니다.

## 【12】 약 같이 먹으면 위험한 조합 찾기

### 한 줄로
> **"이 약 두 개 같이 먹어도 되나?"**

### 데이터 — 확인이 더 필요합니다
- **식약처 공개 데이터**: 의약품 정보(효능, 주의사항, **상호작용, 부작용**)를 무료 제공

# 3. 뭘 고를까

| 상황 | 추천 |
|---|---|
| **전부 고려한 1등** | **1번** 법 개정 영향 추적 |
| **기술적으로 제일 새롭고 발표에서 튐** | **2번** 낡은 답변 탐지 |
| **"돈 되냐"는 질문을 확실히 통과** | **3번** 입찰 또는 **8번** 계약서 |
| **실패할 확률이 제일 낮음** | **5번** 폐업 예측 또는 **4번** 관리비 |
| **아무도 안 하는 걸로 승부** | **6번** 국회 법안 |
| **AI 기술을 정면으로 보여주고 싶음** | **9번** 형광펜 또는 **10번** 데이터 질문 |

### 제일 추천: 1번 + 2번 합치기
둘은 **같은 데이터(법 개정 기록)** 위에서 돌아가고 만드는 부분도 겹칩니다. 합치면 하나의 제품이 됩니다.

> **"법이 바뀌면 → 우리 문서 중 뭐가 낡았는지 찾아내고 → 뭘 고쳐야 하는지 알려준다"**

- **돈 되나**: 규정 관리 부서에 실제 수요, 아낀 시간을 돈으로 환산 가능
- **기술 있나**: AI 검색 + AI 판단 + 근거 뽑기
- **숫자 나오나**: 과거 기록으로 **사람 손 없이 채점**
- **6명이 나눠 할 수 있나**: 6조각으로 자연스럽게 갈라짐. 비싼 그래픽카드 불필요
