# 0. 7개 전부에 똑같이 적용되는 것

## 0-1. 일정 (하루도 여유 없습니다)

| 언제 | 뭘 하나 | 끝날 때 손에 쥐는 것 |
|---|---|---|
| 9/9 ~ 9/11 (3일) | **되는지 확인** | 데이터 실물 + 비교할 점수 1개. **안 되면 주제 교체** |
| 9/12 ~ 9/18 | **약속 정하고 뼈대 세우기** | 데이터 모양 6개 확정 + 가짜 데이터로 전체 연결 |
| 9/19 ~ 9/25 | 각자 맡은 부분 1차 완성 | **첫 점수** |
| 9/26 ~ 10/2 | 성능 올리기 1차 | 뭐가 안 되는지 분석 |
| 10/3 ~ 10/9 | 성능 올리기 2차 + 화면 완성 | 보여줄 수 있는 상태 |
| 10/10 ~ 10/13 | **코드 잠그기** | 최종 실험 고정, 보고서 작성 |
| 10/14 ~ 10/20 | 발표 준비 | 자료, 연습, 시연 영상 |

## 0-2. 팀 규칙 5개 (이거 안 지키면 마지막 주에 터집니다)

1. **채점하는 코드는 5번 담당자만 만집니다.** 나머지 5명은 보기만 합니다.
   → 점수를 각자 고치면 아무도 그 숫자를 못 믿습니다.

2. **1번 담당자가 첫 3일에 데이터를 파일로 떠서 나눠줍니다.**
   → 6명이 각자 서버에 요청하면 속도도 느리고 결과도 조금씩 달라집니다.

3. **서로 주고받는 건 함수가 아니라 파일로 합니다.**
   → 쉽게 말하면, 옆 사람 코드를 직접 부르지 말고 **"파일에 저장해두면 내가 읽어간다"** 방식입니다.
   → 이러면 옆 사람이 아직 안 끝냈어도 내 작업을 계속할 수 있습니다.

4. **각자 맡은 부분마다 테스트 5개는 사람이 직접 씁니다.** 이건 AI에게 안 맡깁니다.
   → 테스트 = "이걸 넣으면 이게 나와야 한다"를 미리 적어두는 것

5. **매주 금요일에 성적표 칸을 최소 1개 채웁니다.** 못 채우면 그 주는 실패로 기록합니다.

## 0-3. 폴더는 이렇게 나눕니다

```
data/raw/         원본. 절대 건드리지 않음
data/interim/     각자 만든 중간 결과
data/processed/   최종 정리본
schemas/          "데이터 모양" 약속 6개 (첫 주에 정하고 못 박음)
modules/m1~m6/    각자 작업 공간
eval/             채점 코드 (5번만 접근)
reports/          주차별 성적표
```

# 【A】 입찰, 얼마 써야 딸지 알려주기

## 이게 뭔가요

> **"우리 회사가 딸 만한 공고만 골라주고, 얼마를 써야 하는지 알려준다."**

**누가 쓰나**: 정부 일감을 따려는 중소기업, 입찰 대행사, 건설·용역 회사 영업팀

## 무슨 문제를 푸나

나라장터는 정부와 공공기관이 물건을 사거나 공사를 맡길 때 쓰는 사이트입니다. **하루에 수백 건**이 올라옵니다.

| 지금 이렇습니다 | 우리가 이렇게 바꿉니다 |
|---|---|
| 담당자가 수백 건을 눈으로 훑음 | **볼 만한 20건으로 줄여줌** → 시간 몇 % 절약했는지 계산 |
| 얼마 쓸지 경험과 감으로 정함 | **금액을 예측** → 오차 몇 %인지 숫자로 |
| "넣어볼걸" / "괜히 넣었네"를 나중에 앎 | **과거 데이터로 미리 시뮬레이션** |

**발표에서 할 말**
> "작년 공고 ○건에 우리 방식대로 참여했다면, 볼 공고는 ○% 줄고 실제로 딴 비율은 ○%였습니다."

## 데이터 (직접 확인했습니다)

| 뭘 받나 | 어디서 | 뭐가 들어있나 |
|---|---|---|
| 입찰공고 정보 | data.go.kr/data/15129394 | 무슨 일인지, 예상 금액, **자격 제한(면허·지역)** |
| 낙찰 정보 | data.go.kr/data/15129397 | **누가 얼마에 땄는지, 몇 등이었는지** |
| 통합 표준 | data.go.kr/data/15058815 | 입찰·낙찰·계약을 날짜별로 묶어서 |

**3일 안에 반드시 확인할 것**
- [ ] 신청하면 **당일에 승인**되나
- [ ] **공고와 낙찰 결과가 서로 연결되나** ← 이게 이 프로젝트 최대 위험. 안 붙으면 아무것도 못 합니다
- [ ] 최근 1년치 각 5,000건이 받아지나

## 정답지를 어떻게 만드나

| 맞혀야 할 것 | 정답은 어디에 |
|---|---|
| 얼마에 낙찰됐나 | 낙찰 정보에 그대로 있음 |
| 우리 회사가 자격이 되나 | 공고문의 자격 조건 vs 가상 회사 정보 → 규칙으로 정답 만들고 **100건은 사람이 검수** |
| 우리가 1등 했나 | 개찰 순위 1등인지 |

> ⚠️ **꼭 지킬 것**: 학습은 2025년까지, 시험은 2026년 것으로.
> **미래 정보를 슬쩍 쓰면 점수가 잘 나오는데 전부 가짜입니다.**

## 6명이 뭘 맡나

### 1번 — 공고 모으기
- **하는 일**: 공고 데이터 받아서 정리, 중복 제거
- **결과물 예시** (이런 모양의 파일을 만듭니다)
```json
{"공고번호":"20260901-00123-00", "올린날":"2026-09-01", "종류":"용역",
 "제목":"...", "발주처":"○○구청", "예상금액":142000000,
 "지역제한":["서울"], "필요면허":["정보통신공사업"], "마감":"2026-09-10",
 "공고문전체":"..."}
```
- **끝났다고 할 수 있는 기준**: 1년치 5,000건 이상 + 빠진 값이 얼마나 되는지 보고서

### 2번 — 낙찰 결과 모으고 공고와 연결하기
- **하는 일**: 개찰 결과를 받아서 **공고와 짝을 맞춥니다** (이 프로젝트 최대 난관)
```json
{"공고번호":"20260901-00123-00", "개찰일":"2026-09-12", "낙찰자":"○○㈜",
 "낙찰금액":128500000, "낙찰률":0.9049, "참가자수":37}
```
- **끝났다고 할 수 있는 기준**: **90% 이상 짝이 맞음** + 안 맞은 건 왜 안 맞았는지 분류

### 3번 — 공고문 읽고 자격 조건 뽑아내기 (AI 담당 ①)
- **하는 일**: 공고문 글을 AI에게 읽혀서 **표 형태로 정리**합니다
```json
{"필요면허":["정보통신공사업"], "가능지역":["서울","경기"],
 "필요실적":{"금액":50000000,"기간":3}, "중소기업만":true}
```
- **끝났다고 할 수 있는 기준**: 사람이 100건 확인했을 때 **85% 이상 정확**

### 4번 — 우리 회사가 자격 되는지 판정
- **하는 일**: 회사 정보와 자격 조건을 맞춰보고, 안 되면 왜 안 되는지 설명
- **어려운 점**: 면허 이름이 조금씩 다르게 적힙니다 ("정보통신공사업" vs "정보통신공사")
  → 글자가 달라도 **뜻이 같으면 같은 걸로 처리**하는 AI 기술을 씁니다
- **끝났다고 할 수 있는 기준**: 정답 대비 정확도 80% 이상

### 5번 — 금액 예측 + 채점 (이 사람이 성적표 주인)
- **하는 일**: ① 낙찰 금액 예측 ② 딸 확률 예측 ③ **과거 데이터로 시뮬레이션**
- **중요**: 금액을 **하나로 찍지 말고 범위로** 예측합니다
  > "1억 2,850만 원"보다 **"1억 2,600만~1억 3,100만 원일 확률 80%"** 가 실무에서 쓸모 있고 정직합니다
- **끝났다고 할 수 있는 기준**: 단순한 방법(전체 평균으로 찍기)보다 얼마나 나은지 명시

### 6번 — 화면 만들기
- 화면 3개: ① 오늘의 추천 공고 순위 ② 공고 상세(자격 체크리스트 + 권장 금액) ③ 시뮬레이션 성적표
- **끝났다고 할 수 있는 기준**: 진짜 데이터로 3화면 동작, **클릭 3번 안에 근거까지 도달**

## 목표 숫자

| 뭘 재나 | 비교 대상 | 목표 |
|---|---|---|
| 금액 예측 오차 | 그냥 평균으로 찍기 | **3%p 이내** |
| 자격 판별 정확도 | 단어 검색 | **80% 이상** |
| 볼 공고 수 | 전부 다 보기 | **90% 줄이기** |
| 추천 상위 10%의 낙찰 확률 | 아무거나 넣기 | **2.5배 이상** |

## 위험한 점

| 뭐가 위험한가 | 어떻게 대응하나 |
|---|---|
| 공고와 낙찰이 안 붙음 | **3일 안에 판정.** 안 되면 통합 표준 데이터로 갈아탐 |
| 낙찰가에 운이 섞여 있음 | 정확한 금액 맞히기를 포기하고 **범위 예측으로 목표 변경**. "이 부분은 예측 불가"라고 정직하게 보고 |
| 업종마다 너무 다름 | **1개 업종만** (예: 정보통신 용역) 깊게 파기 |

# 【B】 계약서에서 나한테 불리한 조항 찾기

## 이게 뭔가요

> **"받은 계약서를 표준 계약서와 나란히 놓고, 나한테 불리하게 바뀐 조항만 빨갛게 표시한다."**

**누가 쓰나**: 프리랜서, 소상공인, 초기 스타트업, 작가·디자이너 같은 창작자

## 무슨 문제를 푸나

계약서를 **"요약해주는"** 서비스는 많습니다. 그런데 요약을 봐도 불리한지는 모릅니다.

> **왜냐하면 불리한지는 비교를 해야만 알 수 있기 때문입니다.**
> "손해배상은 을이 전액 부담한다"는 조항만 봐서는
> 원래 그런 건지, 이 계약서만 이상한 건지 알 수가 없습니다.
> **표준 계약서와 나란히 놓고 봐야 비로소 "아, 여기만 다르네"가 보입니다.**

**뭘 숫자로 재나**

| 재는 것 | 무슨 뜻인가 |
|---|---|
| 조항 짝 맞추기 정확도 | 표준 제5조와 계약서 제6조가 같은 내용인 걸 알아봤나 |
| 잡아내는 비율 | 진짜 불리한 조항 중 몇 %를 찾았나 |
| 헛짚는 비율 | 멀쩡한 조항을 불리하다고 한 비율 |

## 데이터

| 뭘 쓰나 | 어디서 |
|---|---|
| 공정거래위원회 **표준약관 / 표준계약서** | 공개 |
| 부처별 표준계약서 (문체부 등) | 공개 |
| 관련 법 조문 (약관규제법 등) | 법제처 |
| 공공기관 계약서 양식 | 공개 |

**3일 안에 확인**: 표준계약서 20종 확보 / 조항 자동 쪼개기가 되나 / 실제 계약서 샘플 30건 구할 수 있나

## 정답지를 어떻게 만드나 — **일부러 나쁘게 바꾸기**

표준 계약서를 **의도적으로 불리하게 고쳐서** 정답을 만듭니다.

| 어떻게 | 예시 | 얼마나 나쁜가 |
|---|---|---|
| 권리 삭제 | 해지 통보 유예기간 조항을 지움 | 심각 |
| 기한 늘리기 | 대금 지급 30일 → 90일 | 심각 |
| 책임 떠넘기기 | 손해배상 전액 부담 추가 | 심각 |
| 한도 만들기 | 배상 한도를 계약금 10%로 제한 | 보통 |
| 한쪽만 권한 | 발주자가 마음대로 해지 가능 | 심각 |
| **아무 문제 없는 변경** | 문구만 다듬기, 순서만 바꾸기 | **없음** |

> **마지막 줄이 이 프로젝트의 핵심입니다.**
> 멀쩡한 변경을 섞지 않으면, **"모든 조항을 다 빨갛게 칠하는"** 프로그램도 만점을 받습니다.
> 그건 쓸모없는 프로그램입니다. 멀쩡한 걸 섞어야 진짜 실력이 드러납니다.

## 6명이 뭘 맡나

| 담당 | 하는 일 | 결과물 |
|---|---|---|
| **1번** | 표준계약서 모으고 조항 단위로 쪼개기 | `{"문서id","조항번호","제목","내용"}` |
| **2번** | 위의 6가지 방법으로 일부러 나쁘게 바꾸기 | `{"쌍id","원래조항","바뀐조항","변형종류","심각도"}` |
| **3번** | **표준 조항 ↔ 계약서 조항 짝 맞추기** | `{"표준":"제5조","대상":"제6조","점수":0.93,"상태":"짝있음/없어짐/새로생김"}` |
| **4번** | **AI가 판정**: 불리한가, 어느 방향으로, 얼마나 | `{"판정":"불리함","심각도":"상","근거":"지급기한 30→90일","관련법":"하도급법 제13조"}` |
| **5번** | 채점 | 짝맞추기 정확도, 잡아낸 비율, 헛짚은 비율 |
| **6번** | 화면: 나란히 비교 + 위험도 색깔 + 근거 법 링크 + 협상 문구 제안 | 시연용 |

## 3번 담당이 하는 일이 왜 어려운가 (기술 포인트)

> 계약서는 **조항 순서가 바뀌고 번호가 어긋납니다.**
> 표준 제5조가 계약서에서는 제6조일 수도, 제4조일 수도 있습니다.
>
> 이때 **"제일 비슷한 것부터 하나씩 짝지어 나가면"** 큰일 납니다.
> 앞에서 하나 잘못 붙이면 **뒤가 줄줄이 밀립니다.**
>
> 그래서 **전체를 한 번에 놓고 "가장 좋은 조합"을 찾는 방법**을 씁니다.
> 마치 6명이 6개 자리에 앉을 때, 한 명씩 정하지 말고 **전체 만족도가 최대가 되는 배치를 한 번에 계산**하는 것과 같습니다.
> 이런 계산법이 이미 있습니다(헝가리안 알고리즘). 파이썬 한 줄로 씁니다.

## 목표 숫자

| 뭘 재나 | 목표 |
|---|---|
| 조항 짝 맞추기 정확도 | **90% 이상** |
| 불리한 조항 잡아내는 비율 | **80% 이상** |
| 멀쩡한 걸 불리하다고 하는 비율 | **15% 이하** |

# 【C】 우리 아파트 관리비, 바가지인가

**누가 쓰나**: 입주자대표회의, 일반 입주민, 지자체 감사 담당

## 무슨 문제를 푸나

관리비는 항목별로 전부 공개됩니다. 그런데 **비교 기준이 없어서 봐도 모릅니다.**

## 이 프로젝트의 진짜 기술은 여기 있습니다

**"비슷한 아파트끼리 묶기"가 기술의 절반입니다.**

> 그냥 "6개월 안에 망할까? 예/아니오"만 맞히면 정보를 버리게 됩니다.
>

> - 3년째 영업 중인 가게
> - 3개월째 영업 중인 가게
>

>
> **생존분석**은 이런 걸 제대로 다루는 방법입니다.
> "언제쯤 망하나"까지 답하고, **지금까지 버틴 기간 자체를 정보로 씁니다.**
> 원래 의학에서 "이 환자가 얼마나 오래 사시나"를 계산하려고 만든 방법인데, 가게 수명에도 그대로 씁니다.

## 5번 담당: 확률이 진짜 맞는지 반드시 확인

> 순위는 잘 매기는데 확률값이 엉터리인 모델이 흔합니다.
> (위험한 가게를 위로 잘 올리긴 하는데, "70%"라고 한 게 실제론 30%인 경우)
>
> 이걸 검증해서 넣으면 **완성도가 확 올라갑니다.** 대부분의 팀은 이걸 안 합니다.

# 【E】 AI 답변에서 거짓말 부분 표시하기

> 비싼 AI보다 정확하고 100배 싸게."**

## 무슨 문제를 푸나

AI에게 문서를 주고 "이거 보고 답해"라고 해도 **문서에 없는 내용을 지어낸 문장이 섞입니다.**

지금 이걸 거르는 방법은 두 가지뿐인데 둘 다 문제입니다:

| 방법 | 문제 |
|---|---|
| 사람이 검수 | 느리고 비쌈. 실시간 서비스엔 못 씀 |
| 비싼 AI에게 "이거 맞아?" 물어보기 | **정확도도 생각보다 낮고** 돈이 많이 듦 |

## 이미 증명된 숫자 (외국 연구, 우리도 따라할 수 있음)

공개 시험 RAGTruth (문제 18,000개, 연습용 15,090 / 시험용 2,700):

| 방법 | 모델 크기 | 점수 |
|---|---|---|
| GPT-4에게 물어보기 | – | **63.4점** |
| 예전 최고 방식 | – | 65.4점 |
| 130억짜리 모델 학습 | 130억 | 78.7점 |
| **4억짜리 작은 모델** | **4억** | **79.2점** |
| 80억짜리 모델 학습 | 80억 | 83.9점 |

> **4억짜리가 130억짜리를 이겼습니다.** 30배 작은데 더 정확합니다.
> 속도도 그래픽카드 1장으로 **초당 30~60건** 처리합니다.

비용도 비슷한 연구(MiniCheck)에서:

| 항목 | 숫자 |
|---|---|
| 7.7억짜리 작은 모델 정확도 | 74.7점 |
| GPT-4 | 75.3점 (**차이 0.6점**) |
| **1만 3천 건 검사 비용** | **$0.24 vs $107 — 약 400배 차이** |

**한국어에는 이런 도구가 없습니다.** 시험지(K-HALU, K-FinHallu)는 있는데 도구가 없습니다.

## 4주에 맞는 현실적인 방법 — 3단계로 거르기

큰 모델을 학습시키려 하지 말고, **비용이 다른 3가지 방법을 단계로 씁니다.**

```
문장 하나가 들어오면

1단계 (공짜, 즉시)
  "이 문장의 숫자·날짜·조문번호가 원문에 진짜 있나?"
  없으면 → 바로 "근거 없음" 판정. 끝.

2단계 (거의 공짜, 0.005초)
  "이 문장이 원문 어딘가와 뜻이 아주 비슷한가?"
  아주 비슷하면 → 바로 "근거 있음" 판정. 끝.

3단계 (돈 듦)
  앞에서 못 정한 애매한 것만 AI에게 물어보기
```

> **성과 = "AI 호출을 100%에서 30%로 줄이면서 정확도는 유지했다."**
> 1·2단계 기준선을 조절해가며 **"돈을 얼마나 쓰면 정확도가 얼마나 나오는지" 곡선을 그리는 게** 이 프로젝트의 결과물입니다.

## 큰 발견: 필요한 기능이 이미 API에 있습니다

Claude API에는 **인용(Citations) 기능**이 있습니다.
문서를 주면서 이 기능을 켜면, **답변의 어느 부분이 문서의 몇 번째 글자에서 나왔는지**를 알려줍니다.

> **반대로 말하면, 인용이 안 붙은 부분이 곧 "근거 없이 지어낸 부분" 후보입니다.**
>
> 이걸 직접 만들려면 몇 주가 걸리는데, **API가 그냥 해줍니다.**
> 덕분에 4주 안에 들어옵니다.

# 【F】 한국어로 물으면 데이터 찾아주기

## 이게 뭔가요

> **"작년 3분기 강남구 인구 알려줘" → 프로그램이 알아서 데이터를 찾아 답한다.**

## 왜 이 주제가 채점에서 강한가

> **컴퓨터가 직접 채점합니다.**
>
> AI가 만든 데이터 조회 명령어를 **실제로 실행해서**, 결과가 정답과 같으면 맞은 겁니다.
> **AI 심판도, 사람 채점도 필요 없습니다.**
>
> "그 점수 어떻게 믿냐"는 질문이 **원천 차단됩니다.** 발표할 때 가장 편한 조건입니다.

## 이미 나와 있는 숫자

공개 시험 BIRD: **질문 12,751개, 데이터베이스 95개, 분야 37개**

| 누가 | 정확도 |
|---|---|
| **사람** | **92.96%** |
| 현재 1위 AI | **80.04%** |
| 유명 AI들 | 약 70% |

> **최고 AI도 사람보다 13%p 못 합니다. 아직 안 풀린 문제입니다.**
> **그리고 이 숫자는 전부 영어 기준입니다.**

## 우리가 채우는 빈칸 — 한국식 데이터의 어려움

| 뭐가 어려운가 | 예 |
|---|---|
| 한글로 된 항목 이름 | `주민등록인구`, `자치구코드` |
| 회계연도 vs 달력 | "작년 3분기"가 회사 기준인가 달력 기준인가 |
| 행정구역 계층 | 시도-시군구-읍면동, 코드 체계가 여러 개 |
| 한글 값 맞추기 | "강남" vs "강남구" |
| 한국어 어순 | "매출이 가장 높은" vs "가장 높은 매출의" |

**한국식에서 얼마나 떨어지는지 아무도 측정 안 했습니다.**

## 데이터

공공데이터포털에서 **표로 정리할 수 있는 데이터 3~5개**를 골라 실제 데이터베이스로 만듭니다.
예: 인구·행정구역 / 상가업소 / 아파트 실거래 / 공공기관 예산 / 교통카드 통계

질문은 팀이 직접 만들되 **난이도를 3단계**로 나눕니다:
1단계 단순 집계 → 2단계 여러 표 합치기 → 3단계 복잡한 계산

## 6명이 뭘 맡나

| 담당 | 하는 일 |
|---|---|
| **1번** | 공공데이터를 실제 데이터베이스로 만들기 + 항목 설명 문서화 |
| **2번** | **질문 500~800개 + 정답 명령어 작성** (난이도 표시) ← 시간이 제일 많이 듦 |
| **3번** | **채점 장치**: 안전한 공간에서 실행 → 결과 비교 → 오류 분류 |
| **4번** | **질문에 필요한 표·항목만 골라주기** |
| **5번** | **명령어 생성 + 스스로 고치기 루프** |
| **6번** | 오류 유형 분석 + 질문 콘솔 화면 |

## 4번 담당이 왜 중요한가 (성능의 절반)

> 표가 50개 있는데 **전부 다 AI에게 보여주면 AI가 헷갈립니다.**
> 사람도 마찬가지입니다. 서류 50장을 던져주고 "여기서 찾아" 하면 오래 걸립니다.
>
> **관련 있는 표 3~5개만 골라서 주면** 정확도가 크게 오릅니다.
> 이게 4번 담당의 일이고, **이 프로젝트에서 검색 AI가 들어가는 자리**입니다.

## 5번 담당: "스스로 고치기" 가 이 프로젝트의 기술 포인트

```
AI가 명령어를 만듦
   → 문법이 맞나 검사 (실행 전에 미리)
   → 실제로 실행
   → 에러가 났거나 결과가 텅 비었으면?
   → 에러 메시지를 그대로 AI에게 다시 주면서 "이거 고쳐" (최대 3번)
```

> 아이디어는 단순한데 **실제로 정확도가 붙습니다.**
> 그리고 **"한 번에 만든 것" vs "3번 고친 것"의 차이를 따로 잴 수 있어서** 발표 자료가 하나 더 생깁니다.

## 4주 안에 넣을 순서 (효과가 큰 것부터)

1. **표 골라주기** (효과 가장 큼)
2. **실행해보고 스스로 고치기**
3. 비슷한 질문의 정답을 예시로 같이 보여주기
4. 여러 개 만들어서 다수결 — 비용이 배로 드니 마지막

## 목표 숫자

| 뭘 재나 | 비교 대상 | 목표 |
|---|---|---|
| 정확도 | AI에게 그냥 시키기 | **10%p 이상 향상** |
| 난이도별 정확도 | – | 3단계 표 |
| **영어 대비 얼마나 떨어지나** | 같은 질문의 영어판 | **숫자로 측정 (핵심 발견)** |
| 표 골라주기 정확도 | – | 90% 이상 |
| 스스로 고치기의 효과 | 한 번에 만들기 | **몇 %p인지 따로 측정** |

## 위험한 점

| 뭐가 위험한가 | 어떻게 대응하나 |
|---|---|
| **정답 명령어 만드는 데 시간이 오래 걸림** | 1~2주차에 **2명 투입**. 500개 못 채우면 300개로 낮춤 |
| 결과 비교 기준이 애매함 (순서, 중복) | 채점 규칙을 첫 주에 문서로 고정 |
| 데이터베이스 만드는 게 늦어짐 | 3일 안에 데이터 1개로 끝까지 해보고 시간 재기 |

# 【G】 AI 비서가 왜 실수하는지 밝히기

## 이게 뭔가요

> **"AI가 도구를 5번 연달아 쓰면 왜 무너지는가. 원인을 종류별로 밝히고 고친다."**

## 발표에서 제일 센 계산

> AI가 한 번 잘할 확률이 **90%**라고 합시다. 괜찮아 보이죠.
> 그런데 **5번 연달아** 성공해야 하면?
>
> **0.9 × 0.9 × 0.9 × 0.9 × 0.9 = 59%**
>
> **10번 중 4번은 실패합니다.**
> 사람들은 "정확도 90%"만 보고 이걸 모릅니다.

실제 공개 시험(BFCL) 결과도 같은 얘기를 합니다:
- **여러 번 주고받는 경우 점수가 모든 AI에서 5~10점씩 떨어짐**
- 5번 이상 연달아 하면 **그 점수가 계속 곱해짐**
- 비싼 AI와 무료 AI의 차이는 **3~4점**까지 좁혀짐

## 우리가 채우는 빈칸

공개 시험은 **영어 + 해외 서비스 기준**입니다.
**한국 공공 API와 한국어 대화로 만든 시험지는 없습니다.**

## 6명이 뭘 맡나

| 담당 | 하는 일 |
|---|---|
| **1번** | 공공 API 20~30개를 AI가 쓸 수 있는 도구로 정의 (+**일부러 설명을 부실하게 만든 버전**도) |
| **2번** | 한국어 대화 시나리오 300개 + 정답 순서 (30개는 손으로 정밀하게) |
| **3번** | **가짜 서버 + AI 실행 장치** (진짜 API는 안 부름) |
| **4번** | **실패를 종류별로 자동 분류** |
| **5번** | **고치는 방법 4가지를 각각 적용해서 효과 측정** |
| **6번** | 결과 화면: 감쇠 곡선, 실패 종류 분포, 전후 비교 |

## 실패 종류 (이걸 밝히는 게 핵심 결과물)

| 번호 | 뭘 틀렸나 | 어떻게 고치나 |
|---|---|---|
| 1 | 엉뚱한 도구를 고름 | 도구 설명을 다시 씀 |
| 2 | 값 형식을 틀림 (날짜를 이상하게) | **형식을 강제하는 기능 켜기** |
| 3 | **모르는 값을 안 물어보고 지어냄** | 지시문 + 검증 단계 추가 |
| 4 | 앞에서 받은 결과를 까먹음 | 지금까지 상황을 요약해서 다시 넣어주기 |
| 5 | 없는 도구를 부름 | 목록에 없으면 거부 |
| 6 | 대화가 길어지자 처음 지시를 잊음 | 중간에 다시 알려주기 |
| 7 | 무한 반복 | 횟수 상한 |

## 3번 담당이 알아야 할 것

> **AI 개발 도구 중에 "이 반복 작업을 알아서 해주는" 편리한 기능이 있습니다.**
> **그런데 우리는 일부러 안 씁니다.**
>
> 왜냐하면 **우리 목적이 "실패를 관찰하는 것"이기 때문입니다.**
> 편리한 도구는 실패를 알아서 처리해버려서 **우리가 봐야 할 걸 감춥니다.**
> 그래서 반복 과정을 직접 만들어서 **모든 단계를 기록**합니다.

## 꼭 지킬 세부사항 3개

1. **AI가 한 번에 도구를 여러 개 부를 수 있습니다.**
   → 결과를 돌려줄 때 **하나의 메시지에 전부 담아서** 보내야 합니다.
   나눠 보내면 AI가 "아, 여러 개 부르면 안 되는구나"라고 학습해서 다음부터 하나씩만 부릅니다.

2. **실패한 도구도 "실패했다"고 반드시 돌려줍니다.** 빠뜨리면 대화가 깨집니다.

3. **AI가 준 값은 반드시 정식으로 해석해서 읽습니다.** 글자를 직접 잘라 쓰면 깨집니다.
