# 어떤 AI 기술을 어디에 쓰는가 (쉬운 설명판)

대상: 프로젝트 A~G 7개 + 나머지 후보 5개 · 2026년 9월 9일 ~ 10월 20일 · 6명

> **이 문서의 목적**
> **"그래서 AI는 어디에 쓰는 건데요?"** 라는 질문에 **담당자별로** 답할 수 있게 하는 것.
> 어려운 말은 나올 때마다 바로 옆에 쉬운 설명을 붙였습니다.

---

# 0. 먼저 — AI를 어디에 쓰고 어디에 안 쓰는가

## 이것만 기억하면 됩니다

| 이런 일은 | 이걸로 |
|---|---|
| **숫자를 예측하는 일** (낙찰가, 폐업 확률, 관리비 이상치) | **AI 챗봇 말고 전통적인 예측 프로그램** |
| **글을 표로 바꾸는 일** (공고문 → 자격 조건 표) | **AI 챗봇** |
| **판단하고 이유를 설명하는 일** (이 조항이 불리한가) | **AI 챗봇** |
| **비슷한 걸 찾는 일** (비슷한 문장, 비슷한 아파트) | **AI 검색 기술** |

> **가장 흔한 실수: 숫자 예측을 AI 챗봇에게 시키는 것.**
> "이 공고 낙찰가 얼마일 것 같아?"라고 물으면 AI는 그럴듯한 숫자를 말합니다.
> 그런데 **틀립니다.** 이런 건 통계·수학 프로그램이 훨씬 정확하고, 싸고, 빠릅니다.
> AI 챗봇은 **글을 다루는 자리**에만 씁니다.

# 1. AI 챗봇 (Claude) — 3종류를 골라 씁니다

## 1-1. 어느 걸 언제 쓰나

똑같은 회사에서 나온 AI인데 **똑똑한 정도와 가격이 다릅니다.**
비유하면 **경력 20년 전문가 / 경력 5년 직원 / 신입사원** 같은 겁니다.
신입에게 시켜도 되는 일을 전문가에게 시키면 돈만 나갑니다.

| 이름 | 부를 때 쓰는 이름 | 100만 글자 넣을 때 | 100만 글자 받을 때 | 어디에 쓰나 |
|---|---|---|---|---|
| **Claude Opus 5** | `claude-opus-5` | $5.00 | $25.00 | **판단이 필요한 자리** (계약서 불리한지 판정, 법 영향 분석) |
| **Claude Sonnet 5** | `claude-sonnet-5` | $2.00 | $10.00 | 중간 난이도 대량 작업 (공고문에서 조건 뽑기) |
| **Claude Haiku 4.5** | `claude-haiku-4-5` | $1.00 | $5.00 | **단순 반복 대량 작업** (연습문제 만들기, 분류) |

> 가격은 2026년 6월 기준입니다. **9월 9~11일에 anthropic.com/pricing 에서 다시 확인**하세요.
>
> **원칙**: 결과 점수를 좌우하는 자리에만 비싼 걸 쓰고, 나머지는 전부 싼 걸로.
> **데이터 만드는 작업은 거의 전부 제일 싼 걸로 충분합니다.**

## 1-2. 돈을 3~10배 아끼는 기능 4개 (반드시 씁니다)

### ① 묶어서 보내기 (Batch API) — **가격 절반**

> **쉽게 말하면 "급하지 않으니까 천천히 해주세요" 하고 한꺼번에 맡기는 겁니다.**
> 택배로 치면 당일배송 대신 일반배송을 고르는 것과 같습니다. 대신 **값이 절반**입니다.
>
> 3,000개를 하나씩 보내면 비싸고, 3,000개를 한 번에 묶어 맡기면 반값입니다.
> 실시간으로 답이 필요한 게 아니라면 **무조건 이걸 씁니다.**

```python
# 3,000건을 한 번에 맡기기
batch = client.messages.batches.create(requests=[
    {"custom_id": f"item-{i}", "params": {...}} for i in range(3000)
])
# 다 됐는지 가끔 확인 → 끝나면 결과 받기
```

> ⚠️ **주의**: 결과가 **넣은 순서대로 안 옵니다.**
> 그래서 각 건마다 이름표(`custom_id`)를 붙여두고, **순서가 아니라 이름표로 찾아야** 합니다.

### ② 앞부분 기억시키기 (Prompt Caching) — 반복 비용 절감

> **매번 똑같은 자료를 다시 보내는 게 돈 낭비입니다.**
>
> 비유하면 이렇습니다. 변호사에게 상담할 때마다
> **"제 계약서 전문을 다시 읽어드릴게요"** 하고 100장을 매번 읽어주면
> 그 시간만큼 상담료가 나갑니다.
> 대신 **"지난번 그 계약서 기억하시죠? 이번 질문은요..."** 라고 하면 훨씬 쌉니다.
>
> AI도 똑같습니다. 법 조문 100개, 데이터 항목 설명 같은 건 **매번 똑같이 들어갑니다.**
> 이걸 "기억해둬"라고 표시하면 두 번째부터 훨씬 쌉니다.

**규칙 2개**
1. **안 바뀌는 걸 앞에, 매번 바뀌는 걸(질문, 시간) 뒤에** 놓습니다.
2. **앞부분이 한 글자라도 바뀌면 기억이 통째로 날아갑니다.** (예: 프롬프트에 현재 시각을 넣으면 매번 새로 시작)

**확인법**: 답변에 딸려오는 `usage.cache_read_input_tokens` 값이 **0이면 기억이 안 걸린 겁니다.** 반드시 확인하세요.

### ③ 답 모양 강제하기 (Structured Outputs) — 파싱 실패 0으로

> **AI에게 "표로 정리해줘"라고 하면 매번 조금씩 다르게 씁니다.**
> 어떨 땐 "면허: 정보통신공사업", 어떨 땐 "필요한 면허는 정보통신공사업입니다".
> 그러면 그걸 읽어들이는 코드가 계속 깨집니다.
>
> **답의 모양을 미리 정해서 강제**하면 이 문제가 사라집니다.
> **글에서 정보를 뽑는 작업은 전부 이걸로 합니다.** 자유롭게 쓴 글을 잘라 읽으려 하지 마세요.

### ④ 인용 표시 (Citations) — **어디서 나온 말인지 자동 표시**

> 문서를 주면서 이 기능을 켜면, AI가 답할 때
> **"이 문장은 당신이 준 문서의 1,203번째 글자부터 1,340번째 글자에서 나왔습니다"** 라고 알려줍니다.
>
> **반대로 말하면, 아무 데서도 안 나온 문장 = 지어낸 문장입니다.**
>
> **프로젝트 E(거짓말 형광펜)의 핵심 기능이 API에 이미 들어 있습니다.**
> 직접 만들면 몇 주 걸릴 걸 그냥 켜면 됩니다.

> ⚠️ 주의: ③번(답 모양 강제)과 ④번(인용)은 **같이 못 씁니다.** 오류가 납니다.

## 1-3. 생각 깊이 조절하기

```python
client.messages.create(
    model="claude-opus-5",
    thinking={"type": "adaptive"},        # "필요한 만큼 알아서 생각해"
    output_config={"effort": "medium"},   # 얼마나 공들일지: low / medium / high / xhigh / max
    max_tokens=16000,
    messages=[...],
)
```

> **`effort`가 돈과 품질을 조절하는 다이얼입니다.**
> - **판단이 중요한 작업**: `high` 또는 `xhigh`
> - **단순 대량 작업**: `low` 또는 `medium` ← **여기서 돈이 크게 갈립니다**
>
> 긴 답을 받을 땐 `.stream()` 방식을 씁니다. 안 그러면 기다리다 끊깁니다.

> ⚠️ **옛날 방식은 오류가 납니다.** `budget_tokens`, `output_format`, "AI 답변 첫 문장 미리 써주기"는
> 지금 모델에서 **에러**가 납니다. 인터넷에서 옛날 예제를 보고 따라하면 안 됩니다.

# 2. AI 검색 기술 — "비슷한 걸 찾기"

## 2-1. 이게 뭔가요 (제일 중요한 개념)

> **컴퓨터는 글자가 다르면 다른 거라고 생각합니다.**
> "정보통신공사업"과 "정보통신공사"는 컴퓨터에겐 완전히 다른 단어입니다.
>
> **임베딩**이라는 기술은 **글의 뜻을 숫자 좌표로 바꿉니다.**
>
> 비유하면 이렇습니다.
> 세상의 모든 문장을 아주 넓은 지도 위의 점으로 찍는다고 상상해보세요.
> **뜻이 비슷한 문장은 지도에서 가까운 곳에 찍힙니다.**
> - "밥 먹었어?" 와 "식사하셨나요?" → 아주 가까움
> - "밥 먹었어?" 와 "주식 시장 전망" → 아주 멂
>
> 그러면 **"비슷한 문장 찾기"가 "지도에서 가까운 점 찾기"** 가 됩니다. 컴퓨터가 잘하는 일이죠.

## 2-2. 뭘 쓰나

| 용도 | 1순위 | 왜 |
|---|---|---|
| 한국어 문장을 좌표로 | **BGE-M3** | 70개 이상 언어 지원, 한국어 성능 좋음 |
| 한국어 특화가 필요하면 | **KURE** | 고려대에서 BGE-M3를 한국어로 더 훈련시킨 것. 한국어 검색 순위표도 같이 공개 |
| 다시 순위 매기기 | bge-reranker-v2-m3 계열 | 후보를 추린 뒤 정밀하게 재정렬 |
| 단어 그대로 찾기 | BM25 + 한국어 형태소 분석기(kiwipiepy) | 아래 설명 참고 |
| 좌표 저장·검색 | FAISS | 4주 프로젝트엔 이게 제일 빠름 |

## 2-3. 두 가지를 섞어 씁니다 (중요)

> **"뜻으로 찾기"만 쓰면 문제가 생깁니다.**
> "제750조"를 찾는데, 뜻으로만 찾으면 "제751조"도 비슷하다고 가져옵니다. **숫자를 놓칩니다.**
>
> **"단어 그대로 찾기"만 써도 문제가 생깁니다.**
> "해지"를 찾는데 문서엔 "계약 종료"라고 써 있으면 못 찾습니다. **뜻을 놓칩니다.**
>
> **그래서 둘 다 돌려서 결과를 합칩니다.** 이게 기본입니다.
> 합치는 방법 중 제일 간단하고 효과 좋은 게 **RRF**인데, 쉽게 말하면
> **"두 방법에서 각각 몇 등 했는지를 점수로 바꿔서 더하는 것"** 입니다.

> ⚠️ **한국어는 형태소 분석이 필수입니다.**
> 영어는 띄어쓰기로 단어가 나뉘는데, 한국어는 "먹었습니다"에서 "먹다"를 뽑아내야 합니다.
> 이걸 안 하면 단어 검색 성능이 확 떨어집니다.

# 3. 숫자 예측 기술 — AI 챗봇으로 하면 안 되는 것

| 하고 싶은 일 | 쓰는 도구 | 쉬운 설명 |
|---|---|---|
| 표 데이터로 예측 | LightGBM, XGBoost | **스무고개를 수천 번 하는 방식.** "세대수 500 이상인가? 예/아니오" 같은 질문을 수천 개 조합해서 답을 냅니다. 표 형태 데이터에서는 이게 AI 챗봇보다 훨씬 정확합니다 |
| **언제 망할지** 예측 | lifelines, scikit-survival | **원래 의학에서 "이 환자가 얼마나 사시나"를 계산하려고 만든 방법.** 가게 수명에도 그대로 씁니다 |
| 이상한 값 찾기 | 중앙값 기반 계산 | 아래 설명 참고 |
| 갑자기 변한 시점 찾기 | ruptures | "언제부터 이상해졌나"를 자동으로 찾아줍니다 |
| 최적의 짝 맞추기 | scipy의 `linear_sum_assignment` | 아래 설명 참고 |
| 주변에 뭐가 있나 빠르게 찾기 | scipy의 cKDTree | 지도에서 "반경 300m 안" 계산을 빠르게 |
| 왜 그렇게 판단했나 설명 | SHAP | "이 가게가 위험한 건 주변 폐업률이 높아서가 60%, 영업기간이 짧아서가 30%" 식으로 분해 |

## 3-1. "평균 대신 중앙값" — 왜 중요한가

> 관리비 데이터에 이런 게 섞여 있다고 합시다.
> **10만, 11만, 12만, 10만, 9만, 그리고 900만 (입력 실수)**
>
> **평균을 내면 158만 원**입니다. 실제로는 다들 10만 원대인데요.
> 그러면 "158만 원이 정상"이 되어버려서, **진짜 이상한 값을 못 찾습니다.**
> **이상한 값 하나가 다른 이상한 값을 숨겨버리는 겁니다.**
>
> **중앙값**(줄 세웠을 때 한가운데)을 쓰면 **10만 5천 원**입니다. 극단값에 안 흔들립니다.
> 그래서 이상치를 찾을 땐 항상 중앙값 기준으로 계산합니다.

## 3-2. "최적의 짝 맞추기" — 왜 필요한가

> 표준 계약서 20개 조항과, 받은 계약서 22개 조항을 짝지어야 합니다.
> 순서도 다르고 번호도 어긋나 있습니다.
>
> **나쁜 방법**: 제일 비슷한 것부터 하나씩 붙여나가기
> → 앞에서 하나 잘못 붙이면 **뒤가 줄줄이 밀립니다.**
>
> **좋은 방법**: 전체를 한 번에 놓고 **"전체 만족도가 최대가 되는 조합"** 을 찾기
> → 6명이 6개 자리에 앉을 때, 한 명씩 정하지 말고 **전체가 제일 만족하는 배치를 한 번에 계산**하는 것과 같습니다.
> → 이런 계산법이 이미 있습니다. 파이썬 한 줄이면 됩니다.

# 5. 프로젝트별 — 담당자별로 AI를 어디에 쓰나

---

## 【A】 입찰 낙찰 예측

| 담당 | AI 쓰나 | 뭘 쓰나 |
|---|---|---|
| 1번 공고 수집 | ✗ | 데이터 정리만 |
| 2번 낙찰 매칭 | ✗ | 글자 비교 규칙 |
| **3번 요건 추출** | **○ AI 챗봇** | Sonnet 5 + **답 모양 강제.** 공고문 글 → 조건 표 |
| **4번 자격 판별** | **○ AI 검색** | 면허 이름이 조금 달라도 뜻이 같으면 같다고 처리 |
| **5번 금액 예측** | **○ 숫자 예측** | LightGBM. **하나로 찍지 말고 범위로** |
| 6번 화면 | △ | 추천 이유 문장 (제일 싼 모델) |

### 5번이 "범위로 예측"하는 이유

> 낙찰가에는 **추첨 요소가 섞여 있습니다.**
> 그래서 정확히 맞히는 건 애초에 불가능합니다.
>
> "1억 2,850만 원"이라고 딱 찍으면 거의 항상 틀립니다.
> **"1억 2,600만~1억 3,100만 원 사이일 확률 80%"** 라고 하면
> 실무에서 쓸 수 있고, 채점도 정직합니다.

### 예상 AI 비용

| **4번 3단계 판정** | **○ 인용 기능 + AI 챗봇** | **인용 안 붙은 부분 = 지어낸 부분 후보** |

### 이 프로젝트의 기술 카드 3개

**① 인용 기능이 곧 형광펜입니다**
> 앞에서 설명한 Citations 기능을 켜면 **어느 문장이 원문 몇 번째 글자에서 나왔는지** 알려줍니다.
> **인용이 안 붙은 구간이 곧 지어낸 구간 후보**입니다.
> 이걸 직접 만들려면 몇 주 걸립니다. 4주 안에 들어오는 이유가 이겁니다.

**② 3단계로 걸러서 돈을 줄입니다**
```
문장 → 1단계 규칙:   숫자가 원문에 없음 → 바로 "거짓" 판정   (공짜, 즉시)
     → 2단계 뜻비교: 원문과 아주 비슷함 → 바로 "진짜" 판정   (거의 공짜, 0.005초)
     → 3단계 AI:     애매한 것만 물어보기                    (돈 듦)
```
> **성과 = "AI 호출을 100% → 30%로 줄이면서 정확도 유지"**
> 1·2단계 기준선을 움직여가며 **"돈 vs 정확도" 곡선**을 그리는 게 결과물입니다.

**③ 따라잡을 목표가 명확합니다**
| 비교 대상 | 공개 점수 |
|---|---|
| GPT-4에게 물어보기 | 63.4점 |
| 4억짜리 작은 모델 | 79.2점 |
| 작은 모델 vs GPT-4 비용 | **$0.24 vs $107 (400배)** |
