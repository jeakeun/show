# 학습노트 2-1 · 첫 골격 (2026-10-23)

## 오늘 한 것

1. 에이전트 흐름 전체를 LangGraph로 만들었다: 공고 분석 → 요구 항목별 병렬 검색 → 적합도 계산 → 작성 → 검증 → 사람 확정 → 저장.
2. 실제 모델 대신 **가짜 모델**로 흐름 전체를 테스트했다. 테스트 15개가 통과했다. API 키도 비용도 필요 없다.
3. 테스트가 **진짜 버그**를 하나 잡았고, 시험 실행에서 **검색의 약점**을 하나 발견했다 (아래).

실제 모델로는 아직 돌리지 않았다. 메인 PC에서 처음 돌릴 때 결과와 비용을 이 노트에 추가한다.

## 파일과 역할 (01 개념 문서의 패턴과 연결)

| 칸 | 파일 | 패턴 |
|---|---|---|
| 공고 분석가 | `graph.py` analyze → `llm.py` analyze | 맥락 분리 (공고만 봄) |
| 근거 검색가 × N | `graph.py` fan_out · retrieve → `career.py` | **오케스트레이터** (항목 수만큼 실행 중에 나눔), 읽기라 병렬 안전 |
| 적합도 계산 | `scoring.py` | 숫자는 코드가 (ADR-04) |
| 작성자 1명 | `graph.py` write → `llm.py` write | 쓰기는 한 곳 |
| 검증가 | `citations.py`(코드) → `llm.py` verify(AI) | **평가자-최적화자** (지적만, 고치는 건 작성자) |
| 사람 확정 | `graph.py` confirm (`interrupt`) | Human-in-the-loop |
| 저장 | `graph.py` save | 승인 뒤에만 파일을 씀 |

## 왜 이렇게 했나 (면접에서 설명할 것)

1. **모델 호출과 흐름을 나눴다.** `llm.py`(진짜 모델)와 `fake.py`(가짜 모델)가 같은 함수를 갖고 있어서, 그래프에 아무거나 끼울 수 있다.
   그래서 API 키 없이 흐름을 테스트하고, 나중에 모델을 바꿔도 그래프는 그대로다.
2. **검증은 싼 것부터 한다.** 근거 번호가 있는지는 코드가 먼저 공짜로 본다. 통과해야 AI 검증을 부른다. 돈이 드는 검사를 줄인다.
3. **승인 전에는 아무것도 저장하지 않는다.** 저장을 확정 노드 다음 노드에 따로 뒀다.
   LangGraph는 재개할 때 멈췄던 노드를 처음부터 다시 실행해서, 확정 노드 안에서 저장하면 두 번 저장될 수 있기 때문이다.
4. **처음엔 모든 역할에 같은 모델**을 쓰고 생각 강도만 다르게 했다. 싼 모델로 바꿀지는 평가셋으로 재고 정한다.

## 테스트가 잡은 버그

근거 번호 검사기가 "5. 직접 짠 것 vs LangGraph"의 **"5."를 한 문장으로 잘라서** "근거 번호 없음"으로 판정했다.
그 결과 멀쩡한 초안을 계속 다시 쓰게 만들었다 (테스트 3개 실패).
실제 AI 초안에도 "1. …" 같은 번호 목록이 나오니, 실제로 돌렸으면 비용만 쓰고 계속 다시 썼을 것이다.

- **고친 법**: 문장 끝은 **한글 바로 뒤의 마침표**만 보고, 줄 앞의 "1.", "2)" 같은 목록 번호는 떼고 검사한다.
- **교훈**: 가짜 모델로 흐름을 먼저 테스트한 덕에, 돈 들기 전에 잡았다.

## 시험 실행에서 발견한 것

공고는 **"Python", "AI Agent"** 인데, 운영 경험 문서에는 **"파이썬", "에이전트"** 라고 쓰여 있다.
그래서 키워드 검색이 둘을 잇지 못하고, 실제로 운영한 경험인데도 "학습 근거"나 "근거 없음"으로 판정했다.

- 2교시에서 배운 그대로다. **키워드 검색은 같은 단어만 찾는다.** 뜻이 같아도 표기가 다르면 못 찾는다.
- 다음 단계(2-2)에서 동의어 사전 또는 뜻 검색(임베딩)을 섞고, 평가셋으로 얼마나 나아지는지 잰다.

## 새 용어

| 용어 | 한 줄 뜻 | 비유 |
|---|---|---|
| **가짜 모델 (fake)** | 진짜 AI 대신 정해진 답을 돌려주는 시험용 부품 | 연습용 마네킹 |
| **테스트 (pytest)** | 코드가 기대대로 도는지 자동으로 확인하는 작은 프로그램들 | 시험지 자동 채점 |
| **구조화된 출력** | AI 답을 정해진 JSON 모양으로만 받는 기능. 형식이 깨지지 않음 | 빈칸 채우기 양식 |
| **생각 강도 (effort)** | AI가 얼마나 깊게 생각할지. 높을수록 정확하지만 비쌈 | 시험 문제에 쓰는 시간 |
| **fallbacks** | 안전 장치가 요청을 거절하면 다른 모델로 다시 돌리는 기능 | 대타 선수 |
| **프롬프트 캐시** | 매번 같은 앞부분(지시문·근거)을 저장해 두고 싸게 재사용 | 자주 쓰는 문장 상용구 |

## 스스로 점검

<details><summary>Q1. 저장을 사람 확정 노드 안에서 하지 않고 다음 노드로 뺀 이유는?</summary>

LangGraph는 interrupt 뒤 재개할 때 그 노드를 처음부터 다시 실행한다. 확정 노드 안에서 저장하면 두 번 저장될 수 있다. 그래서 되돌릴 수 없는 일(저장, 나중엔 지원 이력 등록)은 다음 노드에 둔다.
</details>

<details><summary>Q2. 근거 검색가를 요구 항목 수만큼 나눈 건 5가지 패턴 중 무엇이고, 왜 안전한가?</summary>

공고마다 항목 수가 달라 실행 중에 나눌 개수가 정해지니 오케스트레이터다. 검색은 읽기만 해서 서로 충돌할 쓰기가 없으니 동시에 돌려도 안전하다.
</details>

<details><summary>Q3. "Python"과 "파이썬"을 못 잇는 문제는 1~5교시 중 어디서 배운 내용인가?</summary>

2교시. 키워드 검색은 같은 단어만 찾고, 뜻 검색(임베딩)은 표기가 달라도 뜻이 가까우면 찾는다. 그래서 둘을 섞는 하이브리드를 쓴다.
</details>

## 메인 PC에서 처음 실제로 돌리는 법

1. 가상환경은 OneDrive 밖에 만든다: `py -3 -m venv D:\jobfit-venv`
2. `D:\jobfit-venv\Scripts\pip install -r requirements.txt`
3. `jobfit-agent\.env` 파일을 만들고 `ANTHROPIC_API_KEY=...` 한 줄을 넣는다. 유튜브 자동화가 쓰는 키와 같은 키를 써도 된다. **.env 는 깃에 올라가지 않는다.**
4. `D:\jobfit-venv\Scripts\python -m pytest` 로 테스트가 통과하는지 본다.
5. `D:\jobfit-venv\Scripts\python run.py eval\postings\001.md` 로 실행하고, 끝에 나오는 **비용**을 이 노트에 적는다.
