# 학습노트 2-1b · 멘토의 공고 읽는 법 반영 (2026-10-26)

## 오늘 한 것

1. 메인 PC가 멘토링 녹화(30분)에서 멘토의 공고 읽는 원칙 10개와 원티드 공고 6개를 정리했다 ([정리본](../../../docs/멀티에이전트/멘토-공고읽는법-2026-10-26.md)).
2. 그 기준을 jobfit-agent의 세 에이전트에 넣었다 (설계 결정 J-14).
   - **분석가**: 회사가 무엇으로 돈을 벌고, 무슨 지표를 보는지 읽는다.
   - **작성자**: 같은 경험을 그 지표의 말로 다시 쓴다.
   - **검증가**: 회사에 안 통하는 지표를 앞세운 문장을 잡는다.
3. 분석가 채점 도구를 만들고, 가짜 분석가로 기준선을 쟀다 (J-15). 테스트는 19개 통과다.

## "AI를 학습시킨다"의 진짜 뜻

모델 자체를 다시 학습시키지 않았다 (1교시: 학습 vs 추론, 파인튜닝).
대신 두 곳에 멘토의 기준을 넣었다.
- **지시문**: 멘토의 질문과 회사 유형별 지표를 분석가·작성자·검증가 지시문에 넣었다.
- **평가셋**: 멘토가 해석한 내용을 정답표(`mentor_reading`)에 넣고, 분석가가 얼마나 따라가는지 숫자로 잰다.

지시문을 고치고 → 평가셋으로 재고 → 다시 고치는 반복이, LLM 에이전트를 "가르치는" 실제 방법이다.

## 기준선에서 나온 발견

| | 요구 항목 재현율 | 정밀도 | 회사 유형 일치 |
|---|---|---|---|
| 가짜 분석가 (공고 줄을 자르기만 함) | 86% | 75% | 0/3 |

- 공고 줄을 그대로 자르기만 해도 요구 항목은 86%를 찾는다. 요구 항목 뽑기는 쉬운 일(1차 정보)이다.
- 회사 읽기(2차 정보)는 0/3이다. 실제 분석가의 가치는 여기서 나와야 한다.
- 멘토 원칙 4 "1차 정보는 AI가 바로 정리한다, 사람은 행간을 읽어야 한다"와 같은 결과다.

## 멘토 원칙과 에이전트 연결

| 멘토 원칙 | 에이전트에 넣은 곳 |
|---|---|
| 5. "무엇으로 돈을 버나 → 중요 지표는?" | 분석가의 회사 읽기 (`business_model`, `key_metrics`) |
| 5. 회사 유형별 지표 (기술 판매 / 플랫폼 / 새 사업 / 상품 판매) | 분석가 지시문의 `company_type` 기준 |
| 6. 같은 경험을 회사 지표로 재구성 | 작성자 규칙 "회사 지표에 맞추기" |
| 7. 안 맞는 지표는 안 통함 | 분석가 `weak_metrics` + 검증가 "회사 지표와 안 맞음" |
| 4. 사람은 행간을 읽는다 | 사람 확정 화면에 회사 읽기를 "AI 추정"으로 표시 |
| 8. 질문만 알면 AI와 같이 할 수 있다 | 이 에이전트 자체 |

## 지어내기 대비

회사 읽기는 추론이라 지어내기 쉽다. 그래서 세 가지를 막아 뒀다.
- 판단 근거가 된 **공고 문구를 그대로 인용**하게 했다.
- 공고만으로 모르면 **확신도 "낮음"** 으로 두게 했다.
- 멘토 예시의 숫자(정확도 80→90%)는 예시일 뿐이다. 작성자는 근거에 없는 숫자를 쓰지 않고, 있으면 좋을 숫자는 "보강할 증거"로 따로 적는다.

> 기준선을 재보니 요구사항 뽑기는 단순 규칙으로도 86%가 나와서, 에이전트의 진짜 가치는 회사 읽기에 있다는 걸 숫자로 확인했습니다."

요구 항목 뽑기는 공고에 쓰인 것을 옮기는 쉬운 일(1차 정보)이라 기준선이 높다. 실제 분석가가 비용을 들일 가치는 회사 읽기(2차 정보)에서 나와야 하고, 그걸 회사 유형 일치로 잰다.
