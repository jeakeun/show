# jobfit-agent — 공고 맞춤 지원서 멀티 에이전트

채용 공고 하나를 넣으면 이렇게 진행합니다.
1. 요구사항을 뽑습니다.
2. 내 경력 문서에서 근거를 찾아 적합도를 계산합니다.
3. **모든 문장에 근거가 달린** 자기소개서·이력서 강조점 초안을 만듭니다.
4. 사람이 확정하면 지원 이력에 등록합니다.

> 상태: **근거 검색 개선 (2-2)** (2026-10-27). 테스트 32개 통과. 평가셋 공고 7개를 실제 모델(Opus 5.5)로 돌렸습니다.
> 공고 분석가 재현율 91%·정밀도 92%.
> - 여러 에이전트: 7개 모두 코드·AI 검증 통과. 근거 번호 문제를 고친 뒤 남은 지적 28 → 0, 비용 US$4.45 → 3.43.
> - 기준선(에이전트 1개, US$1.66): 근거 번호는 다 달았지만 첫 초안에 과장 8건·학습을 실무처럼 2건이 남았습니다.
> - 근거 검색(2-2): 001에서 운영 경험을 못 찾던 원인 세 가지를 고쳤습니다. 정답 항목 117개로 재면
>   운영 근거 적중 32% → 70%, 판정 일치 62% → 75%, 001 적합도 50 → 67점(정답 67점). 모델 호출 없는 채점입니다.
>
> - 근거 판정(2-3): 키워드 글자 맞추기 판정이 117개 중 29개 틀려서, AI 근거 판정가가 판정하고 코드가 근거 번호를 검사하게 바꿨습니다.
>   여러 부분을 묻는 항목 규칙까지 넣은 뒤 판정 일치 75% → 89%, 가짜 운영 5 → 2, 깎임 20 → 9, 정답 적합도와의 차이 13.3 → 7.0점
>   (채점 1회 US$0.86). 한 번씩만 돌려서 실행마다 흔들리는 폭은 아직 모릅니다.
>
> 검색을 바꾼 뒤 실제 모델로 지원서는 아직 안 돌렸습니다.
> 결과는 [eval/results/](eval/results/)에 있습니다.
> 지금은 [show 저장소](https://github.com/jeakeun/show) 안의 폴더이고, 새 공개 저장소가 생기면 기록째로 옮깁니다.
> 아직 만들지 않은 것을 만든 것처럼 쓰지 않습니다.

## 왜 만드나

- **실제로 쓰려고**: 지원할 때마다 공고에 맞춰 경력을 골라 쓰는 일을 줄입니다.
- **지어낸 경력을 막으려고**: AI가 쓴 지원서는 그럴듯하지만, 하지 않은 일을 한 것처럼 쓰기 쉽습니다.
  이 프로젝트의 학습 자료를 만들 때 검토 에이전트가 과장되거나 근거 없는 표현을 53개 잡아냈습니다.
  그 경험을 **검증가 에이전트**로 만든 것이 이 프로젝트의 핵심입니다.
- **AI Agent 개발 역량을 보여주려고**: LangGraph 멀티 에이전트, RAG, 레거시 시스템 연계, 사람 승인, 평가를 한 프로젝트에 담습니다.

## 구조

```
공고 ──→ [① 공고 분석가] 요구 항목을 구조화된 목록으로
              │
              ├─→ [② 근거 검색가] × 요구 항목 수   ← 경력 문서 RAG. 읽기라 병렬
              │
         [③ 적합도 계산] 코드                       ← 숫자는 코드가
              │
         [④ 작성자] 1명                              ← 쓰기는 한 곳. 문장마다 [근거 번호]
              │
         [⑤ 검증가] 근거 없는 문장·과장 표현 검사 ──→ 문제 있으면 ④로 (최대 2회)
              │
         [⑥ 사람 확정]                              ← 되돌릴 수 없는 일 앞에서 멈춤
              │
         [⑦ 저장] 확정된 초안만 저장                 ← 지원 이력 등록(지원 관리 API)은 2-5 단계에서 이 자리에 붙임
```

각 칸을 왜 이렇게 나눴는지는 [docs/DESIGN.md](docs/DESIGN.md)에 있습니다.

## 진행 단계

| # | 내용 | 상태 |
|---|---|---|
| 2-1 | 첫 골격(흐름 전체) + 평가셋 + 에이전트 1개짜리 기준선 | 골격 ✅ · 멘토 기준 반영 ✅ · 평가셋 공고 7개 · 채점 도구 ✅ · 실제 모델 실행 ✅ · 기준선 비교 ✅ |
| 2-2 | 경력 문서 RAG (근거 검색가), 검색 적중률 측정 | 문서 정리·동의어·종류별 검색 ✅ · 검색 채점 도구 ✅ (운영 근거 적중 32% → 70%) · 뜻 검색(임베딩) 비교는 아직 |
| 2-3 | 공고 분석가 + 적합도 계산 | AI 근거 판정가 + 코드 검사 ✅ (판정 일치 75% → 89%) · 반복 실행 흔들림 측정은 아직 |
| 2-4 | 작성자 + 검증가 루프 (LangGraph) | |
| 2-5 | 사람 확정 + 지원 관리 API 연결 | |
| 2-6 | 에이전트 1개 vs 여러 개 실측 비교, 비용·추적 | |
| 2-7 | LangFlow로 근거 검색 다시 만들기 | |

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `run.py` | 실행. 공고 파일을 넣으면 초안을 만들고 사람 확정을 받음 |
| `jobfit/graph.py` | 에이전트 흐름 (LangGraph): 분석 → 병렬 검색 → 적합도 → 작성 → 검증 → 사람 확정 → 저장 |
| `jobfit/llm.py` | 모델 호출 (공식 Anthropic SDK): 생각 강도, 구조화된 출력, 거절 대비, 캐시, 비용 기록 |
| `jobfit/career.py` | 경력 문서 자르기(LangChain 분할기) + 근거 아닌 부분 빼기 + 키워드 검색(BM25, 운영·학습 문서 종류별) |
| `jobfit/words.py` | 말 맞추기: 영어는 단어 통째로, 한글은 두 글자씩, 동의어 사전 (LLM ↔ 클로드, Python ↔ 파이썬) |
| `jobfit/scoring.py` | 키워드 판정, AI 근거 판정 검사, 적합도 계산 (코드) |
| `jobfit/citations.py` | 근거 번호 검사 (코드) |
| `jobfit/prompts.py` | 에이전트별 지시문, 출력 형식 |
| `jobfit/fake.py` | 가짜 모델 (API 키 없이 흐름 시험) |
| `jobfit/evaluate.py`, `eval_analyzer.py` | 공고 분석가 채점: 요구 항목 재현율·정밀도, 회사 유형이 멘토 해석과 같은지 |
| `jobfit/retrieval_eval.py`, `eval_retrieval.py` | 근거 검색 채점: 정답 근거(`eval/evidence.json`)와 비교, 검색 방식별 비교표 (모델 호출 없음) |
| `jobfit/batch.py`, `batch_run.py` | 지원서 변경 테스트: 여러 공고를 사람 확정 직전까지 돌려 초안·지적·비용을 모음 (승인·저장 안 함). `--baseline` 은 같은 공고를 에이전트 1개로 돌려 비교 |
| `tests/` | 부품 테스트 + 흐름 테스트 |

## 실행

```
pip install -r requirements.txt
python -m pytest                                  # 테스트 (API 키 불필요)
python run.py eval/postings/001.md --dry-run      # 가짜 모델로 흐름 확인 (비용 없음)
python run.py eval/postings/001.md                # 실제 실행 (JOBFIT_API_KEY 필요, 비용 발생)
python run.py eval/postings/001.md --baseline     # 에이전트 1개짜리 기준선
python eval_analyzer.py                           # 공고 분석가 채점 (평가셋 공고 전체)
python eval_retrieval.py                          # 근거 검색 채점 (비용 없음)
python eval_retrieval.py --ai-judge --estimate     # AI 근거 판정 채점 비용 추정 (무료). --estimate 빼면 실제 채점
python batch_run.py --only 008,009 --max-usd 5    # 지원서 변경 테스트 (비용 상한)
python batch_run.py --baseline --max-usd 3        # 같은 공고를 에이전트 1개짜리 기준선으로 (비교용)
```

비용 상한은 공고를 새로 시작하기 전에만 확인합니다. 공고 하나를 도는 중에는 멈추지 않아서, 마지막 공고 비용만큼 넘을 수 있습니다.
