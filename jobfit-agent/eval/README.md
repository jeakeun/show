# 평가셋 (2-1 단계)

멀티 에이전트가 정말 나은지는 **같은 문제로 잰 숫자**로만 말할 수 있어서, 코드보다 평가셋을 먼저 만듭니다.

## 구성

| 폴더 | 내용 |
|---|---|
| `postings/NNN.md` | 공고 원문 (회사명이 없어도 됨) |
| `answers/NNN.json` | 사람이 만든 정답: 요구 항목 목록, 채점에서 뺀 항목과 이유, 항목별 정답 근거(2-2에서 채움) |

## 정답을 만드는 규칙

- 요구 항목은 **담당 / 필수 / 우대 / 스킬**로 나눕니다.
- 같은 요구가 여러 곳에 나오면 하나로 합치고, `excluded` 에 이유를 적습니다.
- "기타 업무"처럼 구체적인 요구가 없는 줄은 채점에서 빼고 이유를 적습니다.
- 정답 근거는 `career/` 문서의 위치(파일 + 섹션)로 적습니다. 근거가 없으면 "없음"이 정답입니다. **없는 경력을 있다고 하지 않는 것도 채점 대상**입니다.

## 잴 것

| 단계 | 지표 |
|---|---|
| 공고 분석 | 요구 항목을 빠뜨리지 않았나(재현율), 없는 항목을 만들지 않았나(정밀도) |
| 근거 검색 | 항목별 정답 근거가 상위 k개 안에 들어온 비율 |
| 초안 | 근거 번호가 없는 주장 문장 수, 근거와 안 맞는 문장 수(사람 표본 검사), 과장 동사 수 |
| 운영 | 공고 1개당 비용, 걸린 시간 |

같은 평가셋으로 **에이전트 1개짜리 기준선**과 멀티 에이전트를 비교합니다.

## 현재

- 공고 1개 (`001`, 사용자가 공유한 LangChain AI Agent 개발 공고). 목표는 10~20개.
