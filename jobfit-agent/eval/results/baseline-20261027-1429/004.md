## 자기소개서

저는 유튜브 채널 운영, 앱 마케팅, 취업 정보 수집, 코인 모의투자, 카카오 마케팅 메시지 에이전트까지 개인 자동화 프로젝트를 모두 클로드 코드와 함께 만들었고, 메인 PC의 윈도우 작업 스케줄러에서 매일 자동으로 운영하고 있습니다 [E1]. 기록에 적힌 성과는 운영자인 제가 방향을 정하고, 제 지시로 클로드 세션이 함께 일한 결과입니다 [E21]. 대표 사례는 지식 쇼츠 채널 '1분호기심'입니다 [E9]. 이 채널은 트렌드 수집, Claude 대본 작성과 사후검사, ffmpeg 렌더링, YouTube API 업로드, 조회수 기록, 일요일 회고를 통한 전략 갱신까지 하나의 파이프라인으로 이어져 있습니다 [E9]. 2026년 8월부터 사람이 손대지 않아도 매일 2편이 올라가고, 영어 채널에도 미러링되고 있습니다 [E2][E9]. 6인 팀 프로젝트인 웹 서비스 '집가'에서는 마케팅 파트를 혼자 맡았습니다 [E11]. 영상 정규화부터 문구 생성, 발행 큐까지 이어지는 M1~M6 파이프라인과 5채널 원클릭 업로더를 만들었습니다 [E11]. 쓰레드에는 API 자동 예약 게시를 적용했고, 플랫폼 제재를 예방하려고 공개 문구에서 술·음주 표현을 전면 금지하는 원칙을 두었습니다 [E12].

AI에게 맡길 일과 코드나 사람이 판단할 일은 '매번 같은 답이 나와야 하는가'를 기준으로 나눕니다 [E34]. 한 번은 회고 AI가 50편 표본 합계에서 생긴 착시를 보고 '-76% 급락'이라는 원인 서사까지 지어낸 일이 있었습니다 [E32]. 감사로 이 문제를 찾은 뒤 해당 계산을 없앴고, 계산·누적 상태·정해진 형식의 문자열은 코드가 맡도록 바꿨습니다 [E32][E33]. 또 채널 전체 조회수 값이 9/2부터 사실상 멈춰 회고 추세가 왜곡될 상황을 발견했습니다 [E38]. 그래서 영상별 증가분의 합으로 추세를 보고 '정지' 표시를 붙이도록 고쳤습니다 [E38]. 대본은 작성 AI와 기준표를 가진 검수 AI로 나눴습니다 [E24]. 일주일간 재생성 3건이 모두 검수 오탐이었다는 것을 확인하고, 슬롯별 기준으로 고쳤습니다 [E25]. 사람 승인은 '되돌릴 수 있는가'를 기준으로 위치를 정했습니다 [E39][E40]. 되돌릴 수 있는 개선은 이전본을 보관한 채 자동 적용한 뒤 보고하고, 돈이 드는 결정이나 영상 삭제는 사람이 고르게 했습니다 [E39][E40]. 성공 판정도 AI가 출력한 '완료' 문구 대신 결과물 파일의 실존과 종료 코드로 바꿨고, 실패나 품질 저하는 폰 푸시로 알리도록 했습니다 [E43][E44].

정책과 예외가 얽힌 영역은 AI 판단이 아니라 규칙으로 구조화합니다 [E45]. 현재 개발 중인 market-compass는 1인 셀러의 요청을 받아 대상 선정, 문구 생성, 정보통신망법·카카오 정책 위반 검사, 사람 승인 두 번, (가상) 발송까지 진행하는 에이전트입니다 [E15]. 규정 검사는 테스트가 붙은 규칙 R01~R12로 만들고, 발송 경로는 한 곳으로 묶었습니다 [E15][E45]. 법 규정 판정은 매번 같아야 하고, 규칙 번호로 이유를 설명할 수 있어야 한다고 판단했기 때문입니다 [E45]. 개발 구조에 대한 이해를 넓히기 위해 7개월 과정에서 Java·Spring Boot·React·AWS를 학습했습니다 [E103]. 또 LangGraph·LangChain 예제를 시험용 가짜 모델로 돌려, 쓰기 도구만 사람 승인 뒤에 실행되는 구조를 실험했습니다 [E100]. 이 실험에서 승인 전에는 DB 값이 바뀌지 않는 것을 확인했습니다 [E101].

## 이력서 강조

- 지식 쇼츠 채널 '1분호기심'을 클로드 코드로 구축했습니다. 트렌드 수집부터 대본, 렌더링, 업로드, 회고까지 무인으로 돌아가며, 2026-08부터 매일 2편 발행하고 영어 채널에도 미러링하고 있습니다 [E2][E9].
- 6인 팀 웹 서비스 '집가'의 마케팅 파트를 혼자 자동화했습니다. M1~M6 파이프라인, 5채널 업로더, 쓰레드 API 자동 예약 게시를 구현했습니다 [E11][E12].
- AI와 코드의 역할을 나누는 기준을 세웠습니다. 계산·고정 문자열은 코드에 맡기고, 작성 AI와 검수 AI를 분리했습니다. 이 과정에서 일주일간 재생성 3건이 모두 검수 오탐인 것을 찾아 기준을 고쳤습니다 [E25][E33][E34].
- 운영 관측성과 비용을 관리했습니다. 모든 API 호출 비용을 기록해 대시보드에 '매일 운영비'와 '주간 분석비'로 나눠 표시했고, 역할별로 모델을 배정했습니다. 성공 판정은 결과물 파일의 실존으로 하도록 바꿨습니다 [E8][E41][E43].
- 읽기 전용 자가감사를 운영했습니다. 첫 감사에서 노출된 API 키, 코인봇 수수료 계산 오류(20.5%), 유령 데이터를 발견했고, 1회차 주간 감사에서는 8건을 찾아 검증 후 6건을 수정했습니다 [E37][E38].
- 규제 검사 규칙 엔진을 개발하고 있습니다. 카카오 마케팅 메시지 에이전트에 정보통신망법·카카오 정책 규칙 R01~R12와 사람 2회 승인 구조를 설계했으며, Guard 테스트는 24/48까지 완료했습니다 [E15][E45].
