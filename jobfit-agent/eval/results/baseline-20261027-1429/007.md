## 초안 (다시 쓰기 없음)
## 자기소개서

저는 유튜브 채널 운영, 취업 정보 수집, 코인 모의투자 같은 개인 자동화 프로젝트를 클로드 코드와 함께 만들었고, 이 자동화들은 메인 PC의 윈도우 작업 스케줄러에서 매일 돌아갑니다 [E1]. 대표 프로젝트인 유튜브 파이프라인은 트렌드 수집, Claude 대본 작성, ffmpeg 렌더링, YouTube API 업로드로 이어지며, 사람이 손대지 않아도 매일 아침과 저녁에 쇼츠를 올립니다 [E9]. 파이프라인을 부서별 에이전트로 나누자는 안이 나왔을 때는 기각했습니다. 판단이 없는 공정에 에이전트를 두면 감독관만 늘어 비용과 실패 지점이 함께 늘기 때문입니다. 그래서 LLM은 대본 작성·검수·회고처럼 판단이 필요한 칸에만 두고, 렌더링과 업로드는 코드로 남겼습니다 [E27]. 복잡도는 필요한 곳에만 더한다는 이 판단이 "복잡한 시스템을 단순한 구조로" 만든다는 팀의 방향과 맞닿아 있다고 생각합니다 [E28].

에이전트를 무인으로 운영하면서 가장 신경 쓴 부분은 실행 상태를 관측하고 통제하는 일이었습니다. 처음에는 AI가 출력한 "완료" 문구로 성공을 판정했는데, 오판이 반복됐습니다. 그래서 결과물 파일이 실제로 있는지와 종료 코드로 판정하도록 바꾸고, 실패나 품질 저하 발행은 폰 푸시로 알리게 했습니다 [E43][E44]. 모델은 역할마다 다르게 배정했고, 모든 호출 비용을 기록해 대시보드에서 매일 운영비와 주간 분석비로 나눠 봅니다 [E41][E8]. 비용을 줄이려고 출력 한도를 낮췄다가, 상위 모델의 사고 토큰이 한도에 포함된다는 점을 놓쳐 본문 0자 실패를 겪은 적이 있습니다. 이후 한도를 다시 올리고, 한도 초과를 명시적 오류로 처리하도록 고쳤습니다 [E41][E42]. 분석 AI가 운영 설정을 몰래 바꾸지 못하도록 실행 전에 설정·소스 파일의 해시를 백업하고, 변경되면 자동 원복하는 가드도 넣었습니다. 이후 회고 AI가 만든 임시 스크립트를 이 가드가 실제로 격리하는 것까지 확인했습니다 [E29][E30].

Agent Runtime의 상태 관리를 더 깊이 이해하려고 LangGraph도 학습했습니다. 검수 루프, interrupt 기반 사람 승인, Send 병렬 실행을 시험용 가짜 모델로 돌려 구조를 실험했습니다 [E49][E58][E60][E63]. 이 실험에서 interrupt 이후 재개하면 해당 노드가 처음부터 다시 실행된다는 점을 확인했고, 그 앞에는 두 번 실행되면 안 되는 작업을 두지 말아야 한다는 원칙을 정리했습니다 [E61][E62]. 프레임워크 경험이 학습 예제 수준이라는 한계를 스스로 기록해 두었고, 이를 채우기 위해 jobfit-agent를 개발하고 있습니다 [E47]. jobfit-agent는 공고 분석, 경력 근거 병렬 검색, 근거 검증, 사람 확정으로 이어지는 LangGraph·RAG 프로젝트이며, 2026-10-27에 실제 모델로 공고 7개를 처음 실행했습니다 [E4].

## 이력서 강조
- 유튜브 쇼츠 자동화 파이프라인을 2026-08-02부터 운영하고 있으며, 매일 2편을 자동 업로드하고 영어 채널에도 현지화해 올립니다 [E2].
- AI 출력 문구 대신 결과물 파일 실존과 종료 코드로 성공을 판정하고, 실패와 품질 저하 발행을 폰 푸시로 알리는 관측 체계를 만들었습니다 [E43][E44].
- 역할별로 모델을 배정하고 호출 단위로 비용을 기록했습니다. 2026-09-07~13 기준선은 대본 생성 비용 주 US$3.72(호출당 약 US$0.16)입니다 [E41][E42].
- 작성 AI와 기준표를 가진 검수 AI를 분리했습니다. 일주일간 재생성 3건이 모두 검수 오탐이었던 원인을 찾아, 슬롯별 기준으로 나눠 고쳤습니다 [E24][E25].
- 분석 AI가 보호 파일을 바꾸면 자동 원복하고, 새로 생긴 파일은 격리하는 해시 가드를 도입해 실제 격리 동작을 확인했습니다 [E29].
- LangGraph의 상태 갈림길, interrupt·체크포인터 승인, Send 병렬 실행을 학습 예제로 실험했고, 이를 jobfit-agent 개발로 이어가고 있습니다 [E58][E61][E63][E4].
