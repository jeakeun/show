## 자기소개서

저는 반복되는 일을 찾아 AI 워크플로우로 바꾸고 매일 운영해 왔습니다. 유튜브 채널 운영, 앱 마케팅, 취업 정보 수집, 코인 모의투자 등 개인 자동화 프로젝트를 클로드 코드와 함께 만들었고, 메인 PC의 윈도우 작업 스케줄러에서 매일 자동으로 돌리고 있습니다 [E1]. 대표 프로젝트인 '1분호기심' 채널은 트렌드 수집, AI 대본 작성, ffmpeg 렌더링, YouTube API 업로드, 조회수 기록, 일요일 회고까지 이어지는 파이프라인입니다. 사람이 손대지 않아도 매일 아침과 저녁에 쇼츠가 올라갑니다 [E9]. 6인 팀 프로젝트 '집가'에서는 마케팅 파트를 혼자 맡았습니다. 영상 정규화, 전사, 9:16 클립, 문구 생성, 스토어 링크, 발행 큐로 이어지는 M1~M6 파이프라인을 만들어 이 파트를 자동화했습니다 [E11].

운영하면서 가장 중요하게 본 것은 AI가 잘하는 일과 못하는 일을 나누는 것이었습니다. 파이프라인을 단계별 에이전트로 쪼개자는 안은 이득이 없다고 보고 기각했습니다. 대신 대본 작성, 검수, 회고처럼 판단이나 글쓰기가 필요한 칸에만 LLM을 두고, 슬롯 결정, 렌더링, 업로드는 코드가 맡게 했습니다 [E27]. 고정 문자열을 AI에게 쓰게 하고 AI로 검사했다가 저녁 자가테스트가 사흘 동안 빠진 일도 겪었습니다. 그 뒤로 계산, 누적 상태, 정해진 형식의 문자열은 코드가 맡도록 바꿨습니다 [E32][E33]. 비용은 판단 난이도에 맞춰 주간 분석에 Opus, 대본에 Sonnet, 검수와 팩트체크에 Haiku를 배정했습니다. 모든 호출 비용을 기록해 대시보드에 '매일 운영비'와 '주간 분석비'로 나눠 보여줍니다 [E41]. 정확도 면에서는 일주일 동안 재생성된 3건이 모두 검수 AI의 오탐이었다는 것을 찾아냈고, 슬롯 정보를 검수 AI에 넘겨 기준을 나누는 것으로 고쳤습니다 [E25]. 안정성을 위해 성공 판정은 AI 출력 문구 대신 결과물 파일 실존과 종료 코드로 하도록 바꿔 왔고, 자동화 실패와 품질 저하 발행은 폰 푸시로 알리게 했습니다 [E43][E44]. 매주 읽기 전용 자가감사도 돌립니다. 8/27 첫 전수 감사에서는 노출된 API 키, 코인봇 수수료 계산 오류, 없는 회차 기록을 찾았습니다 [E37].

경험과 배움을 정리해 다른 사람도 쓸 수 있게 만드는 일도 꾸준히 해 왔습니다. 운영 중 실제로 내린 설계 결정 10개를 상황, 대안, 결정, 이유, 대가, 결과 순서의 기록으로 정리했습니다 [E21]. 개발 중인 market-compass에서는 일차마다 비개발자용 학습노트를 쓰고 있습니다 [E15]. 새 기술은 직접 실행해 보며 익힙니다. LangGraph 1.2.16으로는 검수 루프, 사람 승인 후 재개, 병렬 감사 구조를 시험용 가짜 모델로 실행해 보며 학습했습니다 [E49][E59][E61][E63]. RAG는 제 설계 문서를 대상으로 청킹을 실험했습니다. 글자 수로만 자르면 41조각 중 31조각은 어느 결정에 대한 내용인지 알 수 없었습니다 [E79]. 제목 기준 분할기의 기본 설정이 제목을 검색 본문에서 빼서 정답을 놓친다는 것도 확인했습니다 [E84]. 다만 이 결과는 질문 하나로 한 실험이라, 일반화하려면 평가셋으로 다시 확인해야 한다고 기록해 두었습니다 [E85]. 지금은 이 학습을 바탕으로 공고 분석, 경력 근거 검색, 초안 작성, 근거 검증, 사람 확정으로 이어지는 LangGraph·RAG 기반 jobfit-agent를 개발하고 있습니다. 2026-10-27에는 실제 모델로 공고 7개를 처음 실행했습니다 [E4].

## 이력서 강조
- 트렌드 수집부터 대본, 렌더링, 업로드, 주간 회고까지 이어지는 유튜브 쇼츠 자동화 파이프라인을 설계해 2026-08-02부터 매일 2편 운영 중이며, 영어 채널 미러도 함께 운영 [E2][E9].
- 역할별 모델 배정(Opus·Sonnet·Haiku)과 프롬프트 캐싱을 적용하고, 모든 API 호출 비용을 기록해 '매일 운영비·주간 분석비'로 나눠 대시보드에 표시 [E41][E8].
- 검수 AI의 재생성 3건이 모두 오탐임을 찾아 슬롯별 기준으로 수정하고, 주간 회고 전략은 별도 AI가 반박 검증하도록 설계 [E25][E35].
- 성공 판정을 결과물 파일과 종료 코드 기준으로 바꾸고 실패 시 폰 푸시 알림을 구축했으며, 주간 읽기 전용 자가감사로 노출된 API 키와 수수료 계산 오류를 발견 [E43][E44][E37].
- "매번 같은 답이 나와야 하는가"를 기준으로 AI와 코드의 역할을 나눠, AI가 손으로 세던 카운터를 코드(`streaks.py`)가 실측 기록에서 계산하도록 전환 [E33][E34].
- LangGraph·RAG를 학습하며 청킹·검색 실험을 진행했고, 이를 바탕으로 맞춤 지원서 에이전트 jobfit-agent를 개발 중이며 실제 모델로 공고 7개를 처음 실행 [E79][E84][E4].
