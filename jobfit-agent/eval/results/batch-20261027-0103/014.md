## 회사 읽기 (AI 추정)
회사 유형: 기타 (확신도 보통, AI 추정)
돈 버는 방식: 콘텐츠·크리에이터·커머스 사업을 운영하는 회사로, 이 자리는 사내 현업 업무를 AI Agent로 자동화·협업화해 업무 효율과 사업 성과를 높이는 내부 AX(AI 전환) 역할
중요 지표: 현업 실제 사용률·활용도(도입된 Agent 수, 사용 빈도), 업무 시간·인력 절감 등 비즈니스 성과, 프로토타입→프로덕션 전환 속도와 개수, Agent 운영 안정성·품질(테스트, 오류율)
안 통하는 지표: 외부 사용자 수·트래픽 대응 규모, 벤치마크 기준 모델 성능 수치만의 개선, 사용되지 않은 기술 데모·연구 성과
근거 문구: "코드를 잘 짜는 것에서 멈추지 않고, 비즈니스 문제를 이해해 실제 사용과 성과로 연결하는 엔지니어를 찾습니다" / "뉴셀렉트의 콘텐츠·크리에이터·커머스 업무를 사람과 AI가 함께 일하는 AI Product로 만드는 사람입니다" / "배포 이후 사용 데이터와 현업 피드백을 반영해 품질과 활용도를 개선합니다" / "현업의 프로토타입 수준 산출물을 프로덕션 수준으로 고도화합니다"

## 자기소개서

저는 유튜브 '1분호기심' 자동화(트렌드 → AI 대본 → 영상 렌더링 → 자동 업로드, 매일 2편)를 2026년 8월 2일부터, AI데일리 취업 정보 수집을 8월 3일부터 운영하고 있습니다 [E27]. 앱 '집가' 출시 마케팅에서는 영상 제작·문구 생성·5채널 발행 자동화로 출시 마케팅 1차를 마쳤습니다 [E27]. 이 시스템들은 제가 설계·운영하고, 구현은 클로드 코딩 에이전트가 맡았습니다 [E5]. 유튜브 파이프라인을 단계마다 '부서별 에이전트'로 나누자는 안이 나왔을 때, 저는 판단 없는 공정에 감독관을 두는 격이라 비용과 실패 지점만 늘어난다고 보고 기각했습니다 [E8]. 대신 대본 작성·검수·팩트체크·댓글 답글처럼 판단이나 글쓰기가 필요한 칸에만 LLM을 두고, 렌더링·업로드·자막 맞추기는 코드가 맡게 했습니다 [E8]. 그 덕분에 8월 4일부터 하루 2편 돌던 파이프라인을 쪼개지 않고 그대로 유지했습니다 [E9].

사람이 판단할 위치는 운영하면서 두 번 바꿨습니다 [E13]. 8월에는 회고 AI가 플레이북을 바로 반영했고, 9월 7일부터는 모든 회고 제안을 사람이 승인하게 했습니다 [E13]. 그러자 9월 20일에 플레이북이 승인 대기로 하루 묵어 다음 날 적용 시작을 놓쳤고, 비개발자인 운영자에게는 승인 판단 자체도 부담이었습니다 [E13]. 그래서 9월 21일부터 기준을 '되돌릴 수 있는가'로 바꿨습니다 [E13]. 되돌릴 수 있는 플레이북·프롬프트 개선은 이전본을 보관한 채 자동 적용한 뒤 보고하고, 프롬프트가 문법·스모크 테스트에 실패하면 자동으로 원복하게 했습니다 [E13]. 돈이 드는 결정, 영상 삭제·공개 전환, 실전 매매 전환은 계속 사람이 정하며, 이 결정들은 리포트에 A/B/C/D 선택지로 올라옵니다 [E22].

에이전트가 안전하게 일하도록 쓰기 권한도 통제했습니다 [E25]. 감사에서 코인 회고 AI가 쓰기 권한이 열린 틈에 임시 분석 스크립트를 만든 전례를 찾았습니다 [E25]. 그 뒤 회고 실행 스크립트에 가드를 넣어, 실행 전에 설정·소스 파일 해시를 백업해 두고 바뀌면 자동 원복하며 새로 생긴 파일은 격리하게 했습니다 [E25]. 9월 6일 회고 AI가 다시 임시 스크립트를 만들었을 때 가드가 이를 격리하는 것을 확인했습니다 [E25]. 리포트가 실제 데이터와 맞는지는 읽기 전용 감사 에이전트 3기를 병렬로 돌려 원본 데이터와 대조했고, 이 과정에서 코인봇 수수료 계산 오류(20.5%)와 AI데일리의 없는 회차 기록을 찾았습니다 [E19]. 지금은 매주 일요일 헤드리스 클로드 1회 실행으로 같은 대조를 하고 있으며, 1회차 시험에서 8건을 발견해 검증 후 6건을 실제로 고쳤습니다 [E19]. 다만 Agent Framework는 아직 실전 경험이 없고, LangGraph로 검수 루프·승인·병렬 처리 구조를 흉내 낸 학습 예제를 돌려본 수준입니다 [E24].

## 이력서 강조

- 유튜브 자동화(매일 2편 업로드)와 AI데일리를 2026년 8월부터 설계·운영 중이며, 구현은 클로드 코딩 에이전트가 담당 [E5][E27].
- 판단·글쓰기 칸에만 LLM을 두고 렌더링·업로드는 코드로 처리하는 구조로 설계해, 하루 2편 파이프라인을 쪼개지 않고 유지 [E8][E9].
- 사람 승인 위치를 '되돌릴 수 있는가' 기준으로 재설계함: 가역 변경은 자동 적용 후 보고와 스모크 테스트 실패 시 자동 원복, 비가역 결정은 A/B/C/D 선택지로 사람이 결정 [E13][E22].
- 분석 AI의 설정 변경을 막는 가드 도입: 파일 해시 백업 후 자동 원복, 신규 파일 격리, 실제 격리 동작 확인 [E25].
- 읽기 전용 감사 체계 운영: 첫 전수 감사에서 수수료 계산 오류와 유령 데이터 발견, 주간 감사 1회차 시험에서 8건 발견 후 6건 수정 [E19].
- (학습) LangGraph 예제로 `interrupt`와 같은 `thread_id` 재개를 이용한 사람 승인, 병렬 감사 후 단일 보고서 작성 흐름을 실행해 확인 [E26][E20]. (학습) 7개월 과정에서 Java·Spring Boot·React·AWS를 학습 [E21].
