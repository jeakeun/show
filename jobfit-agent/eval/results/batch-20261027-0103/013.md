## 회사 읽기 (AI 추정)
회사 유형: 새 사업 (확신도 보통, AI 추정)
돈 버는 방식: 회사는 의료AI 솔루션을 개발·공급하는 기술 판매 스타트업이나, 이 자리(AX팀)는 사내 AI Native Workspace를 처음부터 구축하는 내부 혁신 조직이다. 성과는 사내 구성원의 생산성 향상(10배·100배)과 도구 채택·사용으로 측정될 가능성이 크다.
중요 지표: 사내 업무 생산성 향상(업무 시간·수작업 절감), AI 기반으로 재설계·자동화한 워크플로우 수와 구축 속도, 사내 구성원 도구 채택률·사용 빈도, 통합한 데이터 소스 수와 Agent 활용 범위, 교육·가이드를 통한 구성원 AI 활용 역량 확산
안 통하는 지표: 외부 사용자 수·대규모 트래픽 처리, 의료AI 모델 정확도 등 제품 성능 지표, 판매량·매출 같은 외부 상업 지표, 미세한 지연시간 단축 최적화
근거 문구: "AX 팀은 AIRS Medical의 AI Native Workspace 시스템을 만들고 있습니다" / "AI 시대에 맞는 회사를, 10배·100배의 생산성으로 처음부터 직접 설계·구축하는 경험" / "정답이 정해진 문제가 아니라, 무엇을 만들면 회사가 한 단계 도약할지를 함께 찾아갑니다" / "사내 도메인 팀(Sales · Finance · RA·QA · CS 등)과 협업해 핵심 업무 워크플로우를 AI 기반으로 재설계" / "사내 도구를 직접 만들어 동료에게 임팩트를 준 경험"

## 초안 (사람 확정 직전, 승인 안 함)
## 자기소개서

저는 개인 업무를 하나씩 자동화로 바꿔 매일 돌리고 있습니다 [E12]. 유튜브 채널 운영, 앱 마케팅, 취업 정보 수집, 코인 모의투자, 버추얼 스트리머, 카카오 마케팅 메시지 에이전트를 모두 클로드 코드와 함께 만들었습니다 [E12]. 이 자동화들은 메인 PC의 윈도우 작업 스케줄러에서 매일 자동으로 실행됩니다 [E12]. 역할을 정확히 말하면 설계와 운영은 제가 했고, 구현은 클로드 코딩 에이전트와 함께 했습니다 [E13]. 2026-10-23에는 웹드라마 반자동 작업과 맞춤 지원서 에이전트의 첫 골격을 추가했습니다 [E12]. 10-26까지는 회당 90초·매화 보상 규칙과 업로드 순서·중복 보호를 보강했습니다 [E12]. 두 PC에서 함께 돌리면 이중 업로드와 이중 매매가 생기기 때문에, 자동 실행은 메인 PC에서만 하도록 운영 규칙을 정했습니다 [E9].

사람이 보지 않는 무인 업로드에는 검수 단계를 설계해 넣었습니다 [E8]. 유튜브 대본에는 의료 조언 같은 정책 위험 표현이 섞이거나 구독 멘트가 빠질 수 있었습니다 [E8]. 그래서 대본을 만드는 AI와 별도로, 기준표로 채점하는 검수 AI를 두기로 결정했습니다 [E8]. 여기에 제목과 의료 단어를 확인하는 코드 사후검사를 함께 두었습니다 [E8]. 차단급 문제는 재생성하고, 2번 연속 걸리면 예비 대본으로 바꿉니다 [E8]. 검수 API가 장애일 때는 통과시키되 코드 사후검사는 그대로 유지합니다 [E8].

남이 만든 시스템을 자동화 도구로 붙여 본 경험도 있습니다 [E6]. 쓰레드는 텍스트 API로 연결해 예약 게시까지 마쳤고, 유튜브는 공식 API와 OAuth로 연동했습니다 [E6]. 티스토리는 오픈 API 종료를 확인한 뒤, 비공식 자동화는 위험하다고 보고 자동화하지 않기로 결정했습니다 [E6]. 대신 글쓰기 페이지를 열고 문구를 복사해 주는 보조 모드까지만 두었습니다 [E6]. 뉴스 RSS에서 죽은 피드(410)가 나왔을 때는 대체 피드로 교체했습니다 [E6].

AX팀이 만드는 사내 Agent 환경에 맞춰, 에이전트에게 사내 시스템을 줄 때 "어떤 도구를, 어떤 권한으로, 어떤 안전장치와 함께 주는가"를 공부하고 있습니다 [E14]. langchain 1.4.7과 langgraph 1.2.16에서, 실제 모델 대신 시험용 가짜 모델로 에이전트 구조를 실험했습니다 [E13]. 조회 도구는 승인 없이 바로 실행되고, 쓰기 도구는 호출 직전에 멈췄다가 승인한 뒤에야 실행되는 것을 확인했습니다 [E11]. 이 실험에서는 도구 호출 횟수에 제한을 두었습니다 [E11]. DB는 자유 SQL 대신 정해진 쿼리에 파라미터만 넣어 읽게 했습니다 [E1]. 제 프로젝트 3개(yt-auto, coin-bot, ai-daily)를 동시에 감사하고 결과를 보고서 노드 하나로 모으는 병렬 구조도 실험했습니다 [E10]. 데이터 쪽은 세 가지를 정리하며 학습했습니다 [E2][E7]. 기존 Postgres 옆에 붙이는 pgvector, 벡터와 키워드(BM25)를 함께 쓰는 하이브리드 검색, 권한으로 먼저 거르는 메타데이터 필터입니다 [E2][E7].

## 이력서 강조

- 개인 업무 자동화(유튜브 채널 운영·앱 마케팅·취업 정보 수집·코인 모의투자·버추얼 스트리머·카카오 마케팅 메시지 에이전트)를 클로드 코드와 함께 만들어, 윈도우 작업 스케줄러로 매일 자동 운영했습니다 [E12].
- 위 자동화에서 설계와 운영은 직접 했고, 구현은 AI 코딩 에이전트와 함께 했습니다 [E13].
- 무인 업로드용 대본 검수 게이트를 설계·운영했습니다: 생성 AI와 검수 AI 분리, 제목·의료 단어 코드 사후검사, 2회 연속 차단 시 예비 대본 전환, 검수 API 장애 시 fail-open [E8].
- 외부 API를 연동했습니다: 쓰레드 예약 게시 완료, YouTube Data·Analytics API OAuth 연동 [E6].
- 오픈 API가 종료된 티스토리는 자동화하지 않기로 판단했습니다 [E6].
- 자동 실행을 메인 PC 한 곳으로 한정해 이중 업로드·이중 매매를 막는 운영 규칙을 세웠습니다 [E9].
- (학습) LangChain·LangGraph에서 시험용 가짜 모델로 두 구조를 실험했습니다: 읽기 도구는 즉시 실행하고 쓰기 도구는 사람 승인 뒤 실행하는 구조, 그리고 병렬 감사 구조입니다 [E10][E11][E13].

## 보강할 증거

- 자동화 전후로 줄어든 주당 작업 시간. 이 팀의 핵심 지표인 업무 생산성 향상을 숫자로 말하려면 필요합니다.
- 자동화 하나를 처음 골격부터 매일 운영할 때까지 걸린 기간. 구축 속도를 보여 줄 수 있습니다.
- 검수 게이트가 실제로 차단·재생성한 건수와 예비 대본 전환 횟수. 안전장치가 운영에서 효과가 있었다는 근거가 됩니다.
- 내가 만든 도구나 가이드를 다른 사람이 써 본 사례, 그리고 Claude Code를 skill·hook·MCP server로 직접 손본 기록. 사내 채택·교육 항목과 우대사항에 아직 근거가 없습니다.
