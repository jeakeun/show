## 회사 읽기 (AI 추정)
회사 유형: 기술 판매 (확신도 보통, AI 추정)
돈 버는 방식: 의료 도메인 특화 LLM 에이전트(임상 의사결정 지원, 의료 문서 요약·검색, 환자 상담) 기술을 개발해 의료기관 등에 제공하는 것으로 보임. 정확한 수익 구조는 공고에 명시되지 않음.
중요 지표: task-success rate·tool-call accuracy 등 에이전트 정확도, hallucination rate 감소, 의료 벤치마크 기준 성능 개선, agent pipeline 지연시간·비용 절감, 신뢰성·재현성·감사 가능성(fallback, 실패율)
안 통하는 지표: 사용자 수·재방문 등 트래픽 성장 지표, 판매량·조회수, 신규 기능을 빠르게 많이 출시한 개수
근거 문구: "task-success rate·tool-call accuracy·hallucination rate 평가" / "최신 벤치마크 기준 성능 개선" / "지연시간·비용·신뢰성 기준 agent pipeline 최적화" / "의료 환경의 안정성·재현성·감사 가능성 확보" / "학회 발표 수준 연구" / "의료진 파일럿 피드백 수집·분석 및 개선 반영"

## 초안 (사람 확정 직전, 승인 안 함)
## 자기소개서

생성 결과의 정확도를 높이려고, 유튜브 파이프라인에서 대본을 만드는 AI와 검사하는 AI를 나누는 구조를 설계하고 운영했습니다 [E12]. 작성 과정을 함께 겪은 AI는 자기 글에 관대해지기 쉬워서, 검사 기준을 작성과 분리했습니다 [E16]. 도입 검증에서 정상 대본 3편은 지적 없이 통과했고, 의료 조언을 넣은 가짜 대본은 정확히 차단했습니다 [E16]. 하지만 검수 AI도 틀렸습니다. 9/7~13에 나온 재생성 3건은 모두 검수 오탐이었습니다 [E16]. 원인은 고전실험형 대본 전용인 "훅" 기준을 저녁 리스트형 대본에도 적용한 것이었고, 9/14에 슬롯 정보를 검수 AI에 넘겨 기준을 나누는 방식으로 고쳤습니다 [E16]. 검수 API에 장애가 나면 대본을 통과시키되(fail-open) 코드 사후검사는 그대로 유지했습니다 [E16]. 숫자와 고정 문자열은 코드가 맡고 해석과 문장만 AI가 맡도록 경계를 정한 결정도 설계 기록에 남겼습니다 [E12].

신뢰성과 감사 가능성은 쓰기 권한을 통제하는 방식으로 확보하려 했습니다. 프로젝트가 늘면서 리포트가 실제 데이터와 맞는지 아무도 대조하지 않는 문제가 생겼습니다 [E17]. 그래서 8/27에 읽기 전용 감사 에이전트 3기를 병렬로 돌려 리포트의 주장을 원본 데이터와 대조했습니다 [E17]. 이 감사에서 코인봇의 수수료 계산 오류와 AI데일리의 없는 회차 기록(유령 데이터)을 찾았습니다 [E17]. 같은 날 진행한 주간 자동 감사 1회차 시험에서는 8건을 발견했고, 검증한 뒤 6건을 실제로 고쳤습니다 [E17]. 분석 AI는 운영 설정을 직접 고치지 못하게 막았습니다 [E19]. 9/6에 회고 AI가 임시 스크립트를 만들었을 때 가드가 이를 격리하는 것을 확인했습니다 [E19]. 사람 승인 위치는 "되돌릴 수 있는가"를 기준으로 정했습니다 [E11]. 돈이 드는 결정, 영상 삭제·공개 전환, 실전 매매 전환은 사람이 고르게 했습니다 [E11]. 되돌릴 수 있는 변경은 이전본을 보관한 채 자동 적용하고 보고합니다 [E11]. 프롬프트는 문법·스모크 테스트에 실패하면 자동으로 원복합니다 [E11]. 비용 면에서는 렌더링·업로드·자막 맞추기처럼 판단이 없는 단계를 에이전트로 쪼개지 않고 코드에 두었습니다 [E6]. 그런 공정에 판단하는 AI를 두면 비용과 실패 지점만 늘어나기 때문입니다 [E6].

에이전트 프레임워크는 학습 단계입니다. LangChain 1.4.7과 LangGraph 1.2.16으로 제 운영 구조를 옮긴 학습 예제를 작성했고, 시험용 가짜 모델로 실행해 구조를 확인했습니다 [E20]. 검수 게이트의 갈림길을 흉내 낸 평가자-최적화자 루프를 만들어 보니 재생성 상한과 예비 대본 분기가 동작했고, 1차에 실패한 뒤 2차에 통과했습니다 [E9][E15]. `interrupt()`로 멈췄다가 같은 `thread_id`로 재개하는 사람 승인 흐름도 익혔습니다 [E10][E25]. `HumanInTheLoopMiddleware`로 쓰기 도구만 승인 뒤에 실행되게 해, 승인 전에는 DB 값이 바뀌지 않는 것도 확인했습니다 [E2]. RAG는 색인, 검색, 출처 표시로 이어지는 흐름과 임베딩 모델 선택 기준을 정리했습니다 [E22][E23]. 가짜 임베딩으로 검색하면 정답 문서 대신 엉뚱한 문서가 1등이 된다는 것도 실험으로 확인했습니다 [E24]. 이 시스템들은 제가 설계하고 운영했으며, 구현은 클로드 코딩 에이전트와 함께 했습니다 [E20].

## 이력서 강조
- 생성 AI와 검수 AI를 분리해 운영했습니다. 의료 조언을 넣은 가짜 대본은 차단하고 정상 대본 3편은 통과시켰으며, 검수 오탐 3건의 원인을 찾아 9/14에 기준을 수정했습니다 [E16].
- 읽기 전용 감사 에이전트 3기를 병렬로 돌려 리포트와 원본 데이터를 대조했습니다. 이 대조를 주간 자동 감사로 만들었고, 1회차 시험에서 8건을 발견해 6건을 고쳤습니다 [E17].
- 사람 승인 위치를 가역성 기준으로 설계했습니다. 비가역 결정은 사람이 고르고, 가역 변경은 이전본을 보관한 채 자동 적용 후 보고합니다. 테스트에 실패하면 자동으로 원복합니다 [E11].
- 분석 AI의 쓰기 권한을 막고, 수집·규칙·분석·실행 4칸 원칙으로 문서화했습니다. 가드가 임시 스크립트를 격리하는 것도 확인했습니다 [E19].
- 판단 없는 단계는 에이전트로 쪼개지 않고 코드에 두어 비용과 실패 지점을 줄였습니다. 이 방식으로 8/04부터 돌던 파이프라인을 유지했습니다 [E6][E7].
- (학습) LangGraph로 검수 루프, 사람 승인 후 재개, 병렬 감사 예제를 가짜 모델로 실행해 확인했습니다 [E3][E9][E25].

## 보강할 증거
- 검수 게이트의 정량 수치: 기간별 검수 건수, 차단 건수, 9/14 수정 전후의 오탐률. 공고의 hallucination rate·정확도 언어로 말하려면 이 숫자가 필요합니다.
- "역할마다 모델을 다르게, 비용은 호출마다 기록" 결정의 실제 값: 호출당 비용, 편당 비용, 파이프라인 지연시간.
- 수수료 계산 오류 "20.5%"가 무엇 대비 몇 %인지, 감사 3기를 나눈 기준, 주간 감사 2회차 이후의 발견·수정 건수.
- 9/21 이후 실제 자동 적용·원복 기록, 그리고 RAG의 실제 임베딩 모델 비교 평가셋 결과(정답 문서 검색 적중률 등).
