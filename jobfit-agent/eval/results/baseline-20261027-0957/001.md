## 자기소개서

저는 유튜브 채널 운영, 취업 정보 수집, 코인 모의투자 같은 개인 자동화 프로젝트를 클로드 코드와 함께 만들었고, 메인 PC의 윈도우 작업 스케줄러에서 매일 자동으로 운영하고 있습니다 [E1]. 대표 프로젝트인 유튜브 자동화는 트렌드 수집, Claude 대본 작성, ffmpeg 렌더링, YouTube API 업로드를 거쳐 사람이 손대지 않아도 매일 아침·저녁 쇼츠를 올립니다 [E9]. 판단 없는 단계까지 에이전트로 만들면 비용과 실패 지점만 늘어난다고 봤습니다. 그래서 LLM은 대본 작성·검수·회고처럼 판단이나 글쓰기가 필요한 칸에만 두고, 렌더링·업로드는 코드로 남겼습니다 [E27][E28]. 작성 AI와 별도로 기준표를 가진 검수 AI를 붙였습니다. 일주일 동안 생긴 재생성 3건이 모두 검수 오탐이었다는 것을 찾아, 슬롯 정보를 넘겨 기준을 나누는 방식으로 고쳤습니다 [E24][E25]. 분석 AI는 제안만 쓰게 하고, 보호 파일이 바뀌면 자동으로 되돌리는 가드를 넣었습니다. 이후 회고 AI가 다시 임시 스크립트를 만들었을 때 가드가 이를 격리하는 것을 확인했습니다 [E29][E30].

LangGraph는 langgraph 1.2.16 환경에서 시험용 가짜 모델로 학습 예제 세 가지를 실행해 봤습니다. 검수 루프, interrupt를 이용한 사람 승인 후 재개, Send를 이용한 병렬 감사 구조입니다 [E49][E58][E60][E63]. 이 과정에서 재개하면 interrupt가 있는 노드가 처음부터 다시 실행된다는 점을 확인했습니다. 따라서 그 앞에 DB 쓰기 같은 작업을 두면 두 번 실행된다는 것도 알게 됐습니다 [E61][E62]. RAG는 제 설계 문서를 대상으로 청킹을 실험했습니다. 글자 수로만 자르면 41조각 중 31조각은 어느 결정에 대한 내용인지 알 수 없었습니다 [E79]. 제목 기준 분할기는 기본 설정에서 제목을 본문에서 빼기 때문에, 키워드 검색이 정답을 놓친다는 것도 확인했습니다 [E84][E85]. 임베딩은 아직 시험용 가짜 임베딩으로 흐름만 확인한 단계입니다. 실제 임베딩 모델 비교는 평가셋으로 할 계획입니다 [E81]. 레거시 연계는 조회 도구는 바로 실행하고, 쓰기 도구는 HumanInTheLoopMiddleware로 승인 뒤에만 실행되게 한 예제로 학습했습니다. 승인 전에는 DB 값이 바뀌지 않는 것을 확인했습니다 [E99][E100][E101]. 운영에서는 YouTube API 업로드, 업비트 공개 시세, 쓰레드 API 예약 게시처럼 외부 시스템을 자동화에 연결해 왔습니다 [E9][E12][E14].

지금은 이 학습을 실제 프로젝트로 옮기고 있습니다. 공고 분석부터 경력 근거 병렬 검색, 코드 기반 적합도 계산, 초안 작성, 근거 검증, 사람 확정까지 이어지는 LangGraph·RAG 맞춤 지원서 에이전트입니다 [E4]. 2026-10-23에 첫 골격을 만들었고, 2026-10-27에 실제 모델로 공고 7개를 처음 실행했습니다 [E4]. 아직 체계적인 평가셋이 없다는 점은 약점으로 인정하고 있습니다. 평가셋을 만들어 실측하는 것을 다음 과제로 두고 있습니다 [E47]. 설계와 운영은 제가 했고 구현은 AI 코딩 도구와 함께 했습니다 [E49]. 계산과 법 규정 판정처럼 매번 같은 답이 필요한 부분은 코드로, 해석과 문장은 AI로 나누는 기준으로 에이전트를 만들겠습니다 [E33][E45].

## 이력서 강조

- 유튜브 쇼츠 완전 자동화 파이프라인을 2026-08-02부터 운영하고 있습니다. 트렌드 수집, Claude 대본, ffmpeg 렌더링, YouTube API 업로드를 거쳐 매일 2편을 올립니다 [E2][E9].
- 작성 AI와 검수 AI를 분리하고 코드 사후검사를 더해 업로드 전 대본 게이트를 만들었습니다. 일주일 재생성 3건이 모두 검수 오탐인 것을 찾아 슬롯별 기준으로 고쳤습니다 [E10][E24][E25].
- 분석 AI의 쓰기 권한을 막는 가드를 설계했습니다. 설정 해시 백업, 자동 원복, 새 파일 격리 기능을 넣었고, 이를 수집·규칙·분석·실행 4칸 원칙으로 문서화했습니다 [E6][E29][E30].
- LangGraph·RAG 기반 맞춤 지원서 에이전트를 개발하고 있습니다. 흐름은 공고 분석, 근거 병렬 검색, 코드 적합도, 초안, 근거 검증, 사람 확정 순이며, 2026-10-27에 실제 모델로 공고 7개를 처음 실행했습니다 [E4].
- LangGraph 학습 예제(검수 루프, interrupt 승인 재개, Send 병렬)를 실행했습니다. HumanInTheLoopMiddleware로 쓰기 도구만 승인 뒤 실행되게 하는 레거시 연계 예제도 실험했습니다 [E58][E60][E63][E100][E101].
- RAG 청킹과 BM25 키워드 검색을 실험해, strip_headers 설정 하나로 정답 검색 여부가 뒤집히는 것을 확인했습니다 [E84][E85].
