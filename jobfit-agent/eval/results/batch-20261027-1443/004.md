## 회사 읽기 (AI 추정)
회사 유형: 새 사업 (확신도 높음, AI 추정)
돈 버는 방식: 아정당 브랜드로 통신·렌탈 상품을 중개·판매하고 상담·개통까지 연결해 수수료/매출을 얻는 생활 솔루션 플랫폼. 이 자리는 하나의 사업을 맡아 새 서비스를 처음부터 만들어 전환·매출로 증명하는 빌더 역할
중요 지표: 전환율, 매출, 신규 서비스 출시 속도·개수, A/B 테스트 기반 개선 성과, 상담·개통 등 운영 효율(시간·비용 절감), 유입~전환 퍼널 개선
안 통하는 지표: 지연시간 단축, 모델 정확도 등 순수 기술 성능, 대규모 트래픽 처리·인프라 아키텍처 고도화, 코드 품질 자체
근거 문구: "새로운 서비스를 처음부터 만들어 띄우는 일을 중심으로 맡고" / "그 사업에 필요한 제품을 만들어 전환율, 매출 등 지표로 결과를 증명해요" / "코딩 실력보다 무엇을 왜 만들지 정하고 성과까지 이어가는 기획 역량을 가장 중요하게 봐요" / "상담과 개통 같은 뒷단 운영이 효율적으로 돌아가도록 함께 챙겨요" / "꾸준한 A/B 테스트로 가설을 검증하고 고도화해 성과를 만들어요" / "자체 브랜드 아정당을 통해 통신·렌탈 분야에서 업계 1위"

## 자기소개서

집가(ZipGa) 출시 전 마케팅에서 영상 15편을 기획했습니다 [E18]. 기획한 영상은 ComfyUI 프롬프트와 채널별 문구로 자동 생성하는 흐름으로 운영했습니다 [E18]. 일일 브리프, 경쟁사 감시, 시장 트렌드, ASO, 글쓰기, 발행을 맡는 코워크 스킬 9종을 두었고, 채널별 성과 리포트와 결정·조사·에러 기록을 남겼습니다 [E18]. 2026년 9월 초 기준으로 유튜브 티저·시연 쇼츠를 예약 발행했고, 쓰레드는 API로 8/31~9/5분을 자동 예약 게시했으며, 인스타그램은 직접 올렸습니다 [E18]. 지금은 카카오 마케팅 메시지 에이전트 market-compass를 만들고 있습니다 [E16]. 1인 셀러가 "지난달 안 온 단골한테 뭐 좀 보내줘"라고 말하면 대상 선정, 문구 생성, 규제 검사, 사람 승인 두 번, (가상) 발송까지 이어지는 에이전트입니다 [E16]. 2주 계획 중 2일차까지 진행했고, 기획과 가상 데이터를 마친 뒤 Guard 규칙 절반(테스트 24/48)을 완료했습니다 [E16][E22].

market-compass는 '자동'보다 '안 걸리게'를 핵심으로 두었습니다 [E16]. 그래서 정보통신망법·카카오 정책 위반을 코드로 검사하는 Guard(규칙 R01~R12)를 대상 판단(Radar), 발송(Dispatch)과 다른 모듈로 나눴습니다 [E16]. 숫자는 코드만 계산하고, 실측과 추정을 분리하고, 발송 경로는 한 곳뿐이라는 원칙도 세웠습니다 [E16]. 집가에서는 플랫폼 제재를 예방하려고 공개 문구·영상에서 술·음주 표현을 전면 금지하고 "모임", "늦은 밤"으로 표현합니다 [E18]. 사람의 승인을 어디에 둘지도 운영하면서 고쳤습니다 [E9]. 9월 7일부터 모든 회고 제안을 사람이 승인하게 했는데, 9월 20일 플레이북이 승인 대기로 하루 묵어 다음 날 적용 시작을 놓쳤습니다 [E9]. 비개발자인 저에게는 승인 판단 자체도 부담이었습니다 [E9]. 그래서 9월 21일부터 기준을 "되돌릴 수 있는가"로 바꿨습니다 [E9]. 되돌릴 수 있는 플레이북·프롬프트 개선은 이전본을 보관한 채 자동 적용하고, 적용 후 폰과 바탕화면으로 보고하게 했습니다 [E9][E10]. 돈이 드는 결정, 영상 삭제·공개 전환, 실전 매매 전환은 리포트에 A/B/C/D 선택지로 올라오고, 제가 "1A 2B"처럼 답해 정합니다 [E11][E12]. 품질 문제로 이미 올린 영상을 지우고 다시 올렸다가, 유튜브가 중복으로 보고 노출을 거의 주지 않은 일(16시간 조회 2회)이 있었습니다 [E9]. 이후로는 품질을 업로드 전 게이트에서만 잡고, 이미 나간 영상은 교체하지 않습니다 [E9][E11].

AI에게 맡길 일과 코드에 맡길 일은 "매번 같은 답이 나와야 하는가"로 나눴습니다 [E25]. 고정 문자열을 AI에게 쓰게 하고 AI로 검사했다가 사흘간 영상이 빠지는 루프를 겪었고, 그 뒤로 그런 부분은 코드가 붙이게 바꿨습니다 [E25]. 대본을 만드는 AI와 검사하는 AI도 나눴습니다 [E20]. 9/7~13에 나온 재생성 3건은 모두 검수 오탐이었습니다 [E20]. 원인은 고전실험형 전용인 "훅" 기준을 저녁 리스트형 대본에도 적용한 것이었고, 9/14에 슬롯 정보를 검수 AI에 넘겨 기준을 나누는 것으로 고쳤습니다 [E20]. 분석 AI는 설정과 코드를 직접 고치지 못하며, 몰래 고치면 가드가 원래대로 되돌리고 폰으로 알립니다 [E10]. 9월 6일에는 회고 AI가 만든 임시 스크립트를 이 가드가 격리하는 것을 확인했습니다 [E4].

## 이력서 강조

- 집가 출시 전 마케팅: 영상 15편을 기획하고, ComfyUI 프롬프트·채널별 문구 자동 생성과 코워크 스킬 9종으로 마케팅 자동화를 운영했습니다 [E18].
- 집가 채널 발행: 유튜브 티저·시연 쇼츠 예약 발행, 쓰레드 API 자동 예약 게시(8/31~9/5분), 인스타그램 수동 업로드로 채널별 발행을 진행했습니다 [E18].
- market-compass(개발 중): 정보통신망법·카카오 정책 규칙 R01~R12를 코드로 검사하고 사람 승인을 두 번 거치는 메시지 에이전트를 설계했습니다 [E16]. 2주 계획 중 2일차까지 Guard 규칙 절반(테스트 24/48)을 완료했습니다 [E16][E22].
- 승인 위치 재설계: 전부 승인 방식에서 적용이 하루 밀린 일을 겪은 뒤, "되돌릴 수 있는가"를 기준으로 자동 적용·보고와 사람 결정을 나눴습니다 [E9][E10].
- 사람 결정 정리: 돈·정책·채널 정체성처럼 사람이 정할 일은 추천안과 안 정하면 생기는 일을 담은 A/B/C/D 선택지로 올리도록 유튜브 회고·코인 회고·자가감사에 공통 적용했습니다 [E12].
- AI 결과 검증 기준: "매번 같은 답이 나와야 하는가"로 AI와 코드의 역할을 나눴고, 고정 문자열 누락 루프를 겪은 뒤 코드 처리로 바꿨습니다 [E25].

## 보강할 증거

- 집가 채널별 성과 리포트의 실제 숫자(조회, 유입, 클릭, 설치 등). 이 회사는 전환율·매출로 말하므로, 발행에서 유입·전환으로 이어지는 퍼널 숫자가 필요합니다.
- 실제 A/B 테스트 사례(같은 쇼츠·문구의 두 버전 비교와 결과 해석). 현재 근거의 A/B/C/D는 사람이 고르는 결정 선택지이지 실험이 아닙니다. 면접에서 A/B 테스트 경험으로 말하면 안 됩니다.
- 9/21 선조치 후보고 전환 이후 실제 자동 적용 건수와 승인 대기로 밀린 시간의 변화. 근거에 "확인 필요"로 남아 있습니다. 운영 효율 개선을 숫자로 말하려면 기록을 모아야 합니다.
- market-compass 완성·배포 후 실제 셀러가 써 본 사례와 반응(발송 대상 수, 재방문 등), 그리고 GA·SQL로 데이터를 분석해 방향을 바꾼 사례.
