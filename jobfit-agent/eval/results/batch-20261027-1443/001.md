## 자기소개서

공고의 "Legacy System과 연계 (Agent Action에 필요한)" 업무를 목표로, 레거시 DB를 에이전트 도구로 연결하는 예제를 2026-10-22에 실제로 실행해 확인했습니다 [E4]. 이 예제의 조회 도구는 자유 SQL을 받지 않고 정해진 쿼리에 파라미터만 넣으며, 조회 범위를 최대 31일로 제한하고 합계 같은 숫자는 도구가 계산하도록 했습니다 [E5]. 되돌리기 어려운 쓰기 작업인 자동 업로드 중지 도구는 사람의 승인을 받은 뒤에만 실행되도록 조회 도구와 나눴습니다 [E5]. 설치한 langgraph 1.2.16의 설명을 보고, interrupt는 재개될 때 노드 처음부터 모든 로직을 다시 실행한다는 점도 확인했습니다 [E1]. 실패하면 재시도하는 ModelRetryMiddleware와 ToolRetryMiddleware를 학습했고, 이를 해외 채널 업로드의 5회 백오프와 연결해 정리했습니다 [E12].

LangChain과 LangGraph는 langchain 1.4.7과 langgraph 1.2.16을 설치해 예제 코드를 실제로 실행하며 익혔습니다 [E3]. 실제 모델 대신 시험용 가짜 모델과 단순 함수로 구조만 확인한 학습용 예제입니다 [E3]. create_agent에 읽기 전용 도구를 붙여 실행했고, "사용자 질문 → AI의 도구 호출 결정 → 도구 결과 → AI의 최종 답"으로 이어지는 에이전트 루프를 확인했습니다 [E6]. LangGraph의 Send로 감사 작업 3개를 동시에 돌린 뒤 결과를 합쳐 보고서 작성 노드 하나로 모으는 "읽기는 병렬로, 쓰기는 하나로" 구조도 실행해 확인했습니다 [E9]. 1.0부터 create_agent가 LangGraph 위에서 돌아간다는 점을 정리했습니다 [E2]. LangFlow는 LangChain 팀 제품이 아니라 현재 IBM이 소유한 별도 오픈소스라는 점도 함께 정리했습니다 [E2].

RAG는 청킹 실험을 2026-10-22에 실제로 돌려 보며 학습했습니다 [E7]. 벡터 저장소는 데이터 양, 회사가 이미 쓰는 인프라, 필터 기능, 운영 부담을 기준으로 고른다고 정리했습니다 [E10]. 이미 Postgres를 쓰는 회사라면 pgvector를 레거시 DB 옆에 붙이기 좋다는 점도 함께 정리했습니다 [E10]. 사내 문서에는 제품 코드, 약어, 고유명사가 많습니다 [E10]. 그래서 벡터 검색과 BM25 키워드 검색을 함께 쓰는 하이브리드 검색, 넓게 뽑은 결과를 더 정확한 모델로 다시 순위 매기는 재정렬 기법을 학습했습니다 [E10]. 에이전트형 RAG 구조도 정리했습니다 [E8]. 이 구조는 검색을 도구로 주고, 관련성을 채점해 부족하면 질문을 바꿔 다시 검색하며, 검수 AI가 답의 모든 문장이 검색된 근거에 있는지 검사합니다 [E8]. 학습 문서에서는 제 자동화를 운영하는 클로드 코드가 메모리 색인을 먼저 보고 필요한 파일만 여는 방식을 "벡터 없는 색인 기반 검색"과 연결해 보았습니다 [E8]. 다만 이 방식의 효과는 측정하지 않았습니다 [E8].

## 이력서 강조

- 레거시 DB 연계 예제를 실제로 실행해 확인했습니다 [E4]. 조회 도구는 정해진 쿼리와 파라미터로 실행하고, 쓰기 도구는 사람 승인 뒤에 실행되도록 나눴습니다 [E5].
- langchain 1.4.7과 langgraph 1.2.16으로 create_agent 기반 에이전트 루프를 시험용 가짜 모델로 실행해 구조를 확인했습니다 [E3][E6].
- LangGraph Send로 감사 작업 3개를 병렬 실행하고, 결과를 보고서 작성 노드 하나로 합치는 구조를 실행해 확인했습니다 [E9].
- RAG 청킹 실험을 실제로 돌렸습니다 [E7]. 하이브리드 검색, 재정렬, pgvector 같은 벡터 검색 선택 기준도 학습했습니다 [E10].
- 검수 AI가 답의 모든 문장이 근거에 있는지 검사하는 에이전트형 RAG 구조를 정리했습니다 [E8].

## 보강할 증거

- LangFlow로 직접 만들어 본 플로우 사례 (현재 근거는 개념 정리뿐임)
