## 자기소개서

저는 유튜브 채널 운영, 앱 마케팅, 취업 정보 수집, 코인 모의투자 등 개인 자동화 프로젝트를 클로드 코드와 함께 만들었고, 메인 PC의 윈도우 작업 스케줄러로 매일 자동 실행하고 있습니다 [E1]. 설계와 운영은 제가 맡았고, 구현은 클로드 코딩 에이전트와 함께 했습니다 [E49]. 코드·설정·프롬프트는 main이 아닌 `work/<작업명>` 브랜치에서 수정하고, 검증·테스트를 통과한 뒤에만 병합합니다 [E20]. 예약 작업이 도는 중에는 병합을 거부하는 도구도 두었습니다 [E20]. 대표 프로젝트인 유튜브 자동화는 트렌드 수집, Claude 대본 생성, ffmpeg 렌더링, YouTube API 업로드까지 이어지며, 사람이 손대지 않아도 매일 아침·저녁 쇼츠가 올라갑니다 [E9].

AI 서비스를 안정적으로 돌리기 위해 LLM은 판단이나 글쓰기가 필요한 단계에만 두었습니다 [E27]. 렌더링·업로드처럼 판단이 없는 단계는 코드로 남겼습니다 [E27]. 성공 여부는 AI 출력 문구가 아니라 결과물 파일이 실제로 있는지와 종료 코드로 판정하도록 바꿨습니다 [E43]. 자동화 실패와 품질 저하 발행은 폰 푸시로 알리고, 알림이 실패해도 본 작업은 멈추지 않게 했습니다 [E44]. 대본 검수 API에 장애가 나면 통과(fail-open)시키되 코드 사후검사는 유지해 업로드가 멈추지 않게 했습니다 [E24]. 비용을 줄이려고 출력 한도를 낮췄다가 사고(thinking) 토큰 때문에 회고가 본문 0자로 실패한 적이 있습니다 [E41]. 그 뒤 한도를 24,000으로 올리고, 한도 초과는 명시적 오류로 처리해 폰 알림이 오게 고쳤습니다 [E42].

SOOP과 관련해서는 브라우저(HTML + MediaPipe)만으로 동작하는 고양이 캐릭터 '몽글이'를 만들어, OBS 윈도우 캡처로 숲(SOOP)·치지직에 송출하도록 구성한 경험이 있습니다 [E16]. 서비스 간 연계는 학습 예제로 실험했습니다 [E99][E100]. LangChain에서 읽기 도구는 바로 실행하고 쓰기 도구는 사람 승인 뒤에만 실행되게 만들었고, 승인 전에는 DB 값이 바뀌지 않는 것을 확인했습니다 [E100][E101]. 도구를 MCP 서버 하나에 모으면 여러 에이전트가 같은 방식으로 쓰고, 권한·로그·호출 제한을 한 곳에서 관리할 수 있다는 점도 학습했습니다 [E106]. 현재는 LangGraph·RAG 기반 맞춤 지원서 에이전트를 개발하고 있습니다 [E4]. 2026-10-27에는 실제 모델로 공고 7개를 처음 실행했습니다 [E4].
