## 자기소개서

유튜브 채널 운영, 앱 마케팅, 취업 정보 수집, 코인 모의투자 같은 개인 자동화 프로젝트를 클로드 코드와 함께 만들었고, 메인 PC의 윈도우 작업 스케줄러로 매일 자동 실행하고 있습니다 [E1]. 유튜브 자동화는 사람이 손대지 않아도 트렌드 수집, Claude 대본 작성과 사후검사, ffmpeg 렌더링, YouTube API 업로드를 거쳐 매일 아침·저녁 쇼츠를 올립니다 [E9]. 이 파이프라인을 에이전트 단위로 쪼개지 않았고, LLM은 대본 작성·검수·회고처럼 판단이나 글쓰기가 필요한 칸에만 두었습니다 [E27]. 슬롯 결정, 렌더링, 업로드는 코드가 맡습니다 [E27]. 작성 AI와 별개로 기준표를 가진 검수 AI를 붙였습니다 [E26]. 일주일간 재생성 3건이 모두 검수 오탐이었다는 것을 찾아내 슬롯별 기준으로 고쳤습니다 [E25][E26]. 회고 AI가 임시 스크립트를 만든 전례가 있어, 보호 파일이 바뀌면 자동으로 원복하고 새 파일은 격리하는 가드를 넣었습니다 [E29]. 9/6에 같은 일이 다시 생겼을 때 이 가드가 파일을 격리했습니다 [E29][E30].

공고의 LangChain·LangGraph 개발과 RAG 구현은 학습 단계에서 예제를 직접 실행하며 익히고 있습니다 [E49][E74]. langchain 1.4.7, langgraph 1.2.16 환경에서 시험용 가짜 모델로 세 가지 구조를 학습 예제로 실행했습니다 [E49][E58][E60][E63]. 검수 루프 갈림길, interrupt를 이용한 사람 승인 후 재개, Send를 이용한 병렬 감사입니다 [E58][E60][E63]. 이 과정에서 interrupt로 멈췄다 재개하면 노드가 처음부터 다시 실행된다는 점을 확인했습니다 [E61]. 따라서 interrupt 앞에 DB 쓰기 같은 작업을 두면 두 번 실행된다는 점도 함께 확인했습니다 [E62]. RAG는 제 설계 결정 문서로 청킹 실험을 했습니다 [E79]. 글자 수로만 자르면 41조각 중 31조각은 어느 결정에 대한 내용인지 알 수 없었습니다 [E79]. 키워드 검색(BM25) 실험에서는 제목 기준 분할기의 기본 설정이 제목을 검색 본문에서 빼서 정답을 놓쳤습니다 [E84]. 제목을 본문에 남기자 정답이 1등으로 올라왔습니다 [E84]. 다만 질문 하나로 한 실험이라 평가셋으로 다시 확인해야 합니다 [E85]. 임베딩은 시험용 가짜 임베딩으로 검색 흐름만 확인했고, 실제 임베딩 모델 비교는 평가셋으로 할 계획입니다 [E81]. 지금은 공고 분석, 병렬 경력 근거 검색, 코드 기반 적합도 계산, 근거 검증, 사람 확정으로 이어지는 LangGraph·RAG 맞춤 지원서 에이전트 jobfit-agent를 개발하고 있습니다 [E4]. 2026-10-27에 실제 모델로 공고 7개를 처음 실행했습니다 [E4].

레거시 연계도 학습 예제로 실험했습니다 [E99][E100]. 읽기 도구는 바로 실행하고, 쓰기 도구는 HumanInTheLoopMiddleware로 승인 뒤에만 실행되게 만들었습니다 [E99][E100]. 승인 전에는 DB 값이 바뀌지 않는다는 것을 확인했습니다 [E100][E101]. 예제의 조회 도구는 자유 SQL 대신 정해진 쿼리에 파라미터만 넣고, 합계는 도구가 계산하게 했습니다 [E99]. 운영 중인 자동화에는 YouTube API 업로드, 업비트 공개 시세와 뉴스 RSS 수집, 쓰레드 API 자동 예약 게시를 연결했습니다 [E9][E12][E14]. 사람 승인 위치는 "되돌릴 수 있는가"를 기준으로 정했습니다 [E39]. 되돌릴 수 있는 프롬프트 개선은 이전본을 보관한 채 자동 적용하고, 적용 후 보고합니다 [E39][E40]. 돈이 드는 결정, 영상 삭제, 실전 매매 전환은 계속 사람이 고르게 했습니다 [E40].

## 이력서 강조

- 클로드 코드와 함께 만든 유튜브 자동화(2026-08-02~), AI데일리(2026-08-03~), 코인 모의투자 봇(2026-08-21~)을 윈도우 작업 스케줄러로 매일 운영하고 있습니다 [E1][E2][E3].
- 작성 AI와 검수 AI를 분리하고, 분석 AI의 설정 수정을 자동 원복 가드로 막고, 숫자는 코드가 계산하게 하는 등 운영 중 내린 설계 결정 10개를 ADR로 정리했습니다 [E21][E22][E23].
- LangGraph 학습 예제로 검수 루프 갈림길, interrupt 승인 후 재개, Send 병렬 감사 구조를 실행해 확인했습니다 [E58][E60][E63].
- RAG 학습 실험에서 청킹 방식별 조각 수(41/13/31)를 비교했습니다 [E79]. BM25 검색에서는 분할기의 strip_headers 설정 하나가 정답 순위를 뒤집는 것을 확인했습니다 [E84][E85].
- 레거시 연계 학습 예제에서 쓰기 도구를 HumanInTheLoopMiddleware 승인 뒤에만 실행되게 만들었고, 승인 전에는 DB 값이 바뀌지 않는 것을 확인했습니다 [E100][E101].
- LangGraph·RAG 기반 맞춤 지원서 에이전트 jobfit-agent를 개발하고 있으며, 2026-10-27에 실제 모델로 공고 7개를 처음 실행했습니다 [E4].
