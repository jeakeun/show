## 자기소개서

저는 유튜브 채널 운영, 앱 마케팅, 취업 정보 수집, 코인 모의투자 같은 개인 업무를 클로드 코드와 함께 자동화했고, 메인 PC의 윈도우 작업 스케줄러에서 매일 돌리고 있습니다 [E1]. 유튜브 쇼츠 채널은 트렌드 수집, AI 대본, ffmpeg 렌더링, YouTube API 업로드, 조회수 기록, 일요일 회고로 이어지는 파이프라인으로 설계했고, 사람이 손대지 않아도 매일 아침·저녁 쇼츠가 올라갑니다 [E9]. 파이프라인을 단계마다 부서별 에이전트로 쪼개자는 안은 판단 없는 공정에 감독관만 늘리는 셈이라 기각했습니다 [E27]. 그래서 LLM은 대본 작성·검수·회고처럼 판단이나 글쓰기가 필요한 칸에만 두고, 렌더링·업로드는 코드가 맡게 했습니다 [E27]. 고정 문자열을 AI가 쓰고 AI가 검사하다가 저녁 영상이 사흘간 빠진 일도 있었습니다 [E32]. 그 뒤로는 계산, 누적 상태, 정해진 형식의 문자열은 코드가 맡고 해석과 문장은 AI가 맡도록 경계를 나눴습니다 [E33].

만든 결과는 정확도·비용·안정성 숫자로 확인하며 고쳤습니다 [E25][E41][E43]. 작성 AI와 별개로 기준표를 가진 검수 AI를 붙였는데, 9/7~13 재생성 3건이 모두 검수 오탐이었습니다 [E24][E25]. 원인을 찾아 9/14에 슬롯 정보를 검수 AI에 넘겨 기준을 나누는 것으로 고쳤습니다 [E25]. 모델은 역할의 판단 난이도에 맞춰 상위·중간·하이쿠 모델로 나눠 배정했습니다 [E41]. 모든 호출 비용을 기록해 대시보드에서 매일 운영비와 주간 분석비로 나눠 보이게 했습니다 [E41][E8]. 비용을 줄이려고 회고 출력 한도를 낮췄다가 사고 토큰 때문에 본문 0자 실패가 난 적도 있습니다 [E41]. 이후 한도 초과를 명시적 오류로 처리하고 실패하면 폰으로 알리도록 바꿨습니다 [E42]. 성공 판정도 AI가 쓴 "완료" 문구 대신 결과물 파일 실존과 종료 코드로 하게 바꿨습니다 [E43]. 사람 승인 위치는 처음에 전부 자동 반영했다가 다음엔 전부 승인으로 바꿨는데, 두 방식 모두 문제를 겪었습니다 [E39][E40]. 지금은 되돌릴 수 있는 변경은 이전본을 남기고 자동 적용 후 보고하고, 되돌릴 수 없는 결정만 사람이 고르도록 기준을 정했습니다 [E40].

흩어진 데이터를 한곳에 모으는 일도 했습니다 [E4][E8]. 유튜브 통계·API 비용·코인 매매·채용 카운트를 매일 공유 SQLite 저장소에 모으고, 모든 프로젝트를 로컬 대시보드 하나에서 보게 했습니다 [E4][E8]. 대시보드는 주간 리포트를 "다섯 살에게 설명하듯" 다시 쓴 쉬운 설명본을 먼저 보여줍니다 [E8]. 쉬운 설명본에 원문에 없는 숫자가 나오면 다시 쓰게 하는 안전장치도 두었습니다 [E8]. 프레임워크는 LangChain 1.4.7과 LangGraph 1.2.16을 설치해 학습했습니다 [E49]. 검수 루프, 사람 승인 후 재개, 병렬 감사 구조를 시험용 가짜 모델로 예제를 만들어 실행해 봤습니다 [E49][E58][E60][E63]. RAG는 제 설계 문서로 청킹과 키워드 검색을 실험했습니다 [E74][E84]. 그 결과 제목 기준 분할기의 기본 설정이 제목을 검색 대상 본문에서 빼서 정답을 놓친다는 것을 확인했습니다 [E84][E85]. 지금은 공고 분석, 경력 근거 병렬 검색, 근거 검증, 사람 확정으로 이어지는 LangGraph·RAG 기반 맞춤 지원서 에이전트를 개발하고 있습니다 [E4]. 2026-10-27에는 실제 모델로 공고 7개를 처음 실행했습니다 [E4].
