## 자기소개서

저는 유튜브 채널 운영, 취업 정보 수집, 코인 모의투자 등 개인 자동화 프로젝트를 클로드 코드와 함께 만들었고, 메인 PC의 윈도우 작업 스케줄러에서 매일 자동으로 돌리고 있습니다 [E1]. 저는 설계와 운영을 맡았고, 구현은 AI 코딩 도구와 함께 했습니다 [E49]. 대표 프로젝트인 유튜브 파이프라인은 트렌드 수집, Claude 대본 작성, ffmpeg 렌더링, YouTube API 업로드를 거쳐 사람 손 없이 매일 아침·저녁 쇼츠를 올립니다 [E9]. 운영 초기에는 AI 출력 문구로 성공을 판정하다 오판이 반복됐습니다 [E43]. 그래서 성공 판정을 결과물 파일 실존과 종료 코드로 바꾸고, 자동화 실패와 품질 저하 발행은 바탕화면 경고 파일과 폰 푸시로 알리게 했습니다 [E43][E44]. 비용 관리를 위해 역할마다 모델을 다르게 배정했습니다 [E41]. 모든 호출의 비용은 기록해 대시보드에 "매일 운영비"와 "주간 분석비"로 나눠 보여줍니다 [E41]. 한번은 비용을 줄이려고 회고 출력 한도를 10,000 토큰으로 낮췄다가 본문 0자 실패를 겪었습니다 [E41]. 상위 모델의 사고 토큰도 이 한도에 포함된다는 점을 놓친 것이 원인이었습니다 [E41]. 이후 한도를 24,000으로 올리고, 한도 초과로 멈추면 명시적 오류로 처리해 폰으로 알리게 고쳤습니다 [E42].

LLM이 들어간 실행 흐름의 안정성은 코드로 강제하는 방식으로 설계했습니다 [E10][E24]. 대본 작성 AI와 별도로 기준표를 가진 검수 AI를 붙였습니다 [E24]. 차단급 문제가 나오면 재생성하고, 2번 연속이면 예비 대본으로 바꿉니다 [E24]. 검수 API에 장애가 나면 통과시키되 코드 사후검사는 그대로 유지합니다 [E24]. 일주일 재생성 3건이 모두 검수 오탐이었다는 사실을 찾아냈고, 슬롯 정보를 검수 AI에 넘겨 기준을 나누는 방식으로 고쳤습니다 [E25]. 분석 AI는 설정을 제안만 하게 했습니다 [E29][E30]. 실행 전에는 설정·소스 파일 해시를 백업해 두고, 파일이 바뀌면 자동으로 원복하는 가드를 넣었습니다 [E29]. 이후 회고 AI가 임시 스크립트를 만든 일이 다시 생겼을 때, 가드가 이를 격리하는 것을 확인했습니다 [E29][E30]. 반대로 렌더링·업로드처럼 판단이 필요 없는 단계는 에이전트로 쪼개지 않고 코드에 두었습니다 [E27]. 비용과 실패 지점이 늘어나는 것을 피하기 위해서였습니다 [E27].

Agent Runtime의 구조는 LangGraph로 학습하고 있습니다 [E49]. 시험용 가짜 모델을 써서 세 가지 예제를 직접 실행했습니다 [E49][E58][E60][E63]. 검수 루프 갈림길, interrupt와 체크포인터를 이용한 사람 승인 후 재개, Send를 이용한 병렬 감사입니다 [E58][E60][E61][E63]. 이 과정에서 interrupt로 재개하면 노드가 처음부터 다시 실행된다는 점을 확인했습니다 [E61]. 따라서 그 앞에 DB 쓰기 같은 작업을 두면 두 번 실행된다는 함정도 정리했습니다 [E61][E62]. 제 운영 시스템과 비교하면서, 중간에 죽었을 때 이어서 하는 기능과 병렬 처리는 제 시스템에 코드로 없던 부분이라 LangGraph로 채워야 한다고 판단했습니다 [E66]. 지금은 공고 분석부터 경력 근거 병렬 검색, 근거 검증, 사람 확정까지 이어지는 LangGraph·RAG 기반 맞춤 지원서 에이전트를 개발하고 있습니다 [E4]. 2026-10-27에는 실제 모델로 공고 7개를 처음 실행했습니다 [E4].

## 이력서 강조

- 트렌드 수집부터 Claude 대본 작성, ffmpeg 렌더링, YouTube API 업로드까지 이어지는 유튜브 쇼츠 완전 자동화 파이프라인을 설계·운영하고 있습니다 [E9]. 2026-08-02부터 운영 중이며 매일 2편을 발행합니다 [E2].
- 작성 AI와 검수 AI를 분리한 업로드 전 게이트를 운영합니다 [E24]. 재생성 상한, 예비 대본 대체, 검수 API 장애 시 통과(fail-open) 처리를 넣었습니다 [E24].
- 성공 판정을 AI 출력 문구 대신 결과물 파일 실존과 종료 코드로 바꿨습니다 [E43]. 실패와 품질 저하 발행은 폰 푸시로 알립니다 [E43][E44].
- 역할별로 모델을 배정하고 모든 호출의 비용을 기록합니다 [E41]. 2026-09-07~13 기준선에서 대본 생성 비용은 주 US$3.72(호출당 약 US$0.16)로 측정됐습니다 [E42].
- 분석 AI가 운영 설정을 직접 고치지 못하도록 해시 백업 기반 자동 원복 가드를 넣었습니다 [E29]. 이후 회고 AI가 만든 임시 스크립트를 이 가드가 실제로 격리했습니다 [E30].
- (학습) LangGraph 1.2.16으로 검수 루프, interrupt 승인 재개, Send 병렬 실행 예제를 시험용 가짜 모델로 직접 실행해 구조를 확인했습니다 [E49][E58][E60][E63].
