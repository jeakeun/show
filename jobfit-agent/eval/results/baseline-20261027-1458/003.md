## 자기소개서

저는 유튜브 채널 운영, 앱 마케팅, 취업 정보 수집, 코인 모의투자 등 개인 자동화 프로젝트를 클로드 코드와 함께 만들었고, 메인 PC의 윈도우 작업 스케줄러에서 매일 자동으로 운영하고 있습니다 [E1]. 설계와 운영은 제가 맡았고, 구현은 AI 코딩 도구와 함께 했습니다 [E49]. 유튜브 대본은 사람이 보지 않고 무인으로 업로드됩니다 [E24]. 그래서 작성 AI와 별도로 기준표를 가진 검수 AI를 붙였고, 제목·의료 단어는 코드로 사후검사하게 했습니다 [E24][E26]. 검수 AI도 틀렸습니다 [E25]. 일주일 동안 재생성 3건이 모두 오탐이었고, 원인을 찾아 슬롯 정보를 검수 AI에 넘겨 슬롯별로 기준을 나누도록 고쳤습니다 [E25]. 성공 판정 방식도 바꿨습니다 [E43]. AI 출력 문구 대신 결과물 파일 실존과 종료 코드로 판정하게 했고, 자동화 실패와 품질 저하 발행은 바탕화면 경고 파일과 폰 푸시로 알리게 했습니다 [E43][E44].

비용과 신뢰성도 운영 기록을 근거로 판단해 왔습니다 [E41][E42]. 모든 API 호출의 비용을 기록하고, 판단 난이도에 맞춰 주간 분석은 Opus, 대본은 Sonnet, 검수·팩트체크는 하이쿠로 모델을 나눴습니다 [E41]. 비용을 줄이려고 회고 출력 한도를 낮춘 적이 있습니다 [E41]. 이때 사고 토큰도 한도에 포함된다는 점을 놓쳐 본문 0자 실패가 났습니다 [E41][E42]. 이후 한도를 24,000으로 올리고, 한도 초과로 멈추면 명시적 오류로 처리해 폰으로 알리게 고쳤습니다 [E42]. 회고 AI가 쓰기 권한으로 임시 분석 스크립트를 만든 전례도 있었습니다 [E29]. 그래서 실행 전에 설정·소스 파일 해시를 백업해 두고, 파일이 바뀌면 자동 원복하며 새로 생긴 파일은 격리하는 가드를 넣었습니다 [E29]. 9/6에 같은 일이 다시 생겼을 때 가드가 그 파일을 격리했습니다 [E30]. 첫 전수 감사에서는 읽기 전용 감사 에이전트 3기를 병렬로 돌려 리포트를 원본 데이터와 대조했고, 노출된 API 키와 코인봇 수수료 계산 오류를 찾았습니다 [E37].

외부 서비스 연동에서는 안정적인 연결 수단이 있는지를 기준으로 판단했습니다 [E103]. 티스토리는 오픈 API 종료를 확인한 뒤 비공식 자동화 대신 사람이 마지막 클릭을 하는 보조 모드로 두었습니다 [E102][E103]. 지금은 1인 셀러의 카카오 마케팅 메시지 발송을 돕는 에이전트 market-compass를 개발하고 있습니다 [E15]. 정보통신망법·카카오 정책 위반은 AI가 아니라 테스트가 붙은 규칙 엔진(R01~R12)으로 검사하도록 설계했고, Guard 규칙 절반을 구현해 테스트 24/48을 통과한 단계입니다 [E15][E45]. LangGraph는 검수 루프, 사람 승인 후 재개, 병렬 감사 구조를 시험용 가짜 모델로 확인하는 학습 예제를 실행해 보았습니다 [E49][E58][E60][E63]. 7개월 과정에서는 Java·Spring Boot·React·AWS를 학습했습니다 [E103].
