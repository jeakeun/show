# 예약 실행

Cowork 쪽에 걸어둔 예약 작업 두 개를 클로드 코드에서도 돌릴 수 있게 옮긴 것.

| 파일 | 무엇 | 주기 |
|---|---|---|
| `research-brief.md` | 리서치 브리프 지시문 | 매일 아침 8시 |
| `publish-video.md` | 영상 배포 지시문 | 화·금 오후 6시 |
| `run-research.bat` | 위 지시문을 실행하는 배치 파일 | |
| `run-publish.bat` | 위 지시문을 실행하는 배치 파일 | |

---

## 먼저 손으로 한 번 돌려보세요

스케줄러에 걸기 전에 반드시 직접 실행해서 되는지 확인합니다.

```
cd <프로젝트 폴더>
automation\run-research.bat
```

`automation\logs\` 안에 로그가 쌓입니다. 여기서 실패하면 스케줄러에 걸어도 실패합니다.

---

## Windows 작업 스케줄러 등록

1. `Win + R` → `taskschd.msc`
2. **작업 만들기** (기본 작업이 아니라 "작업 만들기")
3. **일반** 탭
   - 이름: `집가 리서치 브리프`
   - **"사용자가 로그온할 때만 실행"** 선택 — 로그온 여부와 무관하게 실행하면 브라우저 자동화가 동작하지 않습니다
4. **트리거** 탭 → 새로 만들기
   - 리서치: 매일, 오전 8:00
   - 배포: 매주, 화요일·금요일, 오후 6:00
5. **동작** 탭 → 새로 만들기
   - 프로그램: `automation\run-research.bat`의 전체 경로
   - **시작 위치: 프로젝트 폴더 경로** ← 이걸 비우면 실패합니다
6. **조건** 탭
   - "컴퓨터가 AC 전원일 때만 실행" 체크 해제 (노트북이면)

배포 작업도 같은 방식으로 하나 더 만듭니다.

---

## 명령 형태

배치 파일이 실제로 실행하는 것:

```
type "automation\research-brief.md" | claude -p "위 지시를 그대로 수행한다." --permission-mode dontAsk --output-format text
```

| 플래그 | 뜻 |
|---|---|
| `-p` | 헤드리스(비대화형) 실행. 한 번 처리하고 종료 |
| `--permission-mode dontAsk` | 도구 사용을 묻지 않음. **자동 실행에는 필수** |
| `--output-format text` | 일반 텍스트 출력 (`json`, `stream-json`도 가능) |

작업 디렉터리를 지정하는 전용 플래그는 없어서, 배치 파일이 `cd /d "%~dp0.."`로 프로젝트 루트로 이동한 뒤 실행합니다.

---

## 알아둘 것

**`--permission-mode dontAsk`는 도구를 자동 승인합니다.** 자동 실행이라 어쩔 수 없지만, 그래서 지시문 안에 "판단이 애매하면 하지 않는 쪽을 택한다", "게시 실패 시 재시도하지 않는다" 같은 제동 장치를 넣어뒀습니다. 지시문을 고칠 때 이 부분을 지우지 마세요.

**티스토리는 사람이 자리에 있어야 합니다.** 브라우저 자동화라 크롬이 켜져 있고 로그인돼 있어야 동작합니다. 예약 시간에 컴퓨터가 꺼져 있으면 이 채널만 실패하고 나머지는 정상 진행됩니다.

**Cowork 쪽 예약 작업과 중복 주의.** 지금 Cowork에도 같은 작업 두 개가 걸려 있습니다. 여기서 스케줄러를 켜면 **하루에 두 번 돌아갑니다.** 한쪽을 끄세요.

| 어디서 돌릴까 | 장점 | 단점 |
|---|---|---|
| Cowork 예약 작업 | 컴퓨터가 꺼져 있어도 클라우드에서 실행. 결과가 폰으로 옴 | 티스토리 브라우저 자동화가 어려움 |
| 클로드 코드 + 작업 스케줄러 | 브라우저 자동화가 자연스러움. 로컬 파일 접근이 빠름 | 컴퓨터가 켜져 있어야 함 |

리서치는 Cowork에, 배포는 로컬에 두는 것도 방법입니다. 배포는 어차피 영상 파일과 브라우저가 로컬에 있으니까요.
