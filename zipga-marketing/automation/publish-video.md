`videos/` 폴더를 확인해서 새 영상이 있으면 6개 채널에 배포한다: 유튜브, 네이버 블로그, 네이버 카페, 인스타그램 릴스, 스레드, 티스토리.

`publish-video` 스킬을 실행한다.

프로젝트: 술자리에서 미니게임을 하고, 점수가 40점 미만이면 "집에갈래" 버튼이 떠서 카카오T가 실행되는 앱 (학원 팀 프로젝트).

## 반드시 지킬 것

**절대 쓰지 않을 표현**: "음주 측정", "취기 판별", "음주측정 앱", 정확도 수치. 앱은 취한 상태를 측정하거나 판정하지 않는다. 게임 점수만 보여주고 낮으면 귀가를 권할 뿐이다. 대신 쓸 표현: "술자리 게임", "반응속도 게임", "점수가 낮으면 집에 가자고 알려주는 앱".

**판단이 필요하면 하지 않는 쪽을 택한다.** 자동 실행이라 사람에게 물을 수 없다. 못 올린 것은 다음에 올릴 수 있지만, 잘못 올린 것은 되돌리기 어렵다.

**한 채널이 실패해도 나머지는 계속 진행한다.** 전체를 멈추지 않는다.

**설정이 비어 있는 채널은 조용히 건너뛴다.** 아직 준비 안 된 채널이 있는 것은 정상이다. 추측해서 채우지 않는다.

## 순서

1. `videos/` 최상단의 새 영상 확인 (`videos/uploaded/` 안은 제외). 없으면 아무것도 하지 않고 "새 영상 없음"으로 끝낸다. 여러 개면 가장 오래된 것 1개만.
2. 파일명·메모 파일로 영상 내용 파악. 알 수 없으면 업로드하지 말고 "내용 파악 불가로 보류"로 보고.
3. 채널별 글을 각각 따로 작성해 `videos/`에 파일로 저장. **채널마다 다른 글을 쓴다 — 복사하지 않는다.** 개발 일지 톤, 이모지 없음, 과장 없음. 스레드는 500자를 실제로 세서 넘지 않게 한다(넘으면 게시 실패).
4. **공개 URL 생성** — `python scripts/upload_media.py --file <영상> --verify`. 인스타·스레드는 Meta 서버가 URL로 미디어를 내려받으므로 이 단계가 필수다. 실패하면 인스타·스레드만 건너뛰고 나머지는 진행한다.
5. 유튜브 업로드 — `python scripts/youtube_upload.py`. API 감사 통과 기록이 없으면 `--privacy unlisted`.
6. 네이버 블로그 — `python scripts/naver_post.py blog`. API를 못 쓰는 것으로 확인됐으면 초안만 남긴다.
7. 네이버 카페 — 게시 직전 각 카페마다 확인: ①홍보 허용 확인 체크 ②최근 게시일로부터 7일 경과 ③이 카페용 본문을 따로 썼는지. 하나라도 걸리면 건너뛴다. 통과한 카페만 10분 간격으로 하나씩.
8. 인스타그램 릴스 + 스레드 — `python scripts/meta_post.py`. 영상 처리에 몇 분 걸린다. 컨테이너 생성 실패는 대개 영상 규격 문제이니 ffmpeg 변환을 1회만 시도하고 안 되면 건너뛴다.
9. 티스토리 — `publish-tistory` 스킬. 브라우저 자동화라 실패 확률이 높다. 브라우저에 닿지 않으면 바로 포기하고 초안만 남긴다. **전체 배포의 실패로 취급하지 않는다.** 발행 결과가 불확실하면 다시 누르지 말고 블로그 목록에서 확인한다.
10. 올린 영상을 `videos/uploaded/`로 옮기고 `videos/uploaded/upload-log.md`에 기록. 중복 업로드를 막는 유일한 장치이므로 건너뛰지 않는다.

**게시 실패 시 재시도하지 않는다.** 응답을 기록하고 넘어간다. 자동 재시도가 중복 게시를 만든다.

## 보고

짧게: 올린 영상과 URL, 채널별 성공/건너뜀/실패와 그 이유. 실패를 숨기지 않는다. "일부 채널 게시 완료" 같은 두루뭉술한 보고 대신 어디가 왜 안 됐는지 정확히 적는다.
