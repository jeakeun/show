**확인한 것** — 로그가 `[PRE] ComfyUI-Manager` 에서 20분간 멈춰 있었음(15:47 이후 갱신 없음). 프로세스도 없었음.

**조치** — 설치 위치를 찾아 헤드리스로 직접 기동
```
D:\aivideos\ga\ComfyUI\.venv\Scripts\python.exe main.py --port 8188
  --extra-model-paths-config comfy\comfy_paths.yaml
  --output-directory <ComfyUI-Shared\output>
```

> **현재 상태**: 서버가 다시 꺼져 있음. 다음에 `영상만들기.bat` 을 누르면 자동으로 켜집니다.

### A-2. 🔴 HostBuffer.read_file_slice failed — 원인 확인됨

**증상** — 서버를 켜고 첫 영상 생성이 실패. 재시도하면 성공.

**로그 원문**
```
GetOverlappedResult failed error=1450 offset=7614143112 size=2097152
xfer_file_read: worker failed
hostbuf_read_file_slice: file read failed
RuntimeError: HostBuffer.read_file_slice failed
```

**원인** — **윈도우 오류 1450 = 시스템 리소스 부족**(ERROR_NO_SYSTEM_RESOURCES).
모델 파일이 19.5GB인데 RAM은 32GB. 모델을 디스크에서 스트리밍으로 읽는 중에
다른 프로그램이 메모리를 쓰고 있어 읽기 버퍼를 못 잡은 것. (오류 지점이 파일 7.6GB 위치)

**당시 메모리 상황** — RAM 여유 8.6GB, VRAM 여유 4.3GB. LDPlayer(안드로이드 에뮬레이터), Unity Hub, 크롬 다수 탭이 함께 실행 중이었음.

**조치** — `comfy.py` 에 **실패 시 30초 후 3회 자동 재시도**를 넣음. 실제로 재시도 1회로 복구됨.

**앞으로** — 영상 생성 전에 **LDPlayer·Unity Hub 같은 무거운 프로그램을 닫으면** 이 오류가 거의 안 납니다. 고화질(1.0MP) 생성일수록 영향이 큽니다.

## B. 내가 만든 오류 (수정 완료)

### B-1. 인스타 권한 정보를 틀리게 적었음

**무엇** — 설명서 4-4장에 필요 권한을 `instagram_basic`, `instagram_content_publish`, `pages_show_list`, `business_management` 로 적었음.

**실제** — 메타 공식 문서 확인 결과:
- `pages_read_engagement` 가 **필수인데 빠져 있었음**
- `business_management` 는 **필요 없었음**
- `pages_show_list` 는 필수가 아니라 계정 번호 조회용

**왜 생겼나** — 기억과 웹 검색 결과만으로 썼고, 공식 문서를 직접 열지 않았음.

**조치** — 공식 문서로 검증해 설명서와 `docs\조사-기록.md` 를 정정. 두 가지 연동 방식(페이스북 로그인 / 인스타그램 로그인)의 권한 이름이 다르다는 점도 추가.

**교훈** — **플랫폼 API 정보는 공식 문서를 직접 확인한다.** 블로그·검색 요약은 서로 다른 말을 함.

---

### B-2. 문서에 백스페이스 문자가 들어가 글자가 사라짐

**증상** — 설명서에 `teaser\build_assets.py` 가 `teaseruild_assets.py` 로 표시됨.

**원인** — 파이썬 문자열에서 `\b` 가 **백스페이스 제어문자**로 해석됨. `teaser\build...` 의 `\b` 가 앞 글자를 지운 것.

**조치** — 제어문자를 제거하고 `chr(92)` 로 역슬래시를 명시해 재작성.

**교훈** — 윈도우 경로를 문자열에 넣을 때 `\b` `\n` `\t` 등은 이스케이프로 해석됨. **경로는 raw 문자열이나 슬래시를 쓴다.**

---

### B-3. 한글 자동 입력에서 글자 깨짐

**증상** — 브라우저에 자동 입력할 때 `뜹니다` → `뜽니다`, `뜨면서` → `뜼면서` 로 변형.

**원인** — 브라우저 자동 입력이 한글 조합(특히 `ㄸ` + `ㅡ`)을 제대로 처리하지 못함.

**조치** — 이후 모든 한글 입력을 **클립보드 복사 → Ctrl+V** 방식으로 변경. 이후 깨짐 없음.

**주의** — 유튜브 설명란에 처음 입력했던 오타는 다시 붙여넣기로 수정 완료. **지금 올라간 설명에는 오타 없음.**

---

### B-4. 콘솔 인코딩 오류 (UnicodeEncodeError)

**증상** — 파이썬 스크립트 마지막 출력에서 `'cp949' codec can't encode character '\u2014'`.

**원인** — 윈도우 콘솔 기본 인코딩(cp949)이 em dash(—) 같은 문자를 못 씀.

**영향** — **파일은 정상 생성됐고 출력만 실패.** 결과물에는 영향 없음.

**조치** — 모든 스크립트에 `sys.stdout.reconfigure(encoding="utf-8")` 추가.

---

### B-5. 배너가 안전영역을 벗어남

**증상** — 첫 배너에서 문구와 주소가 "모든 기기에서 보이는 영역" 밖으로 나가 모바일에선 로고만 보였음.

**원인** — 로고 크기(760px)를 크게 잡아 안전영역 423px 높이를 초과.

**조치** — 로고를 430px로 줄이고, **안전영역을 넘으면 오류를 내는 검사(assert)** 를 코드에 넣음. 재발 시 즉시 발견됨.

---

### B-6. 도메인 오독

**증상** — 스크린샷의 주소를 `chwmong.com` 으로 읽어 접속 실패.

**실제** — `chwimong.com`

**조치** — DNS 조회로 후보를 검증해 정정. 이후 정상 접속.

**교훈** — 스크린샷의 작은 글씨는 추측하지 말고 **검증 후 사용**한다.
