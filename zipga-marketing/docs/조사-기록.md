# 조사 기록

자동화를 만들면서 **실제로 문서를 열어 확인한** 사실들. 추측이나 기억이 아니라 출처가 붙은 것만 적었다.

확인 시점: 2026년 8월 28일. 플랫폼 정책은 바뀌므로 몇 달 뒤에는 다시 확인해야 한다.

---

## 배포 채널별 확인 결과

| 채널 | 자동화 | 확인한 것 |
|---|---|---|
| 유튜브 | ✅ 가능 | 공식 업로드 API 있음. 단 감사 전엔 영상이 잠김 |
| 인스타그램 | ✅ 가능 | 공식 API. 로컬 파일 직접 업로드 가능 (resumable) |
| 스레드 | ✅ 가능 | 공식 API. 텍스트는 바로, **영상은 공개 URL 필요**, 500자 제한 |
| 네이버 카페 | ⚠️ 조건부 | 글쓰기 API 있음. 실전 리스크가 큼 |
| 네이버 블로그 | ⚠️ 확인 필요 | 목록엔 있으나 발급 가능 여부 미확인 |
| 티스토리 | ❌ API 없음 | **2024년 2월까지 순차 종료** |

## 1. 유튜브 — 감사를 통과해야 영상이 공개된다

**확인한 것**: 업로드 1회에 1,600 유닛, 하루 기본 할당량 10,000 → **하루 6개까지**. 주 2회는 여유롭다.

**함정**: 검증되지 않은 API 프로젝트로 올린 영상은 `privacyStatus`를 `public`으로 줘도 **비공개로 잠긴다.** 감사(audit)를 통과해야 공개된다.

→ 심사에 시간이 걸리므로 **가장 먼저 신청해야 한다.** 그전까지는 `unlisted`로 올리고 수동 전환.

출처: https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits

## 2. 인스타그램 · 스레드 — 인스타는 직접 업로드 가능, 스레드는 공개 URL 필요

> **2026-08-28 정정.** 이 문서의 원래 버전은 "Meta는 미디어를 업로드받지 않는다"고 적었으나,
> **인스타그램은 resumable upload로 로컬 파일을 직접 올릴 수 있다.** 아래로 대체한다.

Meta는 두 가지 업로드 경로를 제공한다.

| 방식 | 설명 | 공개 URL |
|---|---|---|
| `video_url` 지정 | Meta 서버가 그 URL을 cURL로 내려받음 | **필요** |
| **resumable upload** | 내 PC 파일을 `rupload.facebook.com` 으로 직접 전송 | **불필요** |

`POST /{ig-user-id}/media` 에 `upload_type=resumable` 을 넣어 컨테이너를 만든 뒤,
반환된 URI로 영상 바이트를 직접 올린다. 큰 파일·불안정한 연결을 위해 Meta가 만든 공식 경로다.

**채널별 결론**

| | 인스타그램 릴스 | 스레드 |
|---|---|---|
| 로컬 파일 직접 업로드 | **가능** (resumable) | **불가** — `video_url` 만 받음 |
| 공개 스토리지 필요 | 불필요 | **영상이면 필요** |
| 우리 구현 | `uploader/upload.py` (resumable 방식) | `uploader/upload.py` (텍스트 전용) |

`scripts/meta_post.py` 와 `scripts/upload_media.py` 는 `video_url` 방식으로 작성돼 있다.
**인스타에 쓸 때는 `uploader/upload.py` 를 쓰면 스토리지 없이 바로 올라간다.**
공개 스토리지는 **스레드에 영상을 올리고 싶을 때만** 필요하다.

**구글 드라이브·드롭박스 공유 링크는 안 된다.** 파일이 아니라 미리보기 페이지를 돌려줘서 Meta가 못 내려받는다.
스토리지가 필요해지면 Cloudflare R2(무료 10GB, S3 호환)를 쓴다.

- 출처: [Resumable Uploads — Meta](https://developers.facebook.com/docs/instagram-platform/content-publishing/resumable-uploads/)

**게시에 필요한 권한 (2026-08-28 공식 문서 확인)**

| 연동 방식 | 필요 권한 | 페이스북 페이지 |
|---|---|---|
| Instagram API **with Facebook Login** | `instagram_basic`, `instagram_content_publish`, `pages_read_engagement` | 필요 |
| Instagram API **with Instagram Login** | `instagram_business_basic`, `instagram_business_content_publish` | 불필요 |

- 앱 사용자가 페이지에 Business Manager 역할을 가지면 `ads_management`, `ads_read` 도 필요
- **PPA(Page Publishing Authorization)** 가 걸린 페이지는 권한이 맞아도 게시가 차단된다 → 미리 인증해둘 것
- 두 방식은 **권한 이름이 완전히 다르다.** 앱을 어떤 방식으로 만들었는지에 따라 골라야 한다
- 출처: [Publish Content — Meta](https://developers.facebook.com/docs/instagram-platform/content-publishing/)

**그 외 제약 (원문 유지)**

| 항목 | 인스타그램 | 스레드 |
|---|---|---|
| 게시 제한 | 24시간 100건 | 24시간 250건 |
| 계정 요구 | 프로페셔널 계정 필수 | — |
| 권한 | `instagram_business_content_publish` 등 (**앱 검수 필요**) | 액세스 토큰 |
| 방식 | 컨테이너 생성 → 처리 대기 → 게시 | 동일 (게시 전 30초 권장) |
| 지원 형식 | 릴스 | 이미지·영상·텍스트·캐러셀 |

출처:
- https://developers.facebook.com/docs/instagram-platform/content-publishing
- https://developers.facebook.com/docs/threads/posts

## 3. 네이버 — API는 있는데 실전이 문제

**확인한 것**: 네이버 오픈API 목록에 둘 다 있다.

| API | 엔드포인트 |
|---|---|
| 카페 글쓰기 | `POST https://openapi.naver.com/v1/cafe/{clubid}/menu/{menuid}/articles` |
| 블로그 글쓰기 | `POST https://openapi.naver.com/blog/writePost.json` |
| 블로그 카테고리 조회 | `GET https://openapi.naver.com/blog/listCategory.json` |

둘 다 인증이 필요하다.

**미확인**: 블로그 글쓰기 API가 **지금도 신규 발급되는지** 확인하지 못했다. 문서가 오래된 것일 수 있다. 신청해봐야 안다. 안 되면 블로그는 초안 생성까지만 자동화한다.

**실전 리스크 (카페)**: 기술적으로 되는 것과 실제로 되는 건 다르다. 대부분의 카페가 홍보 글을 금지하고, 운영자가 패턴을 금방 알아챈다. 스팸 필터에 걸리면 계정 자체가 위험하다. → 그래서 안전 규칙을 강제했다 (`docs/결정-기록.md` 결정 6).

출처: https://naver.github.io/naver-openapi-guide/apilist.html

## 4. 티스토리 — API가 없다

**확인한 것**: 티스토리 Open API가 **2024년 2월까지 순차 종료**됐다. 종료 순서는 파일 첨부 → **글 관련 기능** → 댓글 → 그 외.

→ 인터넷에 돌아다니는 티스토리 파이썬 자동 포스팅 코드는 **지금은 동작하지 않는다.** 검색하다 나와도 시도하지 말 것.

**대안**: 브라우저 자동화뿐. 크롬을 직접 조작한다. 그래서 신뢰도가 낮다 — 크롬이 켜져 있고 로그인돼 있어야 하고, 에디터 UI가 바뀌면 깨진다.

출처: https://tistory.github.io/document-tistory-apis/

## 5. 카카오T — 아직 답을 못 찾았다 (리스크 A)

**찾아본 것**: 외부 앱에서 카카오T를 여는 공식 딥링크/URL scheme이 공개돼 있다는 확인을 **하지 못했다.**

- 카카오는 카카오톡·카카오내비 등 일부 앱의 scheme은 문서화해 두었다 (카카오 데브톡에 관련 문답 있음)
- 카카오T 쪽은 **비즈니스 API**와 **파트너 프로그램** 형태로 운영되는 것으로 보인다 → 학생 팀이 파트너 승인을 받기는 어렵다

**확인해야 할 곳**:
- 카카오 데브톡 (devtalk.kakao.com) — 카카오T URL scheme 관련 문답
- 카카오 T 비즈니스 API 문서 (kakaot-biz-developers.oopy.io)
- 카카오모빌리티 파트너플레이스 (partner.kakaomobility.com)

**안 될 경우 대안**: 앱스토어/플레이스토어 페이지 열기, 웹 링크 우회, 우티·타다 등 다른 호출 앱.

**이건 발표 데모 전에 반드시 결론을 내야 한다.** 안 되면 그 자리에서 데모가 멈춘다.

## 6. 경쟁 지형 (초기 확인)

**직접 경쟁 (해외)**: Drive Sober, SoberGuardian, ENDUI 계열(주정부 배포 DUI 예방 앱)

**국내 대체재**: 안심이(서울시 안심귀가 — 공공·무료라 유료화에 압력), 카카오T 대리(음주 후 이동의 실질적 1순위)

**하드웨어 대체재**: Dräger, BACtrack 등 휴대용 음주측정기. 미국에서 차량 내 음주운전 방지 기술 의무화 입법 논의 진행 중 — 규제 트렌드로 계속 추적.

**가장 강력한 대체재**: **"그냥 친구가 챙겨주기".** 사용자 인터뷰에서 반드시 확인할 것.

**결정 3 이후 1순위로 올라온 카테고리**: 술자리 게임 앱. 우리가 판정을 안 하는 이상 사용자가 비교하는 대상은 음주측정 앱이 아니라 술게임 앱이다.

**이 시장의 근본 난제**: 앱이 없어서 비어 있는 게 아니라 **앱이 안 써져서** 비어 있을 가능성이 높다. "취하면 앱 켤 생각을 못 한다" — 경쟁 앱 리뷰에서 이 유형의 불만을 찾는 것이 VoC 조사의 핵심이다.
