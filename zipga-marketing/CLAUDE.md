# 집가(ZipGa) — 마케팅 자동화 작업 공간

클로드 코드가 이 파일을 자동으로 읽는다. **여기 적힌 내용이 모든 작업의 기본 전제다.**

---

## 제품

술자리에서 미니게임을 하고, **점수가 40점 미만이면 "집에갈래" 버튼이 떠서 카카오T가 실행되는** 앱.
학원 팀 프로젝트이고 한국 시장을 겨냥한다.

### 범위에서 뺀 것 (중요 — 리서치와 카피 양쪽에 영향)

- **"취했다"는 판정·표시를 하지 않는다.** 음주 상태를 측정·진단하지 않는다. 게임 점수만 보여주고 40점 미만이면 귀가를 권할 뿐이다. 이 앱은 측정 도구가 아니라 **술자리 게임**이다.
- 귀가 상태 공유·보호자 알림을 하지 않는다.
- 목적지 자동 입력을 하지 않는다. 카카오T를 실행하는 데까지가 범위다.

### 절대 쓰지 않을 표현

| 쓰지 않음 | 대신 |
|---|---|
| 음주 측정, 음주측정 앱 | 술자리 게임 앱 |
| 취기 판별 | 반응속도 게임 |
| 취했는지 알려주는 | 점수가 낮으면 집에 가자고 알려주는 |
| 정확도 ○○% | (쓰지 않는다) |
| 안전 보장, 사고 예방, 혈중알코올 | 무사히, 집에 가는 |

앱 안에서 판정을 안 해도 **스토어 설명문이나 홍보 문구에서 "음주 측정"이라고 쓰는 순간 같은 문제가 돌아온다.**

### 공개 SNS 발행물의 추가 규칙

플랫폼 제재를 피하기 위해 **인스타·유튜브·쓰레드에 나가는 콘텐츠**는 한 단계 더 순화한다.

- 술·음주·취함·만취 → "모임", "늦은 밤"
- 영상 프롬프트에 `No alcohol, no bottles, no drinks visible` 를 항상 포함
  (`content/generate_files.py`, `comfy/comfy.py` 가 자동으로 붙인다)
- 공개 문구 포지셔닝은 **"설치 없이 링크로 쓰는 사이트"**, 출시일은 **"곧 열립니다"** 까지만
- 출시 전 CTA는 댓글 **"점수"** / **"테스터"**

> 내부 문서·투자자 시연 자료에는 술자리 맥락을 그대로 써도 된다. **공개 발행물만** 이 규칙을 따른다.
> 내부용 영상은 `uploader/_내부용/` 에 둔다.

## 상시 추적 리스크

**A. 카카오T 실행이 가능한가 (최우선)**
외부 앱에서 카카오T를 여는 공식 딥링크/URL scheme이 공개돼 있는지 확인되지 않았다. 카카오는 카카오톡·카카오내비 scheme은 문서화했지만 카카오T는 비즈니스 API·파트너 프로그램 형태로 보인다. **발표 데모의 성패가 여기 걸려 있다.** 불가능하면 대안(스토어 페이지 열기, 웹 링크 우회, 우티·타다)을 즉시 보고한다.
> 노션의 `프로젝트_개요` 에는 "`kakaot://` 실기기 검증 완료"로 적혀 있으나 이후 조사에서 미확인으로 뒤집혔다. **실기기로 다시 확인할 것.**

**B. 40점 컷오프의 근거**
심사에서 거의 확실히 나오는 질문이다. 반응속도·인지 저하 연구를 모으되 **컷오프 설계 참고용이지 "우리 앱이 정확하다"는 근거가 아니다.** 안전한 표현: *"반응속도가 떨어진 상태에서는 판단력도 흐려진다는 연구가 있고, 40점은 그 구간을 잡기 위한 기준선입니다."*
역방향 리스크 — 40점을 넘었다고 "안전하다"는 신호를 주면 오히려 위험하다. 통과 화면 표현이 UX 과제로 남아 있다.

**C. 팀원 계정 간 상호작용**
코드로 못 막는다. 규칙으로만 관리한다. 서로 좋아요·팔로우하면 일곱 계정이 한꺼번에 묶인다.

## 폴더 구조

이 폴더는 **두 갈래**가 합쳐져 있다. 둘 다 같은 제품을 위한 것이다.

```
[콘텐츠 파이프라인 — 영상 만들어 올리기]
run.py                M1~M6 관통 실행
m1_input ~ m6_queue/  모듈 코드 (1인 1모듈, 자기 폴더만 수정)
config.json           앱 이름·발행 슬롯·해시태그
accounts/*.json       계정별 각도(훅)·핸들
prompts/*.txt         마케팅 문구 템플릿 (코드 수정 없이 톤 변경)
content/              영상 15개 기획 + 생성 프롬프트 + 업로드 문구
comfy/                콤피 자동 연결 (서버 자동 기동 + 영상 생성)
uploader/             원클릭 업로더 (watch/ → 유튜브·인스타·쓰레드)
data/                 모듈 간 공유 파일 (자동 생성)

[리서치·다채널 배포 — 코워크에서 넘어온 것]
.claude/skills/       스킬 9개 (리서치 5 + 배포 4)
context/              설정 4개 — 여기만 고치면 모든 스킬에 반영
scripts/              유튜브·네이버·메타 업로드 스크립트
automation/           예약 실행 지시문과 배치 파일
reports/              리서치 PDF 산출물
videos/               스킬이 참조하는 영상 폴더
cowork-plugins/       Cowork용 플러그인 원본 (보관용)
docs/                 결정 기록·조사 기록
```

**영상 위치 주의** — 콤피 파이프라인은 완성본을 `uploader/watch/` 에 넣는다.
배포 스킬은 `videos/` 를 참조하므로, 스킬로 배포할 때는 해당 파일을 `videos/` 로 복사한다.

## 채널별 발행 방식

| 채널 | 방식 | 주의 |
|---|---|---|
| 유튜브 | Data API `videos.insert` | **감사 전에는 영상이 비공개로 잠김** · 예약 발행 내장 |
| 인스타 릴스 | Graph API **resumable upload** | **로컬 파일 직접 업로드 가능 — 공개 URL 불필요** · 앱 검수 + 프로페셔널 계정 필요 |
| 쓰레드 | Threads API | 텍스트는 바로. **영상만 공개 URL 필요** · 500자 제한 · DM API 없음 |
| 네이버 블로그 | 오픈 API | 발급 가능 여부 미확인 · 티스토리와 같은 글 금지 |
| 네이버 카페 | 글쓰기 API | **실전 리스크 최대** — 결정 6의 안전 규칙 강제 |
| 티스토리 | 브라우저 자동화 | **Open API 종료됨** · 실패해도 나머지 채널은 진행 |

> `scripts/meta_post.py` 와 `scripts/upload_media.py` 는 `video_url`(공개 URL) 방식이다.
> **인스타는 `uploader/upload.py` 를 쓰면 스토리지 없이 바로 올라간다.** 자세한 건 `docs/조사-기록.md` §2.

## 일하는 원칙

1. **출처 없는 숫자를 쓰지 않는다.** 못 찾았으면 "확인 실패"로 남기고 추정치로 메우지 않는다.
2. **인용문은 원문 그대로.** 사용자가 쓴 표현이 곧 카피의 재료다. 맞춤법도 고치지 않는다.
3. **채널마다 다른 글을 쓴다.** 복붙하면 카페는 스팸 판정, 블로그·티스토리는 중복 콘텐츠로 양쪽 손해.
4. **같은 영상 파일을 여러 계정에 올리지 않는다.** 영상 지문으로 감지된다. 계정마다 seed를 바꿔 새로 생성.
5. **판단이 애매하면 하지 않는 쪽.** 못 올린 것은 다음에 올릴 수 있지만 잘못 올린 것은 되돌리기 어렵다.
6. **게시 실패 시 재시도하지 않는다.** 자동 재시도가 중복 게시를 만든다.
7. **분량을 채우려고 내용을 늘리지 않는다.** 변화 없는 날의 리포트는 1페이지로 끝낸다.
8. **공개 댓글 답글은 사람이 보낸다.** DM은 자동 가능(1:1·사용자가 먼저 요청). 공개 댓글 자동 응답은 계정이 죽는 지름길.
9. **팀원 계정끼리 팔로우·좋아요·댓글 금지.**

## 예약 작업

같은 작업이 **두 군데에 존재한다.** 둘 다 켜면 하루에 두 번 돌아가므로 한쪽만 쓴다.

| 작업 | 주기 | Cowork | 로컬 |
|---|---|---|---|
| 리서치 브리프 | 매일 아침 8시 | 등록됨 | `automation/run-research.bat` |
| 영상 배포 | 화·금 오후 6시 | 등록됨 | `automation/run-publish.bat` |

**권장 조합** — 리서치는 Cowork(컴퓨터 꺼져 있어도 돌고 폰으로 결과가 옴), 배포는 로컬(티스토리 브라우저 자동화·영상 파일 접근).
Cowork 예약 작업은 클로드 코드에서 관리할 수 없다. **Cowork 앱에서 직접 끄고 켠다.**

배포를 로컬 스케줄러에 걸기 전에 `automation\run-publish.bat` 을 손으로 한 번 돌려본다.
