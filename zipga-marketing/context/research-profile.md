# 리서치 프로필

모든 리서치 스킬이 조사 범위를 좁힐 때 참조하는 기준 문서. 프로젝트 상황이 바뀌면 이 파일만 고치면 된다.

---

## 1. 제품 정의

**한 줄 정의**: 술자리에서 미니게임을 하고, 점수가 40점 미만이면 "집에갈래" 버튼이 뜨고, 누르면 카카오T 앱이 실행되는 모바일 앱.

**핵심 기능 축**
| 축 | 내용 | 리서치 시 주목할 점 |
|---|---|---|
| 미니게임 | 반응속도·터치 정확도를 재는 게임. 점수만 나온다 | 게임 자체가 재미있어야 성립한다. 술자리 게임 앱의 게임 설계를 본다 |
| 40점 컷오프 | 40점 미만이면 귀가 동선으로 넘어간다 | **왜 하필 40점인가**에 답할 근거. 반응속도 저하 관련 연구 자료 |
| 소셜/게임성 | 여럿이 술자리에서 함께 플레이 | 재미 요소가 실제 리텐션으로 이어지는지 |
| 귀가 연결 | "집에갈래" 버튼 → 카카오T 앱 실행 | 외부 앱에서 카카오T를 호출하는 공식 방법이 있는지 (아래 5번 참조) |

**범위에서 제외한 것** (리서치 대상 아님, 다만 경쟁 앱이 하고 있으면 기록은 한다)
- **"취했다"는 판정·표시를 하지 않는다.** 앱은 음주 상태를 측정하거나 진단하지 않는다. 게임 점수만 보여주고, 낮으면 귀가를 권할 뿐이다. 이건 단순한 문구 차이가 아니라 제품의 성격을 정하는 결정이다 (아래 5번 리스크 B 참조).
- 보호자 알림 / 귀가 상태 공유 — 하지 않는다. 따라서 위치 추적·프라이버시 동의 관련 리서치는 우선순위를 낮춘다.
- 목적지 자동 입력 — 카카오T를 실행하는 데까지가 우리 범위. 그 다음은 카카오T가 처리한다.

**타겟 사용자**: 20~30대, 회식·모임에서 술을 마시는 한국 사용자. 1차 페르소나는 "일행 중 취한 친구를 챙겨야 하는 사람".

**포지셔닝 가설**: 음주측정기도 아니고 금주 앱도 아닌, **술자리에서 하는 게임인데 결과가 귀가로 이어지는 앱**. 측정 도구가 아니라 게임으로 자리 잡는 것이 핵심.

## 2. 업종 분류

리서치할 때 이 카테고리들의 교집합에서 자료를 찾는다. 하나의 업종에만 묶이지 않는 것이 이 제품의 특징이자 리서치 난이도.

| 계층 | 분류 |
|---|---|
| 대분류 | 모바일 앱 서비스 (B2C) |
| 앱스토어 카테고리 | 라이프스타일 / 건강·피트니스 / 소셜 (경쟁 앱마다 다르게 등록되어 있음 — 어디에 등록할지가 ASO 의사결정 포인트) |
| 시장 카테고리 1 | 음주 안전 · 음주운전 방지 (Drinking safety / DUI prevention) |
| 시장 카테고리 2 | 안전 귀가 · 개인 안전 (Safe ride home / Personal safety) |
| 시장 카테고리 3 | 모빌리티 연동 서비스 (택시 호출 딥링크) |
| 인접 시장 | 디지털 헬스(음주 절제 앱), 소셜 파티 게임 앱, 음주측정기 하드웨어 |

**리서치 시 유의**: "음주 앱"으로만 검색하면 금주·절주 앱(Drinkaware, Sunnyside 등)만 잡힌다. 반드시 안전 귀가·판별·모빌리티 축을 같이 걸어서 검색할 것.

## 3. 경쟁 지형 (초기 목록 — 리서치하며 갱신)

### 직접 경쟁 (취기 판별 + 귀가 유도)
| 서비스 | 지역 | 메모 |
|---|---|---|
| Drive Sober | 미국 | 반응 테스트 기반 운전 가능 여부 판단 |
| SoberGuardian | 미국 | 음주 상태 자가 점검 + 귀가 지원 |
| ENDUI / R-U-Buzzed 계열 | 미국 (주정부 배포) | BAC 추정 + 택시 호출 연결. 공공 캠페인 앱 |

### 간접 경쟁 (안전 귀가)
| 서비스 | 지역 | 메모 |
|---|---|---|
| 안심이 (서울시) | 한국 | 공공 안심귀가 서비스. 무료·공공이라는 점이 우리 앱의 유료화에 압력 |
| 카카오T / 타다 / 우버 | 한국 | 택시 호출 자체. 우리는 경쟁이 아니라 **연동 대상**에 가까움 |
| 카카오T 대리 | 한국 | 음주 후 이동의 실질적 1순위 대안 |

### 대체재 (다른 방식으로 같은 문제 해결)
- 휴대용 음주측정기 (Dräger, BACtrack 등 하드웨어)
- 차량 내 음주운전 방지 장치 (미국 의무화 입법 논의 진행 중 — 규제 트렌드로 계속 추적)
- 그냥 친구가 챙겨주기 (가장 강력한 대체재. 사용자 인터뷰에서 반드시 확인할 것)

### 술자리 게임 앱 (판정을 뺀 뒤 **비중이 크게 올라간 카테고리**)

우리 앱이 "측정 도구"가 아니라 "게임"이 된 이상, 사용자가 우리를 비교하는 대상은 음주측정 앱이 아니라 술자리 게임 앱이다. 매주 이 카테고리를 확인한다.

- 국내 술자리 게임 앱(구글플레이·앱스토어 "술게임" 검색 상위) — 어떤 게임이 실제로 술자리에서 살아남는지
- 반응속도·순발력 계열 캐주얼 게임 — 우리 미니게임의 직접 참고 대상
- 확인할 것: 게임이 몇 초짜리인지, 여러 명이 폰 하나로 돌려 쓰는지 각자 폰인지, 취한 사람이 조작할 수 있는 난이도인지

### 기타 참고
- Sunnyside, Drinkaware — 음주 데이터 UX 참고 (우선순위 낮음)

## 4. 키워드 시드

리서치·ASO 스킬이 확장의 출발점으로 쓰는 목록.

**한국어** (게임 축을 앞에 둔다 — 우리는 게임으로 발견되어야 한다)
술게임 / 술자리 게임 / 술자리 게임 앱 / 음주 게임 앱 / 반응속도 게임 / 순발력 테스트 / 회식 게임 / 술자리 벌칙 / 안전 귀가 / 대리운전 부르기 / 택시 호출 앱 / 만취 / 회식

**쓰지 않을 키워드**: "음주 측정", "취기 판별", "음주측정기" — 하드웨어 수요와 섞이고, 우리가 측정을 한다는 인상을 준다. 판정을 하지 않기로 한 결정과 어긋나므로 ASO에서 제외한다.

**영어**
drunk test app / sobriety test app / am i drunk / reaction time alcohol / safe ride home app / DUI prevention app / drinking game app / BAC estimate app

**롱테일 후보 (검증 대상)**
"친구 술 취했을 때 / 취한 사람 집 보내기 / 술자리 벌칙 게임 / 회식 후 귀가"

## 5. 조사에서 항상 확인할 질문

리서치 결과가 정보 나열로 끝나지 않게, 매번 아래 질문에 답하는 형태로 정리한다.

1. 우리가 하려는 걸 이미 하고 있는 곳이 있나? 있다면 왜 크지 못했나?
2. 사용자가 실제로 불편해하는 지점은 무엇인가? (리뷰·커뮤니티 원문 인용)
3. 규제·정책이 우리에게 유리한가 불리한가?
4. 지금 이 주에 새로 생긴 변화는 무엇인가?
5. 그래서 우리 팀이 이번 주에 뭘 해야 하나?

### 상시 추적 리스크 2가지

기능 범위가 확정되면서 아래 두 가지가 프로젝트의 실질적 위험 요소가 되었다. 관련 소식이 보이면 **최우선으로** 리포트에 올린다.

**리스크 A — 카카오T 실행이 기술적으로 가능한가**
외부 앱에서 카카오T를 여는 공식 딥링크나 URL scheme이 공개되어 있는지 아직 확인되지 않았다. 카카오는 카카오톡·카카오내비 등 일부 앱의 scheme은 문서화해 두었고, 카카오T 쪽은 비즈니스 API와 파트너 프로그램 형태로 운영되는 것으로 보인다. 확인할 것:

- 카카오 데브톡(devtalk.kakao.com)에 카카오T URL scheme 관련 질문·답변이 있는지
- 카카오 T 비즈니스 API 문서에 외부 앱 호출이 포함되는지, 개인 개발자도 쓸 수 있는지
- 안 되면 대안: 앱스토어/플레이스토어 페이지 열기, 웹 링크로 우회, 또는 우티·타다 등 다른 호출 앱

**이 항목은 발표 데모의 성패를 가른다.** 못 여는 것으로 확인되면 즉시 대안과 함께 보고한다.

**리스크 B — 측정 도구로 오인될 소지 (판정 문구를 뺀 뒤 크게 낮아짐)**
"취함" 판정을 제거하면서 이 리스크의 대부분이 해소되었다. 앱은 게임 점수만 보여주므로 음주 상태를 측정·진단한다고 주장하지 않는다. 다만 완전히 사라진 것은 아니므로 아래를 계속 본다.

- **마케팅 문구가 판정을 되살릴 수 있다.** 앱 안에서 "취함"이라고 안 해도 스토어 설명문이나 홍보에서 "음주 측정", "취기 판별"이라고 쓰면 같은 문제가 돌아온다. 카피를 쓸 때 이 선을 지킨다.
- 경쟁 앱들의 면책 문구(disclaimer)를 원문 그대로 수집한다. 우리는 판정을 안 하므로 필요성이 줄었지만, 어디까지 방어선을 치는지는 참고할 가치가 있다.
- 역방향 리스크: 40점을 넘었다고 "안전하다"고 읽히면 오히려 위험을 키운다. 게임 결과 화면이 통과를 어떻게 표현하는지가 UX 과제다. 경쟁 앱이 이 문제를 어떻게 푸는지 관찰한다.

**리스크 C — 40점이라는 컷오프의 근거**
심사에서 거의 확실히 나올 질문이다. "왜 40점인가?" 답할 재료를 모은다.

- 혈중알코올농도와 반응속도·인지 능력 저하의 상관관계 연구 (논문, 대학 연구 보도자료)
- 스마트폰 반응속도 테스트로 음주 상태를 추정한 선행 연구
- 경쟁 앱들이 자기 임계값을 어떻게 설명하는지

주의: 이 자료를 모으는 목적은 **컷오프를 설계할 참고 자료**이지, "우리 앱이 과학적으로 정확하다"고 주장하기 위한 게 아니다. 판정을 안 하기로 한 결정과 모순되지 않게 쓴다. 발표에서는 "게임 점수가 낮으면 판단력이 흐려진 상태일 가능성이 높다는 연구가 있다" 정도가 안전한 선이다.

## 6. 프로젝트 맥락

학원 팀 프로젝트. 즉, 다음 제약을 리서치 결론에 반영한다.

- **기간이 짧다** → 광범위한 시장 조사보다 "발표에서 근거로 쓸 수 있는 자료"가 우선
- **개발 인력이 적다** → 경쟁 앱의 기능 전부가 아니라 MVP에 넣을 1~2개를 가르는 근거가 필요
- **심사·발표가 있다** → 인용 가능한 출처(뉴스, 통계, 논문, 공공자료)가 붙은 자료가 가치가 높다. 출처 없는 추정치는 리포트에 넣지 않는다.
