## 2. 제품 한 줄 (모든 글의 기준)

술자리에서 미니게임을 하고, 점수가 40점 미만이면 "집에갈래" 버튼이 떠서 카카오T가 실행되는 앱.

**글을 쓸 때 지킬 선** (리서치 플러그인의 결정과 일치시킨다)

- "음주 측정", "취기 판별", "음주측정 앱"이라고 쓰지 않는다. 앱은 취한 상태를 측정하거나 판정하지 않는다.
- 쓸 수 있는 표현: "술자리 게임", "반응속도 게임", "점수가 낮으면 집에 가자고 알려주는 앱"
- 40점 컷오프를 과학적 정확도로 포장하지 않는다.

이 선을 넘으면 앱이 측정 도구로 오인되고, 판정을 빼기로 한 결정이 무의미해진다.

## 3. 배포 채널

### 유튜브
| 항목 | 값 |
|---|---|

| 공개 설정 | `public` — 단, API 프로젝트 감사를 통과하기 전에는 비공개로 잠긴다 (README 참조) |

| 항목 | 값 |

| 카페명 | clubid | menuid | 게시판 | 홍보 허용 여부 확인 | 최근 게시일 |
|---|---|---|---|---|---|
| (미설정) | | | | ☐ 확인함 | |

### 인스타그램 · 스레드

두 채널은 **미디어를 직접 업로드받지 않는다.** 공개 URL을 주면 Meta 서버가 그걸 내려받는 방식이다. 그래서 게시 전에 영상을 공개 스토리지에 올리는 단계가 반드시 들어간다.

| 항목 | 값 |
|---|---|
| 스토리지 | Cloudflare R2 권장 (무료 10GB, S3 호환) |
| 공개 주소 | `(미설정)` |
| 인스타 게시 형식 | 릴스 (REELS) |
| 캡션 길이 | 인스타 2,200자 이내, 스레드 500자 이내 |
| 게시 제한 | 인스타 24시간 100건 / 스레드 24시간 250건 — 주 2회에는 무관 |

**구글 드라이브·드롭박스 공유 링크는 쓸 수 없다.** 파일이 아니라 미리보기 페이지를 돌려주기 때문에 Meta가 내려받지 못한다.

영상 규격이 맞지 않으면 컨테이너 생성 단계에서 실패한다. 콤피 출력이 세로 영상이 아니거나 코덱이 다르면 ffmpeg으로 변환한 뒤 올린다.

### 티스토리

| 항목 | 값 |
|---|---|
| 블로그 주소 | `(미설정)` |
| 게시 방식 | **브라우저 자동화** — Open API가 2024년 2월 종료되어 API가 없다 |
| 신뢰도 | 낮음. 크롬이 켜져 있고 로그인돼 있어야 하며, 에디터 UI가 바뀌면 깨진다 |

티스토리는 "되면 좋고, 안 되면 초안만 남기는" 채널로 다룬다. 실패해도 다른 채널 게시는 계속 진행한다.

## 4. 카페 게시 안전 규칙 (반드시 지킨다)

카페 자동 게시는 계정 정지·강퇴로 이어질 수 있다. 아래는 선택이 아니라 필수다.

1. **홍보 허용 게시판에만 올린다.** 각 카페의 게시판 규칙을 사람이 직접 읽고 위 표의 체크박스를 채운 뒤에만 대상에 넣는다. 확인 안 된 카페는 건너뛴다.
2. **같은 글을 여러 카페에 복사하지 않는다.** 카페마다 본문을 새로 쓴다. 동일 본문 복붙이 스팸 판정의 1순위 신호다.
3. **한 카페당 주 1회를 넘기지 않는다.** 위 표의 "최근 게시일"을 확인하고, 7일이 안 지났으면 건너뛴다.
4. **한 번에 여러 카페에 연속 게시하지 않는다.** 카페 간 최소 10분 간격을 둔다.
5. **글이 홍보만 있으면 안 된다.** 개발 과정, 삽질 기록, 배운 것 같은 읽을거리가 본문의 절반 이상이어야 한다. 앱 얘기는 마지막에 짧게.
6. **오류가 나면 재시도하지 않는다.** 실패는 실패로 기록하고 사람에게 알린다. 자동 재시도가 중복 게시를 만든다.

규칙을 어길 상황이면 **게시하지 말고 사람에게 물어본다.**

## 5. 글 톤

학원 팀 프로젝트를 하는 학생이 개발 과정을 기록하는 톤. 마케팅 문구가 아니라 개발 일지에 가깝게.

- 1인칭 복수("저희 팀은")
- 과장 없음. "혁신적인", "게임 체인저" 같은 표현 금지
- 잘 안 된 것도 쓴다. 그게 읽히는 글이 된다
- 이모지는 쓰지 않는다
- 분량: 블로그 800~1,200자, 카페 500~800자
