# 배포 자동화 최초 설정

자동 배포가 돌기 전에 한 번 해야 하는 준비. 순서대로 진행하고, 각 단계를 **실제로 검증한 뒤** 다음으로 넘어간다.

사용자에게 안내할 때는 파일 경로나 스키마 얘기를 하지 말고, 무엇을 어디서 받아와야 하는지만 평범한 말로 설명한다.

## 순서

### 1단계 — 영상 폴더 연결

콤피 출력 폴더가 Claude 데스크톱 앱에 연결되어 있어야 한다. `get_device_info`로 연결된 폴더를 확인한다.

없으면 사용자에게 데스크톱 앱에서 콤피 출력 폴더를 추가해달라고 요청한다. 이게 안 되면 나머지는 진행할 수 없다.

폴더가 연결되면 `context/publish-profile.md`의 1번 표에 폴더 이름을 기록한다.

### 2단계 — 유튜브 인증

사용자에게 안내할 것:

1. Google Cloud Console에서 프로젝트를 만들고 **YouTube Data API v3**를 켠다
2. OAuth 동의 화면을 구성한다 (외부, 테스트 사용자에 본인 계정 추가)
3. 사용자 인증 정보에서 **데스크톱 앱** 유형의 OAuth 클라이언트 ID를 만들고 JSON을 내려받는다
4. 그 파일을 영상 폴더에 `client_secret.json` 이름으로 둔다

그다음 사용자 컴퓨터에서 인증을 1회 실행한다. 브라우저가 열리므로 사용자가 직접 해야 한다.

```
pip install google-api-python-client google-auth-oauthlib google-auth-httplib2
python3 youtube_upload.py --file <아무 영상> --title "테스트" --dry-run
```

`token.json`이 생기면 성공이다.

**여기서 반드시 짚고 넘어갈 것 — 영상이 비공개로 잠기는 문제**

검증되지 않은 API 프로젝트로 업로드한 영상은 `privacyStatus`를 `public`으로 줘도 비공개로 잠긴다. 감사(audit)를 통과해야 공개가 된다.

- 감사 신청 안내: https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits
- 심사에 시간이 걸리므로 **가장 먼저 신청해두라고 사용자에게 알린다**
- 그 전까지는 `--privacy unlisted`로 올리고, 공개 전환은 수동으로 하는 편이 낫다

이 사실을 사용자에게 반드시 설명한다. 모르고 있다가 "업로드는 됐는데 아무도 못 보는" 상황이 생기면 안 된다.

### 3단계 — 네이버 인증

1. 네이버 개발자센터에서 애플리케이션 등록
2. 사용 API에 **네이버 블로그**와 **카페** 추가
3. 로그인 오픈API(OAuth 2.0)로 액세스 토큰 발급
4. 토큰을 환경변수 `NAVER_ACCESS_TOKEN`에 넣는다

**블로그 API는 발급이 되는지 먼저 확인한다.** 오픈API 목록에는 블로그 글쓰기가 올라와 있지만 문서가 오래됐을 수 있다. 신규 신청이 막혀 있으면 블로그는 자동화 대상에서 빼고 초안 생성까지만 하도록 프로필을 수정한다. 되는 것처럼 가정하고 진행하지 않는다.

검증:

```
python3 naver_post.py blog --title "테스트" --content "테스트" --dry-run
```

dry-run이 아닌 실제 게시는 **비공개 테스트 글로 1회만** 해보고, 성공하면 지운다.

### 4단계 — 카페 목록 채우기

이 단계는 사람이 판단해야 한다. 자동으로 채우지 않는다.

각 카페마다 사용자에게 확인한다:

- 카페 주소와 clubid (카페 관리 페이지나 API로 조회)
- 어느 게시판에 올릴 것인지 (menuid)
- **그 게시판이 홍보 글을 허용하는지 직접 읽고 확인했는지**

세 번째를 확인하지 못한 카페는 목록에 넣지 않는다. 사용자가 "일단 넣어두자"고 해도 넣지 않는다 — 강퇴당하면 되돌릴 수 없다.

확인된 것만 프로필 3번 표에 기록한다.

### 4.5단계 — 공개 스토리지 (인스타·스레드의 전제 조건)

인스타그램과 스레드는 미디어를 직접 업로드받지 않는다. 공개 URL을 주면 Meta 서버가 내려받는다. 이 단계를 건너뛰면 두 채널은 아예 동작하지 않는다.

**Cloudflare R2를 권한다.** 무료 10GB, S3 호환. 다른 S3 호환 스토리지도 된다.

1. Cloudflare에서 R2 버킷을 만든다
2. 버킷에 **공개 접근**을 켜고 공개 주소(`pub-xxxx.r2.dev`)를 확인한다
3. API 토큰(Access Key / Secret Key)을 만든다
4. 환경변수 `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_PUBLIC_BASE`를 채운다

검증:

```
pip install boto3
python3 upload_media.py --file <아무 영상> --verify
```

`--verify`가 통과해야 한다. 여기서 실패하면 인스타·스레드는 절대 안 된다.

**구글 드라이브·드롭박스 공유 링크로 대신하려 하지 않는다.** 파일이 아니라 미리보기 페이지를 돌려줘서 Meta가 내려받지 못한다. 사용자가 이걸 제안하면 왜 안 되는지 설명한다.

### 4.6단계 — 인스타그램 · 스레드 인증

인스타그램:
1. 계정을 **프로페셔널 계정**으로 전환 (개인 계정은 API 게시가 안 된다)
2. Meta 개발자에서 앱 생성, Instagram Graph API 추가
3. `instagram_business_content_publish` 권한 요청 — **앱 검수가 필요하다. 시간이 걸리므로 먼저 신청한다**
4. IG User ID와 액세스 토큰을 환경변수에 넣는다

스레드:
1. Meta 개발자에서 Threads API 사용 설정
2. 사용자 ID와 액세스 토큰을 환경변수에 넣는다

검증:

```
python3 meta_post.py threads --text "테스트" --dry-run
python3 meta_post.py instagram --video-url "<공개URL>" --caption "테스트" --dry-run
```

dry-run 통과 후, 실제 게시는 **스레드 텍스트 글 1건으로만** 시험하고 지운다. 인스타는 실제 릴스가 올라가므로 리허설에서 확인한다.

### 4.7단계 — 티스토리

API가 없으므로 브라우저 자동화를 쓴다. 설정할 것은 두 가지뿐이다.

1. 티스토리 블로그 주소를 프로필에 기록
2. 크롬에 티스토리가 로그인된 상태인지 확인

**사용자에게 반드시 알릴 것**: 티스토리는 크롬이 켜져 있고 로그인돼 있어야만 동작한다. 예약 실행 시간에 컴퓨터가 꺼져 있으면 실패한다. 그래서 다른 채널보다 성공률이 낮고, 실패하면 초안만 남긴다.

### 5단계 — 첫 실행 리허설

실제 영상 1개로 전체 흐름을 dry-run으로 돌려본다. 업로드도 게시도 하지 않고, 만들어질 제목·설명·본문을 사용자에게 보여주고 승인받는다.

승인 후에야 자동 실행을 켠다.

## 완료 조건

아래가 전부 참일 때만 설정 완료로 본다. 하나라도 비면 무엇이 남았는지 알려준다.

- [ ] 영상 폴더가 연결되어 있다
- [ ] `token.json`이 생성되었고 dry-run이 통과한다
- [ ] 유튜브 API 감사를 신청했거나, 신청 전까지 unlisted로 올리기로 합의했다
- [ ] 네이버 토큰이 동작하고, 블로그 API 사용 가능 여부가 확인되었다
- [ ] 카페 목록의 모든 항목에 홍보 허용 확인 체크가 되어 있다
- [ ] 공개 스토리지 `--verify`가 통과한다
- [ ] 인스타 프로페셔널 전환과 권한 검수를 신청했다
- [ ] 스레드 dry-run이 통과한다
- [ ] 티스토리의 한계를 사용자가 이해하고 있다
- [ ] 리허설을 사용자가 승인했다

일부만 끝났어도 **된 채널만 먼저 돌릴 수 있다.** 인스타 앱 검수처럼 시간이 걸리는 항목을 기다리느라 전체를 멈추지 않는다. 프로필에서 아직 준비 안 된 채널은 비워두면 배포 스킬이 알아서 건너뛴다.
