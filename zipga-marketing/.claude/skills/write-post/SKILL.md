# 영상에 맞는 글 쓰기

영상 하나에서 유튜브 설명문, 네이버 블로그 글, 카페 글을 만든다. 채널마다 다른 글을 쓴다.

## 시작하기 전에

`context/publish-profile.md`의 2번(제품 한 줄과 지킬 선)과 5번(글 톤)을 읽는다.

영상 내용을 파악한다. 파일명, 함께 있는 메모 파일, 사용자가 준 설명을 쓴다. **영상 내용을 모르면 추측해서 쓰지 말고 사용자에게 무엇을 담은 영상인지 물어본다.** 잘못된 설명이 붙은 채로 올라가면 되돌리기 번거롭다.

## 절대 쓰지 않을 표현

앱은 취한 상태를 측정하거나 판정하지 않는다. 게임 점수만 보여주고 낮으면 귀가를 권할 뿐이다.

| 쓰지 않음 | 대신 |
|---|---|
| 음주 측정 앱 | 술자리 게임 앱 |
| 취기 판별 | 반응속도 게임 |
| 취했는지 알려주는 | 점수가 낮으면 집에 가자고 알려주는 |
| 정확도 ○○% | (쓰지 않는다) |

이 선을 넘으면 앱이 측정 도구로 오인되고, 판정을 빼기로 한 결정이 무의미해진다.

## 채널별 작성

### 유튜브 설명문

- 첫 2줄이 검색과 클릭을 좌우한다. 여기에 핵심을 넣는다
- 영상에서 무엇을 볼 수 있는지 → 앱이 뭔지 한 줄 → 팀 프로젝트 맥락
- 해시태그 3~5개. 프로필의 기본 태그에서 영상에 맞는 것만 고른다
- 분량 300~500자

### 네이버 블로그

개발 일지 톤. 마케팅 글이 아니다.

구조:
1. 이번에 만든 것 (영상 내용)
2. 만들면서 겪은 문제와 어떻게 풀었는지 — **여기가 본문의 절반 이상**
3. 앱 소개는 마지막에 짧게
4. 영상 임베드

분량 800~1,200자. 이모지 없음. 과장 없음. 잘 안 된 것도 쓴다.

### 네이버 카페

**카페마다 본문을 새로 쓴다.** 같은 글을 여러 카페에 복사하지 않는다 — 스팸 판정의 1순위 신호다.

- 그 카페의 성격에 맞게 도입부를 다르게 쓴다 (개발 카페 / 학생 카페 / 취미 카페)
- 홍보만 있으면 안 된다. 읽을거리가 본문의 절반 이상이어야 한다
- 분량 500~800자
- 게시 전 프로필 4번의 카페 안전 규칙을 다시 확인한다

### 티스토리

네이버 블로그와 같은 개발 일지 톤이되, **본문을 그대로 복사하지 않는다.** 같은 글이 두 블로그에 똑같이 올라가면 검색엔진이 중복 콘텐츠로 처리해 둘 다 손해다.

- 구성 순서를 바꾸거나 다른 에피소드를 앞세운다
- 티스토리는 개발자 독자가 많다. 기술적인 디테일(어떤 라이브러리를 썼는지, 왜 그 방법을 택했는지)을 네이버 버전보다 더 넣는다
- HTML로 작성한다. 브라우저 자동화로 HTML 모드에 붙여넣기 때문이다
- 분량 1,000~1,500자

### 인스타그램 (릴스 캡션)

- 첫 줄이 전부다. 더보기로 접히기 전에 승부가 난다
- 짧게. 3~5줄
- 해시태그 5~10개를 캡션 끝에 몰아 쓴다
- 2,200자 제한이지만 실제로는 500자 안쪽으로 쓴다
- 존댓말보다 반말 섞인 캐주얼한 톤이 어울린다. 단, 과장은 여전히 금지

### 스레드

- **500자 제한.** 넘으면 게시가 실패한다. 반드시 지킨다
- 대화체. 완결된 글보다 한 장면을 던지는 느낌
- 해시태그를 거의 쓰지 않는다. 인스타처럼 달면 겉돈다
- 질문으로 끝내면 반응이 붙는다 ("술자리에서 이런 앱 있으면 쓸 것 같아요?")

## 출력

각 채널별 글을 영상 폴더에 파일로 저장한다.

```
<영상파일명>_youtube.txt
<영상파일명>_blog.html          네이버 블로그
<영상파일명>_tistory.html
<영상파일명>_cafe_<카페명>.txt
<영상파일명>_instagram.txt
<영상파일명>_threads.txt
```

블로그·티스토리는 HTML, 나머지는 일반 텍스트. 자동 게시 전에 사용자가 열어볼 수 있게 하는 것이 목적이므로 파일로 남기는 단계를 건너뛰지 않는다.

저장 후 스레드 글자 수를 확인한다. 500자를 넘으면 줄여서 다시 저장한다. 이건 게시 실패로 직결되므로 눈으로 넘기지 않고 실제로 센다.
