# 영상 배포

영상 폴더를 확인해서 새 영상이 있으면 유튜브에 올리고, 글을 써서 네이버 블로그·카페에 게시한다.

## 0. 사전 점검 (통과 못 하면 중단)

`context/publish-profile.md`를 읽는다.

1번 표에 `(미설정)`이 하나라도 남아 있으면 **여기서 멈춘다.** 무엇이 비었는지 사용자에게 알리고 `setup-publishing` 스킬을 안내한다. 빈 값을 추측해서 채우지 않는다.

연결된 폴더를 `get_device_info`로 확인한다. 없으면 중단하고 사용자에게 알린다.

## 1. 새 영상 찾기

`device_bash`로 영상 폴더를 확인한다.

```bash
ls -la "$HOME/mnt/<폴더>"/*.mp4 2>/dev/null
```

`uploaded/` 하위에 있는 것은 이미 올린 것이므로 제외한다. 폴더 최상단에 있는 영상만 대상이다.

새 영상이 없으면 **아무것도 하지 않고 그렇게 보고한다.** 올릴 게 없는 날은 그냥 없는 것이다.

새 영상이 여러 개면 가장 오래된 것 1개만 처리한다. 한 번에 여러 개를 올리지 않는다.

## 2. 영상 내용 파악

파일명, 같은 이름의 메모 파일(`.txt`, `.md`), 사용자가 준 설명에서 내용을 파악한다.

내용을 알 수 없으면 **업로드하지 말고 사용자에게 묻는다.** 자동 실행 중이라 물을 수 없으면 그 영상을 건너뛰고 "내용 파악 불가로 보류"라고 보고한다. 추측한 설명을 붙여 올리지 않는다.

## 3. 글 작성

`write-post` 스킬을 따라 유튜브 설명문, 블로그 글, 카페별 글을 만들고 영상 폴더에 파일로 저장한다.

## 4. 유튜브 업로드

사용자 컴퓨터에서 실행한다. 영상 파일이 거기 있으므로 옮길 필요가 없다.

```bash
cd "$HOME/mnt/<폴더>" && python3 "scripts/youtube_upload.py" \
  --file "<영상>" --title "<제목>" \
  --description-file "<영상>_youtube.txt" \
  --tags "<태그>" --privacy <public 또는 unlisted>
```

- API 감사를 아직 통과하지 않았으면 `--privacy unlisted`를 쓴다. 프로필에 감사 통과 기록이 없으면 unlisted가 기본이다.
- 업로드는 시간이 걸린다. `device_bash`는 호출당 약 45초 제한이 있으므로, 큰 파일은 백그라운드로 돌리고(`nohup ... &`) 로그 파일을 나중에 확인하는 방식으로 나눈다.
- 사용자 컴퓨터에서 네트워크가 막혀 실행이 안 되면, 그때만 영상을 클라우드로 옮겨 여기서 업로드한다.

출력에서 영상 URL을 받아 다음 단계에 쓴다. **업로드가 실패하면 여기서 멈춘다.** 영상 없이 글만 올리지 않는다.

## 4.5. 공개 URL 만들기 (인스타·스레드용)

인스타그램과 스레드는 미디어를 직접 업로드받지 않는다. 공개 URL을 주면 Meta 서버가 내려받는다. 그래서 이 단계가 반드시 앞선다.

```bash
python3 "scripts/upload_media.py" --file "<영상>" --verify
```

`--verify`를 꼭 붙인다. 여기서 공개 접근이 안 되면 인스타·스레드 게시도 실패하므로, 미리 걸러내는 것이 낫다.

이 단계가 실패하면 **인스타와 스레드만 건너뛴다.** 유튜브·네이버·티스토리는 정상 진행한다.

마지막 줄에 출력되는 URL을 다음 단계에 쓴다.

## 5. 네이버 게시

### 블로그

```bash
python3 "scripts/naver_post.py" blog \
  --title "<제목>" --content-file "<영상>_blog.html" --tags "<태그>"
```

블로그 API를 못 쓰는 것으로 확인됐으면 게시하지 않고 초안 파일만 남긴다.

### 카페 — 여기서 규칙을 어기지 않는다

프로필 4번의 안전 규칙을 게시 직전에 다시 확인한다. 아래 중 하나라도 걸리면 **그 카페는 건너뛴다.**

| 확인 | 걸리면 |
|---|---|
| 홍보 허용 확인 체크가 되어 있나 | 건너뜀 |
| 최근 게시일로부터 7일이 지났나 | 건너뜀 |
| 이 카페용 본문을 따로 썼나 (복사본 아님) | 건너뜀 |

통과한 카페만, **하나씩 10분 간격으로** 게시한다. 한 번에 연속으로 쏘지 않는다.

```bash
python3 "scripts/naver_post.py" cafe \
  --clubid <id> --menuid <id> --title "<제목>" --content-file "<본문파일>"
```

**실패하면 재시도하지 않는다.** 응답 본문을 그대로 기록하고 다음으로 넘어간다. 자동 재시도가 중복 게시를 만든다.

## 5.5. 인스타그램 · 스레드 게시

4.5단계에서 만든 공개 URL을 쓴다.

```bash
python3 "scripts/meta_post.py" instagram \
  --video-url "<공개URL>" --caption-file "<영상>_instagram.txt"

python3 "scripts/meta_post.py" threads \
  --video-url "<공개URL>" --text-file "<영상>_threads.txt"
```

영상 처리에 시간이 걸린다. 스크립트가 상태를 폴링하므로 몇 분 걸릴 수 있다. `device_bash`의 호출 제한(약 45초)에 걸리므로 **백그라운드로 돌리고 로그를 나중에 확인한다.**

컨테이너 생성 단계에서 실패하면 대개 영상 규격 문제다. 세로 비율이 아니거나 코덱이 맞지 않으면 ffmpeg으로 변환한 뒤 다시 시도한다. 변환은 1회만 시도하고, 그래도 안 되면 건너뛴다.

## 5.6. 티스토리 게시

`publish-tistory` 스킬을 따른다. 브라우저 자동화라 실패 가능성이 다른 채널보다 높다.

**실패해도 전체 배포의 실패로 취급하지 않는다.** 초안 파일을 남기고 "수동 게시 필요"로 기록한 뒤 다음으로 넘어간다.

## 6. 마무리

1. 올린 영상을 `uploaded/` 로 옮긴다. **이게 중복 업로드를 막는 유일한 장치이므로 건너뛰지 않는다.**
2. `uploaded/upload-log.md`에 한 줄 추가한다: 날짜, 파일명, 영상 URL, 게시된 채널, 실패한 채널
3. 게시일을 프로필 3번 카페 표의 "최근 게시일"에 기록한다

## 7. 보고

짧게 적는다.

- 올린 영상과 URL
- 게시 성공한 채널
- 건너뛰거나 실패한 채널과 그 이유

실패를 숨기지 않는다. "일부 채널 게시 완료" 같은 두루뭉술한 보고를 하지 않고, 어디가 왜 안 됐는지 정확히 적는다.

## 자동 실행일 때

사용자가 답할 수 없다. 질문하지 말고 위 기본값으로 진행하되, 판단이 필요한 지점에서는 **하지 않는 쪽**을 택한다.

- 영상 내용 불명 → 보류
- 카페 규칙 확인 안 됨 → 건너뜀
- 게시 실패 → 재시도 없이 기록만

올리지 못한 것은 다음 실행 때 다시 시도할 수 있다. 잘못 올린 것은 되돌리기 어렵다.
