# 티스토리 게시 (브라우저 자동화)

**티스토리 Open API는 2024년 2월까지 순차 종료됐다.** 글 관련 기능이 종료 대상에 포함되어 자동 게시용 API가 없다. 따라서 유일한 방법은 사용자의 크롬을 직접 조작하는 것이다.

이 방식은 다른 채널과 성격이 다르다. 아래 제약을 먼저 이해하고 시작한다.

## 이 방식의 한계 (사용자에게 미리 알린다)

| 제약 | 의미 |
|---|---|
| 크롬이 켜져 있고 티스토리에 로그인돼 있어야 한다 | 사용자가 자리에 없으면 실패한다 |
| 에디터 UI가 바뀌면 깨진다 | 티스토리가 화면을 개편하면 다시 맞춰야 한다 |
| 화면을 보며 조작한다 | API보다 느리고, 중간에 예상 못 한 팝업이 뜨면 멈춘다 |

**따라서 티스토리는 "되면 좋고, 안 되면 초안만 남기는" 채널로 다룬다.** 실패해도 다른 채널의 게시는 정상 진행한다. 티스토리 하나 때문에 전체를 멈추지 않는다.

## 절차

### 1. 사전 확인

`claude-in-chrome` 스킬을 먼저 호출한다. 그다음 `tabs_context_mcp`로 현재 탭 상태를 확인한다.

브라우저에 닿지 않으면 여기서 끝낸다. 초안 파일만 남기고 "크롬 연결 안 됨 — 수동 게시 필요"로 보고한다. 재시도하지 않는다.

### 2. 새 탭에서 글쓰기 화면 열기

기존 탭을 재사용하지 않는다. `tabs_create_mcp`로 새 탭을 만들고 글쓰기 주소로 이동한다.

```
https://<블로그주소>/manage/newpost/
```

로그인 화면이 뜨면 **직접 로그인을 시도하지 않는다.** 사용자에게 로그인해달라고 알리고 종료한다. 자격 증명을 입력하려 들지 않는다.

### 3. 제목과 본문 입력

`write-post` 스킬이 만들어 둔 티스토리용 초안 파일을 읽어서 넣는다.

- 제목 입력란에 제목
- 본문은 **HTML 모드로 전환한 뒤** 붙여넣는다. 서식 있는 에디터에 그대로 넣으면 태그가 텍스트로 들어간다
- 유튜브 영상은 링크를 본문에 넣으면 티스토리가 자동으로 임베드한다

각 단계 후 스크린샷으로 실제로 들어갔는지 확인한다. 안 보고 다음으로 넘어가지 않는다.

### 4. 발행

**여기서 특히 조심한다.** 발행 버튼을 누르기 전에 스크린샷으로 제목·본문·공개 설정을 확인한다. 확인 없이 누르지 않는다.

- 공개 설정: 공개
- 발행 후 생성된 글 주소를 기록한다

확인 대화상자가 뜰 수 있다. **JavaScript alert/confirm이 뜨면 브라우저 제어가 멈춘다.** 발행 버튼 외의 요소(삭제, 취소 등)는 건드리지 않는다.

### 5. 실패했을 때

2~3번 시도해서 안 되면 멈춘다. 같은 동작을 반복하지 않는다.

초안 파일 경로를 알려주고, 어느 단계에서 막혔는지 스크린샷과 함께 보고한다. 사용자가 직접 복붙해서 올릴 수 있게 하는 것이 목적이다.

**중복 발행을 조심한다.** 발행 버튼을 누른 뒤 결과가 불확실하면, 다시 누르지 말고 블로그 목록을 열어 글이 올라갔는지 먼저 확인한다.

## 자동 실행일 때

예약 실행 중에는 사용자가 크롬 앞에 없을 가능성이 높다. 로그인이 풀렸거나 브라우저가 닫혀 있으면 조용히 실패한다.

그래서 자동 실행에서는:
1. 브라우저 연결을 먼저 확인하고, 안 되면 **바로 포기하고** 초안만 남긴다
2. 이걸 실패로 보고하되, 전체 배포의 실패로 취급하지 않는다
3. 다음 실행 때 다시 시도하지 않는다 — 사용자가 이미 수동으로 올렸을 수 있다. 중복 게시가 더 나쁘다
