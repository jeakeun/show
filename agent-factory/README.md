# 🏭 에이전트 공장 (agent-factory)

> 시작: 2026-10-22 · 버전 0.1
> 상태: 데모 모드와 자동 테스트 72개 통과. **실제 API로는 아직 한 번도 돌려보지 않았습니다** (이 작업을 한 클라우드 PC에 API 키가 없음). 메인 PC에서 첫 실제 실행 필요.

상황을 한국어로 설명하면, 그 일에 맞는 **에이전트 팀을 설계하고 → 코드로 규칙 검사하고 → 실행**하는 프로그램입니다.

```
"세 폴더를 각각 보고 이번 주 이상 징후를 한 장으로 정리해줘"
        │
  [설계 에이전트] 팀 설계도(YAML)를 만든다
        │
  [규칙 검사 · 코드] 11개 규칙. 어기면 설계자에게 돌려보냄 (최대 2번)
        │
  [검토 에이전트] 설계자의 생각을 모른 채 설계도만 보고 반박 → 심각하면 설계자가 한 번 고침
        │
  [사람] 설계 요약을 보고 "실행할까요? y/N"
        │
  [LangGraph] 단계 순서대로 실행. 2명 이상 단계는 동시에, 검토 루프는 미통과면 다시 쓰기
        │
  runs/<시각>-<팀이름>/result.md  (+ 에이전트별 기록, 비용 장부)
```

## 두 층

| 층 | 하는 일 | 파일 |
|---|---|---|
| **1층 · 에이전트 공장** | 설계도 한 장(모델·지시문·도구·반복 상한) → 실제로 일하는 에이전트 (생각 → 도구 → 결과 확인 반복 루프) | `agent.py`, `tools.py`, `llm.py`, `spec.py` |
| **2층 · 팀 설계자** | 상황 설명 → 팀 설계도 → 규칙 검사 → 검토 → LangGraph 흐름도로 바꿔 실행 | `designer.py`, `rules.py`, `team.py` |

설계도는 YAML 파일이라 **사람이 직접 고쳐도 되고**, 설계 에이전트가 만들어도 됩니다. 어느 쪽이든 같은 규칙 검사를 통과해야 실행됩니다.

## 처음 써보기 (메인 PC)

**1. 데모 (돈 0원, API 키 필요 없음)** — 흐름만 봅니다. AI 대신 정해진 가짜 답이 나옵니다.

1. `agent-factory` 폴더에서 **`demo.bat` 더블클릭** (처음엔 설치 때문에 1~2분 걸림)
2. `1` 입력 → 엔터 (예제 폴더 사용) → 상황 입력. 예: `세 폴더를 각각 조사해서 비교해줘`
3. 설계자가 첫 설계에서 일부러 규칙을 어기고 → 코드가 잡아내고 → 고친 설계가 나오는 과정이 보입니다
4. `y` 를 누르면 실행되고, 끝에 결과 파일 위치가 나옵니다

**2. 실제 실행**

1. API 키: `D:\yt-auto\secrets\.env` 에 `ANTHROPIC_API_KEY` 가 있으면 **자동으로 그걸 씁니다** (화면에 "어디서 찾았는지"만 나오고 키 값은 안 나옴).
   따로 쓰고 싶으면 `agent-factory\.env` 파일에 `ANTHROPIC_API_KEY=...` 한 줄 (깃에 안 올라감).
   - 주의: yt-auto 와 같은 키면 앤트로픽 청구서는 합쳐서 나옵니다. 이 프로그램 비용은 `runs\*\ledger.jsonl` 에 따로 기록됩니다.
2. **`start.bat` 더블클릭** → 메뉴
3. 첫 실험 추천: `2) 저장된 팀 실행` → 예제 폴더 → `report-trend` (1명 팀, 예산 상한 $0.30)

## 명령어

`start.bat` 뒤에 붙이거나, 가상환경 파이썬으로 `python -m agent_factory ...`

| 명령 | 하는 일 |
|---|---|
| (없음) | 메뉴 |
| `design "상황 설명"` | 팀 설계 → `teams/` 에 저장 → 실행할지 물어봄. `--yes` 바로 실행, `--no-run` 설계만, `--no-critic` 검토 생략 |
| `run 팀이름` | 저장된 팀 실행. `--task "작업"` 으로 다른 일을 맡길 수 있음 (없으면 설계도의 상황) |
| `check 팀이름` | 규칙 검사만 |
| `show 팀이름` | 설계 요약 + 팀 그림(mermaid) |
| `list` | 팀·도구·모델·규칙 목록 |

공통: `--demo` (가짜 모델), `--workspace 폴더` (에이전트가 읽을 폴더, 기본은 `sample-workspace`)

예: `start.bat run multi-project-weekly --workspace D:\study-data`

## 설계 규칙 11개 (`rules.py`)

같은 규칙 목록이 **설계 에이전트 지시문에도 그대로 들어갑니다.** 프롬프트와 검사 코드가 어긋날 수 없게 한 곳에서 관리합니다.

| 규칙 | 내용 | 근거 |
|---|---|---|
| R01 이름 형식 | 영문 소문자 이름, 중복 없음 | 파일·노드 이름으로 쓰임 |
| R02 있는 모델·도구만 | 정해진 목록에서만 고름. 새 도구를 만들 수 없음 | AI는 권한을 늘릴 수 없다 |
| R03 크기 상한 | 최대 6명, 5단계, 한 단계 동시 4명 | 비용·맥락 단절 |
| R04 빠짐·중복 없음 | 모든 에이전트가 정확히 한 번 일함 | 설계 실수 방지 |
| R05 혼자 먼저 | 2명 이상이면 "1명으로 안 되는 이유"와 각자 "따로 둔 이유" 필수 | 01-개념 6절, 직함으로 나누지 않기 |
| R06 병렬은 읽기만 | 동시에 일하는 에이전트는 읽기 도구만 | ADR-06 감사 병렬 |
| R07 쓰기는 한 곳 | 쓰기 도구는 최대 1명, 마지막 단계에만 | ADR-03, Cognition 2026 |
| R08 마무리는 한 명 | 마지막 단계는 1명 | 결과물 하나 |
| R09 검토자 분리 | 검토자는 쓰기 도구 없음, 기준 필수, 1~3회 | ADR-05 |
| R10 반복 상한 | 에이전트당 모델 호출 1~12회 | 무한 루프 방지 |
| R11 예산 상한 | 1회 실행 $3 이하, 넘으면 자동 중단 | ADR-08 |

막지는 않지만 경고하는 것: 4명 이상, opus 3명 이상, 웹 검색 사용.

## 도구 (`tools.py`)

| 도구 | 위험도 | 설명 |
|---|---|---|
| list_files / read_file / search_files | 읽기 | 작업 폴더 안에서만. 비밀 파일은 목록에도 안 나옴 |
| calculate | 읽기 | 계산기. **숫자는 AI가 머리로 세지 않고 코드가 계산** (ADR-04) |
| save_file | 쓰기 | 이번 실행 폴더 `files/` 에만. 같은 이름이면 새 이름으로 (덮어쓰기 없음 = 되돌릴 수 있음) |
| web_search | 읽기 | 앤트로픽 서버 웹 검색. 1회 약 $0.01, 에이전트당 최대 5회. opus·sonnet 만 |

위험도 `external`(밖으로 나가는 되돌릴 수 없는 행동, 예: 메시지 발송)은 **실행 직전에 사람에게 묻습니다.** 지금 목록에는 없고, 나중에 추가할 칸만 만들어 뒀습니다 (ADR-07).

## 모델

| 이름 | 모델 | 용도 | 100만 토큰당 입력/출력 |
|---|---|---|---|
| opus | claude-opus-5-5 | 어려운 판단·설계·종합 (설계·검토 에이전트도 이것) | $4 / $20 |
| sonnet | claude-sonnet-5-5 | 일반 작성·분석 | $2 / $10 |
| haiku | claude-haiku-5-5 | 단순 정리·분류·검사 | $0.10 / $0.50 |

opus·sonnet 은 안전 분류기가 거절하면 서버가 다른 모델로 자동 재시도합니다 (`fallbacks="default"`). haiku 는 이 기능이 없습니다.

## 실행 기록 (`runs/<시각>-<팀이름>/`, 깃에 안 올라감)

| 파일 | 내용 |
|---|---|
| `result.md` | 최종 결과. 검토 미통과·예산 초과·데모면 맨 위에 ⚠ 표시 |
| `summary.md` | 걸린 시간, 검토 결과, 에이전트별 호출 수·토큰·비용 표 |
| `agents/NN-*.md` | 에이전트마다: 받은 입력, 도구 사용 기록, 결과 |
| `ledger.jsonl` | 모델 호출 1번당 한 줄 (토큰·비용) |
| `flow.md` | 팀 그림 + LangGraph 가 실제로 만든 그래프 (mermaid) |
| `team.yaml` | 이번에 실행한 설계도 사본 |
| `files/` | save_file 로 저장한 파일 |

설계할 때도 `runs/<시각>-design/` 에 설계 과정(규칙 위반·수정·검토 의견)과 비용이 남습니다.

## 예제 팀 (`teams/`)

| 팀 | 구조 | 왜 이 구조인가 |
|---|---|---|
| `report-trend` | 1명 | 자료가 작으면 나누지 않는 게 낫다 (R05) |
| `fact-checked-summary` | 작성 1명 → 검토 루프 | 숫자가 원본과 맞는지 다른 맥락이 대조 (ADR-05) |
| `multi-project-weekly` | 조사 3명 동시 → 종합 1명 | 유튜브·코인·채용 자료가 서로 독립적 (ADR-06) |

`sample-workspace/` 의 숫자는 전부 연습용 가짜 데이터입니다.

## 안전장치와 한계

- 읽기는 지정 폴더 안에서만. 폴더 밖 경로(`..`, 절대 경로)와 비밀 파일 이름(`.env`, `secrets/`, `*token*`, `*secret*`, `*.key` 등)은 막습니다.
- **한계**: 비밀 파일은 **이름으로만** 막습니다. 이름이 평범한데 안에 키가 든 파일(예: `uploader\config.json`)은 못 막습니다. **작업 폴더는 데이터·리포트 폴더만** 지정하세요. 에이전트가 읽은 내용은 앤트로픽 API 로 전송됩니다.
- 대화 기록은 고치지 않고 이어 붙이기만 합니다 (캐시·사고 블록 보존).
- 규칙을 통과하지 못한 설계도는 직접 고쳐 쓴 것이라도 실행하지 않습니다.
- 예산은 호출 **전에** 확인합니다. 동시에 도는 에이전트가 같은 순간 확인하면 예산을 조금 넘을 수 있습니다.

## 일부러 안 넣은 것 (0.1)

- **그때그때 나누는 지휘자(오케스트레이터)와 라우팅**: 지금은 단계가 설계할 때 고정됩니다. 먼저 고정 구조로 실제 결과를 본 뒤 필요하면 추가.
- **단계 사이 전체 맥락 공유**: 바로 앞 단계 결과만 다음 단계로 넘깁니다 (맥락 보호). 그래서 3단계는 1단계 결과를 직접 못 봅니다.
- **에이전트가 도구를 새로 만드는 기능**: 권한을 스스로 늘리는 길이라 막았습니다.

## 면접에서 말할 거리 (지금 사실인 것만)

- "설계 AI가 팀을 짜면 코드가 11개 규칙으로 검사해서 어기면 돌려보냅니다. 규칙 목록 하나가 설계 AI의 지시문과 검사 코드에 동시에 들어가서 둘이 어긋나지 않습니다."
- "AI는 정해진 도구 목록에서 고르기만 하고 새 권한을 만들 수 없습니다. 동시에 일하는 에이전트는 읽기 도구만, 쓰기는 마지막 한 명만 갖게 코드가 강제합니다."
- "에이전트 정의는 프레임워크와 상관없는 YAML 이고, 흐름 실행만 LangGraph(Send 병렬, 조건 분기 루프)입니다. 직접 짠 실행기와 같은 설계도로 비교할 수 있게 나눴습니다 (비교는 아직)."
- 아직 아닌 것: 실제 API 실행 결과, 1명 팀 vs 여러 명 팀 비교 숫자.
